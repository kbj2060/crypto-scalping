# WS-D 테스트 설계도 — 라이브/백테스트 패리티 + 드리프트 모니터

성격: 운영 인프라. 가설 검정이 아니라 **수락 테스트(acceptance test) + 모니터 자체의 검증**.
공수: 1일 구축 + 상시 운영. 선행 조건 없음.

## 목적

- 사고를 당일 잡는다. 전례: decision_feature_frame 11일 무기록(스키마 체크 하드 실패),
  microstructure_1m 자산 혼합 버그, ou_halflife/garch_vol_z 재현 드리프트.
- 세 가지 감시 대상: (1) 라이브 기록 피처 vs 오프라인 재계산 패리티,
  (2) 피처 분포 드리프트, (3) 섀도우 정책 성과 이탈.

## 구성 요소와 수락 테스트

### D1. 패리티 잡 (주간 + 온디맨드)
**동작**: 최근 7일 `decision_feature_frame*`의 각 의사결정 타임스탬프에 대해
오프라인 파이프라인으로 피처를 재계산, 컬럼별 비교.

- 비교 규칙: 수치형 `max(|a−b|/max(|a|,|b|,ε))` 상대오차, 범주형 완전일치.
- 허용 오차 3단계:
  - `strict` (기본): rel err < 1e-6
  - `loose` (부동소수 누적 연산 컬럼, 예: rolling GARCH): rel err < 1e-3
  - `known_drift` 화이트리스트: `ou_halflife`, `garch_vol_z` 등 데이터 연장 시
    재현 불가로 이미 확인된 컬럼 — 비교하되 실패로 치지 않고 별도 섹션에 보고.
- **수락 기준**: 화이트리스트 제외 컬럼의 99% 이상이 허용 오차 내.
  미달 컬럼은 이름+최대오차+발생 타임스탬프를 리포트에 명시.

**모니터 자체 검증 (구축 시 1회)**:
- 주입 테스트 A: 오프라인 재계산 입력 데이터에서 임의 1컬럼을 1.001배 → 잡이 해당
  컬럼을 반드시 검출해야 통과.
- 주입 테스트 B: 조작 없음 → 화이트리스트 외 오탐 0건이어야 통과.

### D2. 드리프트 스코어 (주간)
**동작**: `decision_feature_frame` + `microstructure_1m` 주요 컬럼의 최근 7일 분포 vs
기준 분포(각 라이브 모델의 학습 구간 분포, 아티팩트로 고정 저장).

- 지표: PSI (10분위, 기준 분포 기준 고정 bin) + KS 통계 병기.
- 경보 기준: PSI > 0.2 경보(관행적 기준), 0.1~0.2 주의. `known_drift` 컬럼은
  자체 이력 대비 z-score로 별도 밴드.
- **수락 기준(구축 시)**:
  - 주입 테스트: 임의 컬럼에 +1σ 시프트 합성 → PSI 경보 발생 확인.
  - 30일 시운전 오탐률: 주의 이상 경보 중 수동 검토로 "실제 시장 변화 또는 실제 버그"로
    분류되지 않는 건이 주당 3건 이하 (넘으면 bin/기준 재조정).

### D3. 섀도우 성과 이탈 감시 (주간)
**동작**: 각 shadow DB(`*_micro_scalp*_shadow.duckdb::shadow_pnl`)의 롤링 7일 성과를
해당 정책의 오프라인 기대 분포와 비교.

- 기대 분포: 오프라인 평가의 일간 PnL을 day-block bootstrap → 7일 합 CI(5%/95%).
- 경보: 실측 7일 합이 CI 밖 (하방 이탈은 즉시, 상방 이탈도 보고 — 상방 이탈은
  흔히 조인/타임스탬프 버그 신호다. naive-join +1.3bps 인플레 전례).
- 결측 감시: `shadow_pnl` 최신 행 나이 > 2×기록 주기 → "기록 중단" 경보
  (11일 무기록 사고 재발 방지의 직접 대응).

### D4. 수집 건강 감시 (일간, 경량)
- 각 DuckDB 테이블의 최신 ts 나이, 24h 행 증가수, null률 급증 체크.
- `microstructure_1m`의 `data_stale/depth_connected/trade_connected` false 비율 일간 집계.
- 경보 기준: 최신 행 나이 > 10분(1m 테이블), 24h 행수가 기대치(1440)의 90% 미만.

## 산출물/배선

- 잡: `scripts/run_live_parity_drift_monitor.py` (cron 주간 + D4는 일간)
- 리포트: `data/live/parity_report_YYYYMMDD.json` + 요약 md
- 대시보드: 기존 dashboard에 패널 1개 (최근 경보 목록 + PSI 상위 10 컬럼)
- 경보 전달: 로그 + dashboard_events.jsonl (기존 이벤트 스트림 재사용)

## 전체 수락 기준 (구축 완료 판정)

1. D1 주입 테스트 A/B 통과.
2. D2 주입 테스트 통과.
3. D3가 6개 shadow DB 전부에서 리포트 생성 + 결측 감시 동작(임의 DB 일시 정지 테스트).
4. D4 일간 잡이 3일 연속 무오류 실행.
5. 전체 잡 실행 시간 < 10분, 라이브 봇 DuckDB 락 경합 없음
   (`serialized_duckdb_access` 경유 + read_only 연결 — 실행 중 봇 의사결정 지연 로그 확인).
