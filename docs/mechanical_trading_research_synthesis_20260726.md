# 기계적 매매 최적해 연구 종합 (2026-07-26)

**질문**: 세계에 존재하는 모든 지표를 찾거나 만들어서 공식화하면 최고의 기계적 매매가 되는가?

**답**: 아니다. 그리고 그것을 반증하는 데이터가 이 저장소에 이미 축적돼 있다. 병목은 지표
개수가 아니라 **탐색 과정 자체가 가짜 승자를 생산하는데 그것을 탐지할 계측기가 없었다**는
점이다. 이 문서는 (1) 그 계측기를 만들어 측정한 결과, (2) 저장소 전체 증거가 가리키는
실제 구조, (3) 남은 유일한 증거기반 후보의 사전등록 설계를 담는다.

## 1. 지표를 더 찾는 것이 왜 답이 아닌가

이 저장소는 이미 그 실험을 여러 번 했다.

| 근거 | 내용 |
|---|---|
| 지표 보유량 | `data/training_features_5m.csv` 기준 **141개** 피처가 이미 존재 |
| Sigma8 | 피처 추가로 Sigma6를 넘으려는 시도 → 실패 |
| Omega4.6.1 exit-logic | 10개 라운드 전부 VAL/OOS 실패 |
| Omega4.7-RL | end-to-end RL로 지표 조합 학습 → OOS -88~-99% |
| 1m 스캘핑 | 사상 최강 결과로 보였으나 lookahead 버그로 전면 무효화 |
| microstructure | 신호는 실재(t=-7.6)하나 0.3~2bps로 비용 4~9bps에 미달 |
| F3-A 펀딩 캐리 | 24/24 변형 kill. 펀딩 컴포넌트 자체가 전부 음수 |
| F3-B 크로스섹션 | 총수익은 양수이나 일일 리밸런싱 비용이 압도 |
| BTC | 3단계 전부 소진, 구조적 효율성 천장으로 결론 |
| VPVR 공식 (오늘) | walk-forward 5개 fold 중 양수 **0개** |

지표 축은 이미 포화 상태이고, 실패는 지표 부족 때문이 아니었다.

## 2. 새 계측기: `core/selection_stats.py`

모든 실패가 같은 형태였다 — 최적화 → 화려한 IS 숫자 → OOS 붕괴. 빠져 있던 것은
**"이 숫자가 같은 규모의 탐색이 순수 노이즈에서 뽑아내는 숫자보다 큰가"** 를 묻는 도구다.

| 함수 | 내용 | 출처 |
|---|---|---|
| `expected_max_sharpe` | N회 독립 시행의 기대 최대 Sharpe = 노이즈 바닥 | Bailey & López de Prado 2014 |
| `probabilistic_sharpe_ratio` | 왜도/첨도 보정 P(true SR > 기준) | Bailey & López de Prado 2012 |
| `deflated_sharpe_ratio` | 기준을 탐색 자신의 기대 최대치로 놓은 PSR | Bailey & López de Prado 2014 |
| `pbo_cscv` | 조합대칭 교차검증 기반 과최적화 확률 | Bailey/Borwein/LdP/Zhu 2017 |

**검증** (수식이 틀리면 아래 전부가 무의미하므로 선행 실시):

- `expected_max_sharpe`: N=200에서 공식 2.7655 vs 몬테카를로 실측 2.7201 (오차 1.7%)
- `PSR`: 기준=관측치일 때 정확히 0.5, 음의 왜도가 값을 낮춤 (0.9785 < 0.9871)
- `pbo_cscv`: 순수 노이즈 100열에서 **0.476** (이론 0.5), 한 열에만 진짜 우위를 심으면
  **0.000** — 판별력 확인

## 3. VPVR 공식에 적용한 판정

200회 **독립 랜덤** 탐색(TPE는 독립 가정을 위반하므로 의도적으로 랜덤 사용), 학습구간
651일의 일별 수익률 기준.

```
노이즈 바닥 E[max daily SR]                0.3598
──────────────────────────────────────────────────────
랜덤 탐색 최고                             0.0309   (바닥의 0.09배)
optuna sharpe 우승자   (train  +79.6%)     0.0654   (바닥의 0.18배)
optuna pnl_mdd 우승자  (train +345.9%)     0.0769   (바닥의 0.21배)
optuna pnl 우승자      (train +1715.0%)    0.0869   (바닥의 0.24배)
```

**모든 우승자가 노이즈 바닥보다 한참 아래다.** DSR은 전부 1e-22 미만. 즉 이 전략 공간은
"우위가 없는" 정도가 아니라, 200회 탐색한 무작위 전략보다도 못한 성적을 낸다.

### 3.1 최적화를 세게 할수록 붕괴가 커진다

| 탐색 | train PnL | holdout PnL |
|---|---|---|
| 랜덤 200회 | +29.0% | **-4.4%** |
| Optuna 200회 | +1715.0% | **-87.8%** |

TPE가 더 큰 IS 숫자를 찾아낸 것은 더 나은 전략을 찾았기 때문이 아니라 **노이즈를 더 깊이
파냈기 때문**이다. IS 숫자의 크기는 신뢰도의 반대 지표로 작동했다.

### 3.2 PBO 0.115는 좋은 신호가 아니다 (주의)

PBO가 0.115로 낮게 나오지만 긍정적으로 해석하면 안 된다. 샘플된 설정의 **98.5%가 완전
파산**(시행 PnL 중앙값 -100%)이라, "파산을 피한다"는 안정적이고 일반화되는 순위 기준이
존재할 뿐이다. 이는 알파와 무관하다. PBO는 수익성이 아니라 상대 순위를 재는 지표이므로
파산이 지배하는 공간에서는 낮게 나온다.

## 4. 통과한 것들의 공통 구조 — 실증적 답

이 저장소에서 val+OOS를 통과했거나 최강 후보로 남은 것들(Omega6 v2, Sigma6, Omega4.6.1)의
공통점은 지표가 아니라 **구조**다.

1. **저빈도** — 1h 봉. "작동하는 레버는 아키텍처가 아니라 낮은 빈도"라는 결론이 반복 확인됨.
   비용이 4~9bps인데 5m은 하루 288봉, 1m은 1440봉이다. 빈도가 곧 비용이다.
2. **추세추종** — 평균회귀가 아니라 방향 지속에 베팅.
3. **레짐 필터** — chop 구간에서 아예 거래하지 않음. 이 저장소에서 가장 반복적으로 검증된
   단일 개선.
4. **이익 확대 허용(트레일링)** — 낮은 승률을 큰 우승 거래로 상쇄.
5. **적은 거래수** — 4개월 19~26건 수준.

"최고의 기계적 매매 방법"에 대한 이 저장소의 실증적 답은 새 공식이 아니라 **이 다섯 가지
구조를 지키는 것**이다. 학계에서 가장 널리 복제된 이상현상(time-series momentum,
Moskowitz-Ooi-Pedersen 2012)과도 일치한다.

## 5. F3-B 저빈도 리밸런싱 — 3자산 시도 후 25자산으로 재설계 (결국 둘 다 종결)

F3-B(크로스섹션 모멘텀)는 kill됐지만 **kill 사유가 다른 모든 실패와 다르다**. 신호가
없어서가 아니라 **비용에만 밀렸다**.

- 비용 전 총수익이 k∈{7,14,30}일 **전부 양수**(1.5~8.2bps/일), k가 클수록 커짐 —
  방향성 있는 진짜 신호의 특징
- 일일 양다리 리밸런싱 비용 20bps/일이 이를 압도
- 실행 문서가 후속 아이디어를 명시적으로 열어둠: 주 1회 리밸런싱 시 비용 약 7배 감소

산술적으로 k=30 기준 총수익 8.2bps/일, 주 1회 리밸런싱 시 비용 2.86bps/일 → 이론상
+5.3bps/일. 다만 **포지션을 일주일 방치하면 총수익도 함께 열화**되므로 실측이 필요하다.
이것이 이 실험의 전부이자 핵심 질문이다.

### 5.1 사전등록 설계 (실행 전 확정, 사후 변경 금지)

기존 anti-fishing 규칙에 따라 별도 사전등록이 필요하므로 즉흥 실행하지 않고 설계만 남긴다.

| 항목 | 값 |
|---|---|
| 가설 | 리밸런스 주기를 늘리면 총수익 열화보다 비용 절감이 커서 순수익이 양수가 된다 |
| 격자 | lookback k ∈ {14, 30, 60}일 × 리밸런스 주기 ∈ {3일, 7일, 14일} = 9개 (고정) |
| 유니버스 | ETH/BTC/SOL 3자산 (확장 금지 — 확장은 별도 실험) |
| 비용 | cost1(10bps 왕복) 주 판정, cost3(30bps) 강건성 |
| 탐색구간 | 2024-01 ~ 2025-08 |
| kill 기준 | 탐색구간 net_cost1 > 0 **그리고** day-block bootstrap t > 3. 미달 시 val/OOS 진행 금지 |
| val / OOS | 2025-09~12 / 2026-01~03 (fresh-forward 규칙 준수, 저장 원장 입력 금지) |
| 노이즈 바닥 | 9개 격자에 대해 `expected_max_sharpe(9, trial_sr_std)` 를 **실행 전** 계산해 기록 |
| 승격 기준 | OOS DSR ≥ 0.95 **그리고** PBO ≤ 0.25 |

3자산 유니버스로 크로스섹션 모멘텀을 검증하는 것은 원래 약한 검정이다(문헌은 20종 이상을
전제). 통과해도 근거의 강도는 제한적임을 미리 명시한다.

### 5.1.1 실행 결과 (2026-07-26, 사전등록 직후 실행) — **KILLED, 단 사유가 중요**

가설의 전반부는 맞았다 — 리밸런스 주기를 늘리자 비용이 실제로 6.70 → 1.45bps/일로 줄었고
4개 변형에서 순수익이 양수로 돌아섰다(최대 +9.03bps/일 ≈ 연 33%). 그러나 **어느 것도 0과
통계적으로 구분되지 않는다** (최대 t=1.31). 노이즈 바닥 대비로도 최고 변형의 일간 Sharpe는
0.0625 vs 바닥 0.0542로 1.15배에 불과하다.

**핵심 진단 — "효과 없음"이 아니라 "확인 불가"다.** 3자산 크로스섹션의 일간 변동성은
약 145bps/일인데 효과 크기는 7~9bps/일이다. 신호대잡음비가 0.06 수준이라 t>3에 도달하려면
**6.3~13.3년치가 필요**한데 1.2년뿐이다. 사전등록한 게이트는 이 유니버스 크기에서
**구조적으로 통과 불가능**했다. (원본 F3-B 문서도 "3자산 유니버스 한계"를 이미 명시했다.)

**부수 발견 — 원본 F3-B의 비용 모델은 약 9배 과대계상이었다.** 원본은 순위가 안 바뀌어도
매일 왕복비용 전액(20bps/일)을 부과했으나 실제 회전율 기준은 2.25bps/일이다 (k=30 일간
리밸런스 기준 — 30일 모멘텀 순위는 평균 9일에 한 번 바뀐다). 다만 이 관대한 회전율 모델로
재계산해도 **최대 t=1.63으로 여전히 미달**이므로 원본의 kill 판정 자체는 결과적으로 옳았다.
비용 모델이 아니라 표본이 부족한 것이다.

**갈림길**: 3자산으로는 이 축을 영원히 확인할 수 없다. 선택지는 둘뿐이다.
(a) 문헌 표준대로 **20종 이상 유니버스로 새 사전등록 실험**을 설계한다 — 종목 수가 늘면
분산으로 크로스섹션 잡음이 줄어 검정력이 올라간다. (b) 축을 영구 종결한다.
**중간은 없다** — 3자산에서 t를 올리려 파라미터를 더 만지는 것은 정의상 노이즈 채굴이다.

## 6. 연구 프로토콜 제안

지금까지의 실패는 개별 아이디어의 문제가 아니라 절차의 문제였다. 다음을 기본값으로 삼기를
권한다.

1. **노이즈 바닥을 먼저 계산한다.** 탐색 규모 N이 정해지면 `expected_max_sharpe(N, σ)`를
   실행 **전에** 기록한다. 이 값을 못 넘으면 결과를 보지 않고 폐기한다.
2. **DSR을 승격 게이트에 넣는다.** `promotion_pass` 조건에 `DSR ≥ 0.95`를 추가.
   기존 Omega artifact integrity gate와 같은 층위로 다룬다.
3. **IS 숫자의 크기를 성과로 보지 않는다.** 오늘 측정에서 IS 수익률과 OOS 붕괴폭은
   양의 상관을 보였다. `+1715%` 같은 숫자는 경보로 읽어야 한다.
4. **탐색은 랜덤으로, 최적화는 마지막에.** TPE/CMA-ES는 독립 가정을 깨서 DSR을 무력화한다.
   후보 선별까지는 독립 랜덤 탐색, 확정된 단일 가설의 미세조정에만 guided search를 쓴다.
5. **경제적 근거를 먼저 적고 그 다음에 테스트한다.** 지표 조합에서 출발하면 반드시
   데이터 스누핑이 된다. F3-A/F3-B는 근거를 먼저 적었기에 kill 판정이 깔끔했다.

## 7. 새 가설 — F5: 펀딩 극단치 + 정산시각 역발상 반전

"이 저장소에서 진짜로 안 해본 것"을 3방향(전체 시도/종결 목록, 수집됐지만 단독신호로 미검증인

전략으로는 한번도 격리 테스트된 적 없는 것 중, **경제적 근거가 명확하고 새 데이터 수집이

### 7.1 가설과 F3-A와의 명확한 구분

**메커니즘**: 펀딩비가 역사적 극단 백분위에 도달하면, 그 방향으로 과밀된 레버리지 포지션이
정산(00:00/08:00/16:00 UTC) 시점 부근에서 청산 회피 목적의 디레버리징 압력을 받아 가격이

## 8. 완전히 새로운 패러다임 — 현물-무기한선물 델타중립 캐리

지금까지의 5개 축(지표 탐색, F3-B 3자산/25자산, 변동성 타게팅, F5 펀딩반전)은 전부 **방향성
베팅**이었다 — 가격이 어디로 갈지 예측하는 신호를 찾는 시도. 사용자가 요청한 "완전히 새로운
방향"은 종류 자체가 다른 것이어야 한다. 3개 패러다임을 검토했다:

| 후보 | 판단 |
|---|---|
| **현물+퍼프 델타중립 캐리** | **채택** — 마켓뉴트럴, 방향성 베팅 자체가 아니라 이 세션의 "추세추종>평균회귀" 결론과 무관. 저장소에 선행사례 전무(감사에서도 "perp-spot basis 데이터 부재"로 명시 확인됨), 데이터도 새로 모으면 됨(공개 API) |
| 패시브 마켓메이킹(스프레드 수취) | 기각(보류) — 종류는 가장 다르지만 오더북 데이터가 며칠치뿐이라 인프라 미성숙 |
| 공적분 페어트레이딩 | 기각 — 방법론은 다르나 본질은 평균회귀, F5/F3-A 가격컴포넌트가 반복 확인한 "이 시장에서 평균회귀는 구조적으로 진다"는 증거와 충돌 위험 |

### 8.1 가설과 F3-A와의 명확한 구분

**메커니즘**: 현물을 롱, 동일 명목가의 무기한선물(perp)을 숏으로 잡으면 가격 리스크가
상쇄되고(델타중립), 남는 손익은 (1) 펀딩비 수취/지급, (2) 베이시스(perp가격-현물가격) 변화
뿐이다. 펀딩이 양수인 기간이 충분히 길면 이 포지션은 방향성 리스크 없이 펀딩비를 누적
수취한다.

**F3-A(이미 KILLED)와 근본적으로 다른 메커니즘**: F3-A는 헤지 없이 퍼프 단독 포지션으로
방향성 레버리지 베팅을 했고, **가격 컴포넌트가 펀딩 컴포넌트를 압도**해서 죽었다. 이 전략은
그 가격 컴포넌트를 현물 반대 포지션으로 애초에 제거한다 — 방향성 리스크 자체가 설계상 없다.
