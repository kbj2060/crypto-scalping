# ETH 진입 모델 층별 재구성 게이트 (2026-09-03)

사용자 제안 *"진입 모델을 모델링하면서 매 기능을 넣을 때마다 전수 조사하는 기능을 추가하자"* 에서
시작. 저장소 기록을 다시 읽은 결론은 **방향은 맞지만 "전수 조사 스캐너"로 만들면 이번에도 못
잡는다**였고, 아래 형태로 재설계해 승인받았다.

```
"매 기능마다 전수 스캔"  →  "층 출력이 동결되는 시점에, 그 층을 다른 경로로 다시 만들어 대조하고,
                              불일치면 다음 층을 못 쌓게 막는다"
```

구현: `scripts/gate_eth_entry_layers_20260903.py` · 어댑터 `scripts/gate_eth_entry_triggers_v1_adapter_20260903.py`
· 규칙: `.claude/CLAUDE.md` "Entry-Model Layer Reconstruction Gate (ETH)" · 정답검증 기록: `tmp/eth_entry_limit_fade_v1_20260903/layer_gates.json`

## 1. 왜 스캐너가 아니라 재구성인가

이 저장소의 미래참조/오염 사고 4건(`docs/homer/README.md` §5.21)은 **메커니즘이 전부 다르고 잡은
방법도 전부 달랐다**: A 앵커(`cluster_dedup`)→지연확정 재시뮬, B 체결봉 크레딧→1분봉 재계산,
C 스태킹 in-sample→OOF 재생성, D 트리거-라벨 순환→공유창 속성 분리 재측정. 표준 대조군 5종(방향뒤집기·
무작위·시드·부트스트랩·DSR/PBO)은 넷 다 통과시켰다 — 대조군도 같은 오염 기질 위에서 채점되기
때문이다. B는 대조군 7종 + DSR 1.0000 + PBO 0.0437을 전부 통과하고 무너졌다.

**효과가 있었던 조치는 예외 없이 "의심층을 독립적으로 다시 만들어보는 것"이었다.** 스캐너는 대조군과
같은 부류다 — 알려진 패턴을 찾을 뿐이다(기존 스캐너 4개 전부 docstring에 "판정이 아니라 후보 목록").

그리고 B는 **도구가 없어서 못 잡은 게 아니다**: 경고(`feedback_intrabar_ordering_optimistic_pessimistic_bracket_20260830`)가
메모리에 있었고 지나쳤다. "전수조사해줘" 한마디에 첫 항목에서 걸렸고 스크립트는 몇 분짜리였다.
섀도우 러너는 이미 L1(체결봉 제외)로 정직했는데 백테스트만 L0였다 — 파리티 테스트 하나면 도메인
통찰 없이 걸렸을 결함이다. 빠져 있던 건 **강제력**이다. 그래서 이 게이트의 핵심은 스캔의 폭이 아니라
**블로킹**이다.

## 2. 게이트 명세

파이프라인 디렉토리의 `gate_config.json`이 계약이고, 러너가 `layer_gates.json`을 쓴다.
FAIL이 하나라도 있으면 exit 1. **FAIL 층 위에 만든 결과는 전부 provisional** — 승격·동결·보고에 쓰지 않는다.

| 게이트 | 재구성(다른 경로로 같은 수를 다시 계산) | 판정 | 잡는 사고 |
|---|---|---|---|
| **L4** known_ts 계약 | 체결 봉이 트리거가 *알려진* 봉보다 뒤인가(`fill_ts > known_ts`). 저장 인덱스 `fi` ↔ `timestamp + btf×5m` 정합 | 위반 1행이라도 FAIL. known_ts 미선언 FAIL | A·D, BTC 108봉 오프셋 부류 |
| **L1** 발동 인과성 | `build_fires(kl)`를 (a) 각 표본 발동의 known_ts에서 자른 데이터로 재실행 → 그 발동이 있어야 함 (b) known_ts **1·3봉 전**에서 자른 데이터의 최근 24h 발동 중 전체집합에 없는 것 = **유령 발동** | missing>0 또는 phantom>0 FAIL | A(앵커 사후확정), 확인봉이 필요한 트리거의 거짓 known_ts |
| **L2** 라벨 1분 재구성 | 먼저 파이프라인 라벨을 청산·비용·명목 설정으로 **1e-9 이내 재현**(못 하면 FAIL). 그다음 체결 5분봉을 1분봉으로 갈라 **지정가에 처음 닿은 분의 다음 분부터**만 체결 봉의 사후 폭으로 쓰고 재계산 | \|Δ평균\| ≤ 2bp **and** \|Δ승률\| ≤ 2pp | B |
| **L2P** 채점 파리티 | 합성 5분봉 경로 300개(체결 봉에 체결 *이전* 유리 극단을 크게 심음)를 백테스트 라벨 함수와 라이브/섀도우 채점기에 같이 통과 | max\|Δ\| ≤ 0.01bp | B' (백테스트↔라이브 규약 불일치) |
| **L3** 피쳐 누수 | 단일 피쳐 AUC(TRAIN) · HGB 분류기 VAL AUC · 선언된 스태킹 피쳐의 OOF 출처(TRAIN 행에 `final` 출처 금지) · **조인 시점**(결정 시각 행의 `log_return`이 klines의 마감봉 수익률과 상관 1.0이어야 함 — 다음 봉과 1.0이면 한 봉 미래참조) · (선택) 피쳐를 한 봉 과거로 밀어 재학습 | 단일 ≥0.95 / 모델 ≥0.99 / OOF 위반 / 조인시점 다음봉 → FAIL. 밀어도 VAL·OOS 둘 다 안 나빠지면 FLAG | C, `move_atr_mult`류, **09-01 exit 스모크의 다음봉 조인(+0.10 AUC)** |
| **T1** 너무 완전한 통과 | 대조군 보고서(base vs 귀무 95백분위)를 다시 채점 | 전부 통과 **and** (DSR ≥ 0.99 or PBO ≤ 0.05) → FLAG | 메타(A·B가 둘 다 이 패턴) |
| **T2** 수치 취약성 | float64 DF / float32 배열 / 컬럼순서 셔플 3변형으로 같은 시드 재학습 → 유지율 선별 평균(VAL·OOS) | 부호 반전 FAIL · 변형간 폭 > \|중앙값\|×0.5 FLAG | 메타(추정치가 0과 구별되는가) |

FLAG(T1/T2)는 L1/L2 재구성 PASS로만 해소된다. **매 기능 추가마다가 아니라 층 출력이 바뀔 때 그 층
게이트를 다시** 돌린다.

## 4. 설계 중 배운 것

1. **`cluster_dedup`은 "발동 시점에서 재계산"만으로는 안 잡힌다.** 앵커는 군집의 최극단이라 자기
   known_ts에서 데이터를 잘라도 부분 군집의 최극단은 여전히 자기 자신이다(missing 0). 잡히는 건
   **known_ts 직전에서 잘랐을 때 나오는 유령 발동**(그 시점엔 앵커였다가 미래가 오면 다른 봉에
   밀려나는 것)이다. L1이 두 절단을 다 하는 이유.
2. **T2는 부호 안정만으론 관대하다.** 정직 라벨 VAL이 세 변형에서 전부 양수(+0.8/+4.7/+2.7)였지만
   변형간 폭 3.9bp가 추정치보다 크다 — 그 크기에서는 믿을 수 없다. `폭/|중앙값| > 0.5` FLAG를
   추가했다. 09-03 retest가 본 부호반전(+2.16/−4.55/−7.52)은 다른 표본(depth3/wait6 부분집합)이라
   같은 현상의 강한 판이었을 뿐이다.
3. **L2는 재구성 전에 라벨을 정확히 재현해야 한다.** 게이트가 파이프라인의 청산·비용·명목 공식을
   모르면 대조 자체가 무의미하다. `(move−cost)×notional`과 `move×notional−cost` 둘 다 시도해 맞는
   쪽을 기록한다(v1은 전자).
4. **저장된 행 인덱스는 반드시 타임스탬프로 검산한다**(L4 ①). v1은 정합했지만 BTC에서 108봉
   오프셋이 대조군을 통과하고 살아남은 전례가 있다.

## 5. 다음 파이프라인에서 쓰는 법

층 출력을 동결(sha256)하기 **전에**:

```
tmp/<pipeline>/gate_config.json   # 계약 -- 아래 항목을 파이프라인 작성자가 명시
python scripts/gate_eth_entry_layers_20260903.py --pipeline tmp/<pipeline>
```

- `known_ts`: raw 트리거면 `assumption` 한 줄(왜 봉 마감에 계산되는지), 확정 지연 트리거면 `fires` 표에
  `known_ts` 열. **선언이 없으면 L4 FAIL** — 이게 강제력의 핵심이다.
- `trigger.module/fn`: `build_fires(kl) → DataFrame[timestamp, …, known_ts]`. klines만 받아야 L1이 자를 수 있다.
- `label`: 체결표 열 이름 + 청산 파라미터 + 비용 + 명목. 게이트가 라벨을 재현 못 하면 FAIL.
- `scoring_parity`: 라이브/섀도우 채점기가 생기는 **즉시** 선언(어댑터는 `LIVE_ADAPTERS`에 추가).
- `features.frame`: 봉 인덱스 피쳐 프레임을 저장해 두면 한 봉 밀기 트립와이어가 돈다.
- 층 출력이 바뀌면 그 층 게이트만 다시. `layer_gates.json`의 `verdict`가 BLOCKED면 다음 층 착수 금지.

## 6. 한계 — 게이트가 못 하는 것

- **5번째 메커니즘.** A~D 재발과 인접 부류를 막는다. 새 메커니즘에 대한 방어는 게이트가 아니라
  "헤드라인 수치를 다른 경로로 한 번 더 계산하기 전엔 그 위에 쌓지 않는다"는 규율 + T1/T2 트립와이어다.
- **검정력.** 독립 일수 42~45일, HOLDOUT 소진은 게이트가 바꾸지 못한다. 게이트는 *다음 시도를 믿을 수
  있게* 만들지 *데이터를 충분하게* 만들지 않는다.
- ETH 전용(1분봉 `ETHUSDT-1m-api.csv`가 2026-07-31까지 — 그 뒤 체결은 L2에서 미커버로 빠진다).
  BTC/XRP는 klines 경로와 라이브 어댑터만 바꾸면 되지만 아직 안 했다.
- L2P 어댑터는 라이브 채점기마다 하나씩 써야 한다(상태기계 인터페이스가 제각각) — 그 어댑터 자체가 테스트다.
- D형(트리거 정의가 라벨 필요조건을 100% 강제)의 **정의 수준** 점검은 여전히 사람이 한다. L4의
  "라벨 시작 ≥ known_ts" 계약이 V자반등 형태(확인창=라벨창 공유)는 막지만, 같은 시점 구조의 동어반복은 못 막는다.
