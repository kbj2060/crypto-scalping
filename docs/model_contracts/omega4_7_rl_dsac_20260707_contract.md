# Omega4.7-RL (omega4_7_rl_dsac_20260707) — RL successor experiment, REJECTED

Status: `rejected_research_not_live_wired`. Requested 2026-07-07: keep ONLY Omega4.6.1's feature
processing and replace the entire model stack with a from-scratch reinforcement-learning agent,
named as the next version.

## What was kept from Omega4.6.1

- The zig075 bundle's 102-column base feature contract (`bundle["base_cols"]`) and its exact
  numeric coercion (`parent._base_input` semantics: reindex -> to_numeric -> inf->nan -> fillna(0)).
- The same fee/slip cost source (`omega._load_fee_slip()`, cost_mult 1.0) and the same frame
  loaders (2025 CSV + regime3 wide24 overlay; `retest.load_frame_current` for 2026).
- Nothing else: no TabM parent, no risk sidecar, no TP/SL barrier, no greedy router, no duration
  gate.

## Architecture (researched choice)

Discrete Soft Actor-Critic (discrete SAC, Christodoulou-2019 style): twin Q-networks + categorical
policy + automatic entropy temperature, 2x256 SiLU MLPs. Chosen because (a) it is the
discrete-action analogue of the DSAC lineage already present in this repo
(`ensemble/train_rl_dsac_*.py`), (b) max-entropy RL is the standard defense against degenerate
single-action policy collapse on financial tapes, (c) the action space ({CASH, LONG, SHORT},
fixed notional 1.0, no sizing) is naturally categorical.

State = z-scored 102 features (TRAIN-window statistics only) + position context (pos,
unrealized_move, hold/288). Reward = position * next-bar return - (fee+slip) * |position change|,
x100 scaling. Episodes: 576-step random-start segments of the TRAIN tape.

## Protocol (Fresh-Forward-aware)

TRAIN 2025-01-01..09-30 (agent training ONLY; strictly pre-VAL, no leakage). VAL 2025-10-01..12-31
(checkpoint + seed selection: greedy-policy rollout every 10k steps, best-VAL checkpoint kept per
seed, best seed selected on VAL). OOS 2026-01-01..06-30 (ONE shot with the frozen selected agent;
other seeds' OOS reported for transparency only). `fresh_forward_bar_by_bar=true`,
`trade_ledgers_used_as_input=false`, `saved_parent_exit_timestamps_used=false`,
`future_rows_used_for_entry=false`. Stored-tape based -> diagnostic research score.

## Results

### v1: 5-minute decisions (STRIDE=1, target_entropy=0.6*log3), 3 seeds x 150k steps

| seed | best VAL | OOS |
|---|---|---|
| 0 | -96.11% / n=2491 / wr 0.469 | -99.84% (transparency) |
| 1 | -97.23% / n=2976 / wr 0.462 | -99.98% (transparency) |
| 2 (VAL-selected) | -93.39% / n=2424 / wr 0.485 | **-99.26% / n=3628 / wr 0.470 (one-shot)** |

Catastrophic. The policy churns thousands of position flips; fees+slippage consume the account.
Learning curves DID improve monotonically (wr 0.25 -> 0.48 over training) but converged nowhere
near cost-viability -- the classic RL-on-price-tape failure mode (per-bar reward SNR far below the
cost hurdle).

### v1.1: hourly decisions (STRIDE=12), lower entropy target (0.3*log3) — the "lower frequency is
the lever that works" fix from this project's Sigma3/Sigma6 history

| seed | best VAL | OOS |
|---|---|---|
| 0 | -58.49% / n=787 | -91.27% (transparency) |
| 1 | -54.00% / n=738 | -87.38% (transparency) |
| 2 (VAL-selected) | -35.97% / n=730 / wr 0.414 | **-87.73% / n=1575 / wr 0.371 (one-shot)** |

Better (about 60pp less bad on VAL) but still deeply negative everywhere; the agent still trades
~1/3 of all hourly decision points and never learns that CASH is usually optimal after costs.

Reference: the frozen Omega4.6.1 live baseline scores +145.34% / MDD -10.13% / 24 trades on the
same OOS window (different sizing, so compare sign/shape: 24 trades in 6 months vs 1,575).

## Verdict

**REJECTED.** Two structured attempts (5m and 1h decision frequency, tuned entropy), consistent
multi-seed behavior, VAL-select/OOS-confirm discipline respected. Model-free RL directly on this
feature tape cannot overcome the transaction-cost hurdle at any tested frequency -- consistent
with (a) the Candidate 6 finding (even a supervised offline-RL-style exit model overfits its
selection window here), (b) the project-wide pattern that trade sparsity is the binding
constraint: the profitable behavior on this tape is "act ~24 times in 6 months", which gives an
RL agent almost zero positive-reward experiences to learn from, while every exploratory action it
takes costs real fees. The supervised decompose-then-gate stack (Omega4.6.1) remains structurally
better suited to this problem than end-to-end RL.

If this direction is ever revisited, the two levers most likely to matter are: (1) constraining
the RL agent to choose only among high-quality candidate entries generated by a supervised parent
(hybrid, not end-to-end -- i.e., RL as router/sizer, which is close to what the rejected
Candidates 3/4 already tested in simpler learned forms), and (2) reward shaping with explicit
cost-aware action budgets. Neither is expected to beat the frozen baseline given six consecutive
failed upgrade candidates.
