> 페이지를 고치려면 그 URL 을 `url` 인자로 넘겨 재배포한다(새로 publish 하면 별개 아티팩트가 된다).

> 실험 원문은 §8 링크. 수치는 전부 재현 가능한 스크립트와 짝지어져 있다.

## 1. 한 장 요약

Omega4.6.1 부모(L2)를 **되살린 데이터로 다시 학습**했다. 데이터 구멍 둘(펀딩·라벨)을 모두
메웠고, 부모는 잘 학습된다. **그런데 아직 배포본을 유의하게 이기지 못했다.**
Zeus 는 여기서 멈추지 않고 **L4 리스크 사이드카 → L5 exit 머리 → L6 라우터**를 차례로
붙이는 프로젝트다.

**현재 최선 후보**: `base/old/대칭게이트`(= L0 라벨)
VAL 2026-03~06(독립일 122)에서 총 **+7.84bp** · 중앙 건당 **+2.55bp** · 양수일 54.2% ·
롱비중 50.8%(편향 없음) · 모델−숏 +5.33 [−2.33, +13.52].
🔴**유의하지 않고**, 🔴**20개 넘는 구성 중 최고를 같은 창에서 고른 값**이다(§6).

## 2. 확립된 사실

### 2.1 데이터 — 구멍 둘을 메웠다
| | 옛 상태 | 지금 |
|---|---|---|
| 펀딩 | 2022·23·24 **전량 중앙값** | `/fapi/v1/fundingRate` **5,343건**(2021-11~2026-09) 실값 |
| 중앙값 채움 | 324,577행 (65.6%) | **0행** |
| 연도간 상수열 | **11개**(`ou_halflife` 포함 — L8 게이트의 그 열) | **3개**(2022 롱숏비, 바이낸스 이력 한계) |
| zigzag 라벨 | 2024·2025·2026(1~2월)만 | **2021-12 ~ 2026-08** |

⭐**zigzag 생성기는 커밋돼 있었다** — `scripts/build_wave3_action_labels_20260531.py`.
파일명이 wave3 라 이름 검색에 안 걸렸고 내부 `DEFAULT_OUT` 이 `zigzag_action_labels_20260531`
이다. 손대지 않고 돌리니 **2024·2025 가 행 단위 완전 재현**(210,481행 일치율 1.000000).
→ 역공학 시도는 불필요했다. **산출물 이름이 아니라 산출물 «경로»로 코드를 찾는다.**

### 2.2 학습창 깊이 — 중립, 그리고 경제적으로는 해롭다
배포 부모의 실TRAIN 은 **2025-01~09 한 해**(78,509봉)뿐이다. 5.6배(437,713봉)를 줘도:
- bacc 는 **올라간다**(0.5803 vs 배포 0.5686)
- 🔴**중앙 건당 bp 가 음수**(−2.91/−1.81/−1.34) — 거래 절반 이상이 지고 꼬리가 평균을 올린다
- 🔴편향을 빼도 안 살아난다(최고 +3.98)
- 🔴**구조적 탈락**: TRAIN 이 2022~2026 전체라 **아래층이 쓸 깨끗한 구간이 없다**

⇒ **deep 은 부모 후보에서 제외.** base 는 덜 배웠기 때문에 **2022-01~2024-12(315,648봉)**가
통째로 깨끗하게 남고, 통과율 3.5%면 **약 11,000건**의 후보 — exit 머리의 12,000 샘플과 맞는다.

### 2.3 포지션 편향 — 제거했고, 빼도 엣지가 남는다
편향의 출처는 학습 가중치였다: `balanced(y_전체) × route_prob` 가 **클래스 균형을 전체에서
잡고 라우팅을 나중에 곱해** bull 전문가에게 LONG 과대표집 분포를 준다.
- **학습단 제거(new)** 는 작동한다(롱비중 시드폭 .194→.137, 대칭 게이트가 무의미해짐)
  🔴그런데 **돈이 떨어진다**(+6.93→+4.29). 라우팅 뒤 클래스 불균형은 **정보였다**.
- **결정단 대칭 게이트**만 씌우면 롱비중 26.6→**50.8%** 로 균형이 되면서 **총bp 가 오르고**
  (+7.84) **모델−숏이 +1.49 → +5.33** 으로 커진다. ⇒ **편향을 빼도 엣지가 남는다.**

### 2.4 손익 집중도 — "한두 건 운"은 base 가 아니라 **배포본**
| | 중앙 건당bp | 양수일 | 최고1일 지분 | 상위3일 지분 |
|---|---|---|---|---|
| 배포본 | +0.64 | 45.1% | **27.0%** | **67.0%** |
| base | +0.12~+1.33 | 48~**52.7%** | 15.2~27.1% | 42.1~73.4% |
| deep | **−2.91~−1.34** | 43.7~48.6% | (분모≈0, 무의미) | — |

### 2.5 라벨 설계 — 현행이 이미 거의 최적
라벨은 **봉 하나가 아니라 구간 전체**다(LONG 918구간·중앙 34봉·최대 441 / CASH 5봉).
`zigzag_soft_*` 가 이미 존재하나(soft_long 평균 .7395) **학습 손실에 안 들어간다**.
| 판 | 총bp | 중앙 | 양수일 |
|---|---|---|---|
| 버퍼2/hard(현행) · 버퍼2/smoothing | **+7.84** | +2.55 / **+2.64** | 54.2% |
| 버퍼2/soft | +7.21 | +1.09 | **60.4%** |
| 버퍼0/soft | +6.56 | +2.03 | 52.5% |
| 🔴버퍼0/hard | +3.15 | **−2.51** | 44.3% |
🔴**버퍼 축소는 해롭다** — 그 5봉은 **피벗에서 방향이 뒤집히는 구간**이고 확신 라벨을 붙이면
「곧 반대로 갈 봉」을 롱이라 가르친다. **soft 는 라벨이 더러울 때의 보험**으로 작동한다
(버퍼0 에서 +3.15/−2.51 → **+6.56/+2.03**).

### 2.6 h48qual — `fee_cost` 는 비용이 아니라 **선별 문턱**이다
배포 h48qual 은 같은 VAL 에서 **83건(0.7건/일)** 만 쏜다. 품질 라벨이 경제 라벨이고
`fee_cost = (5bp+2bp)×2다리×3배 = 42bp` 인데 `min_tp` 가 60bp 라 대부분 CASH 가 된다.
배리어 시뮬을 원래 값으로 **99.93% 재현**한 뒤 비용만 쓸어보니:

| fee_cost | 라벨 활성률 | 재학습 후 건/일 | 총bp | 중앙 |
|---|---|---|---|---|
| **42bp**(현행) q=0.50 | 59.8% | 3.9 | +3.26 | **+4.34** |
| **42bp 대칭보정** | 59.8% | **11.5** | **+3.88** | +2.37 |
| 3.06bp(USDC×3) q=0.50 | 78.7% | 30.1 | +1.21 | +1.56 |
| 1.02bp(USDC×1) q=0.50 | 79.6% | **32.5** | +1.09 | +1.38 |
| 1.02bp 대칭보정 | 79.6% | 8.7 | **−0.29** | +0.71 |

⭐**실측 비용(1.02bp)으로 "정정"하면 라벨로서는 나빠진다.** CASH 가 40%→20% 로 줄며 품질
머리가 걸러낼 게 없어지고, 골라 쏘게 만들면 총bp 가 음수가 된다(순위가 나빠졌다는 뜻).
42bp 는 "우리가 내는 비용"이 아니라 **"이 정도는 벌어야 후보로 친다"는 문턱**으로 일하고 있었다.
⭐**발화율 문제의 절반 이상은 라벨이 아니라 `q=0.50` 고정 임계값이었다** — 같은 라벨로
대칭보정만 걸어도 0.7 → 11.5건/일(16배).

### 2.7 두 부모의 성질이 상보적이다
`runtime_contract.json` 실측: **두 부모의 방향 라벨은 동일한 zigzag** 이고 차이는 품질 머리뿐이다.
| | direction | quality | q |
|---|---|---|---|
| h48qual | zigzag | **h48_conservative** (48봉=4시간, TP=max(0.6%,1.2·vol), SL=max(0.4%,0.8·vol)) | 0.50 |
| zig075 | zigzag | **zigzag (동일)** | 0.75 |
두 타깃 일치율 **50.9%**. 같은 창·같은 시드에서 품질 타깃만 바꾸면:
- **zigzag 품질** = 총량에 강함 (+7.84bp, 7.4건/일)
- **h48 품질** = 적중률에 강함 (양수일 **59.1%**, q=0.50 이면 중앙 **+4.34bp**)

## 4. 열린 결정 (다음 세션이 먼저 답해야 할 것)

1. **앙상블을 번들에 담을까?** 5시드 앙상블이 현행 번들 스키마에 안 들어간다
   (`bundle["models"][expert]` 가 전문가당 단일 모델). 담으려면 **라이브 어댑터
   `_load_tabm_models` 를 손봐야** 하고 그건 라이브 경로 변경이다. 단일 시드로 내려가면
   시드 분산(+3.13~+4.53)이 돌아온다.
2. **부모를 하나로 갈까 둘로 갈까?** (a) zigzag 품질 단일 (b) h48 품질 단일
   (c) **둘 다 + 라우터** ← 원래 Omega4.6.1 설계, 성질이 상보적이라 이제 말이 된다.
3. **L4 리스크 사이드카를 먼저**(권고) — exit 머리가 `pos_notional/leverage/exposure` 를
   요구하는데 사이드카가 없으면 상수로 때워야 하고, 계약상 `risk_sizing_source` 명시 의무가 생긴다.

## 6. 🔴반드시 지킬 규약

- **선택편향이 이미 쌓였다.** 20개 넘는 구성을 같은 VAL(독립일 122)에서 비교하고 최고를
  인용하고 있다. 잡음 ±2~3bp 에서 그만큼 부풀려진다
  ([[feedback_selection_is_the_thing_to_walk_forward_20260915]]). **+7.84 는 기대값이 아니다.**
- **층마다 자기 창**을 갖는다. 같은 VAL 에서 연속으로 고르지 않는다.
- 각 층은 붙이기 전 **증분**을 재고 CI 가 0 을 배제 못 하면 **안 붙인다**(헤드라인이 올라도).
- **single-touch OOS 2026-07-01~09-30 은 조립 완료본 한 번**에만 쓴다.
  **2026-09-17 현재 미접촉.** 라벨은 2026-08-30 까지 있으므로 언제든 검정 가능하다.
  ⚠️검정력 주의: OOS 92일 · 통과율 3.5% ⇒ 약 930건/독립일 90 으로 **VAL 보다 적다.**
- **모델−롱과 모델−숏을 항상 같이** 내고 **약한 쪽으로 판정**한다
  ([[feedback_report_excess_over_both_legs_always_20260917]]).
- **평균만 보지 않는다** — 중앙 건당bp · 양수일 비중 · 최고1일 제거를 같이 낸다.
- 층 출력이 바뀌면 `scripts/gate_eth_entry_layers_20260903.py` 를 그 층에 다시 돌린다.
- exit 머리를 만들 때 **Position-Feature Train/Inference Parity 계약**을 먼저 읽는다
  (`pos_unrealized/mfe/mae` 는 notional 곱하지 않은 원시 변동률, `pos_tp/pos_sl` 은 라벨
  배리어가 아니라 **라이브 ATR 공식**으로 독립 계산, 배리어 판정은 intrabar 인데 exit 머리
  입력은 종가 — **두 컨벤션이 공존하므로 통일하면 안 된다**).
