### 2-2. 손절·주문에 관한 사용자 결정 (질문지 · `docs/rtcore_design_20261120.md` §0)

- 손절은 거래소 주문이 아니라 **대시보드 서버의 감시**(`bracket_tick`)다. 거래소에는 익절 지정가만 있다. −5% 거래소 스탑은 파이썬·Rust 모두에서 뺐다. 앱은 손절 판정에 관여하지 않는다.
- 새 주문 설계는 지정가만. 이미 있는 시장가 분기는 그대로 둔다(손절·익절 청산 잔량, 진입 잔량).
- 자동 물타기·전량 청산·근거 신호 표식은 옮기지 않는다. 뉴스 판정·로컬 LLM 은 전환 범위 밖.
- 포지션 위험은 읽기 전용이고 손절은 사용자가 한다(기존 원칙 그대로).

### 2-3. 1.0 기준 커밋이 낡았다

앱 설계의 기준은 main `ec0d977f` 다. 그 뒤 휴대폰 화면에서 주문 막대가 사라졌고 주소가 줄었다. 재개 절차(앱 설계 «보류» 절)의 ①~④를 새 main 으로 다시 한다: `shape.py --check` → 휴대폰 실호출·실응답 재수집 → `net.rs`·`ENDPOINTS.md` 갱신 → 기준 화면 재캡처.

### 2-4. 응답 모양은 앞으로도 바뀐다

- 화면이 실시간 코어를 구독하게 되면(브랜치 `claude/rt-screen-subscribe-20261121` 에서 «그림자» 단계 진행 중) 수급·풋프린트·시세는 SSE(`/api/stream`·`/api/events`) 대신 `/rt` 밀기로 온다. SSE 는 통과 판정 전까지 같이 돈다.
- 응답 서버를 Rust(`rtserve`)로 바꿀 때 통과 기준은 «실응답 사본과 본문 일치»다. 즉 `/api/*` 모양은 유지하는 것이 목표다. 주소 목록 문서(`docs/rtserve_routes_20261121.md`)는 작성 중이다.

## 4. 이 세션이 만든 것 중 앱이 가져다 쓸 것

### 4-1. 실시간 코어의 메시지 규격 — `rtcore/src/proto.rs`

- serde 만 쓰는 모듈이다(tokio 없음). 화면 크레이트가 그대로 가져다 쓰라고 그렇게 뒀다.
- 다만 `rtcore` 크레이트 자체는 tokio·웹소켓에 기댄다. 앱이 이 형을 쓰려면 ① `proto.rs` 를 작은 크레이트로 떼어 내거나 ② 파일을 경로로 끼워 넣어야 한다. **아직 안 했다 — 앱 세션이 정할 것.**
- 접속 규칙(`hub.rs`): 웹소켓 경로 `/rt` → 첫 메시지 `{"subscribe":["ethusdt", …]}`(10초 안 · 최대 8종목) → 종목마다 스냅숏 1회 → 이후 사건마다 밀기. `seq` 가 비면 끊김이니 다시 붙어 스냅숏을 받는다. 서버가 20초마다 ping. 동시 연결 16.
- 모든 메시지에 시각 셋: `ex_ms`(거래소 사건) · `rx_us`(코어 수신) · `tx_us`(코어 송신). 앱이 «사건 → 그림» 지연을 스스로 잴 수 있다.
- 메시지 종류: `trade` · `book` · `mark` · `snapshot`(1초 수급 전체 + 풋프린트 144봉 + 주문용 시세 + 5분 청산 원) · `supply1s` · `footprint` · `liq` · `flow` · `oi` · `kline`(마감 1분봉) · `prices`(전 종목 마지막 체결가 · 0.1초마다 바뀐 것만) · `liq5m`.
- **읽기 전용 시세만 나간다.** 계좌·포지션·주문 상태는 이 문으로 안 나간다(다른 문을 따로 두기로 했고 아직 없다). 앱의 계좌 카드·주문 상태는 당분간 HTTP 다.
- 인증: 코어는 사람을 확인하지 않는다(앞단 Cloudflare Access 몫). Origin 머리가 없는 접속(= 앱)은 받는다. 앱은 서비스 토큰 머리를 웹소켓 핸드셰이크에 실으면 될 것으로 «추정»한다 — Cloudflare 문서에 명시가 없어 **시험이 필요하다**.

### 4-2. egui 풋프린트 카드 — `rtui/`

- 앱 시제품과 같은 eframe/egui 0.37 이다. 풋프린트 그리기(`fp.rs` · `draw.rs`) · 레인(`lane.rs`) · 표식(`marks.rs`) · 프로파일(`profile.rs`) · 가리킴(`hover.rs`) · 코어 구독(`feed.rs`)이 있다. 웹 화면의 요소 17개는 아직 안 옮겼다.
- 데스크톱 1920 배치를 겨냥해 쓴 코드다. 휴대폰 배치는 따로 맞춰야 한다.
- 글꼴: Pretendard 400·700·800 + JetBrains Mono 400·700 을 쓰는 글자만 추린 판(`rtui/fonts/README.md` · `subset.sh` · ttf 는 gitignore). 앱의 한글 표시에 그대로 쓸 수 있다.
- 상태: 웹 화면을 egui 로 계속 옮길지는 «윈도 크롬 실측을 보고 결정»으로 멈춰 있다(개발기 측정은 중앙값이 거의 같고 가끔 크게 늦는 값만 나았다). 이 판정은 웹 화면에 대한 것이고 앱과는 별개다.

### 4-3. 주문 규칙표 — `rtorder/RULES.md`

- 접수 문(G) · 계획 조립(P) · 지정가 집행(E) · 대기 주문(W) · 브래킷(B) · 청산(C) · 재시작(R) · 계좌 알림(A) 의 규칙 번호와 원본 줄 번호. «sltp 만» 정리 절에 없어진 규칙이 있다.

## 5. 지킬 것 (사용자 지시 · 전부 유효)

- **실주문 시험 절대 금지.** 주문 경로는 가짜 서버로만. 첫 실사용은 사용자가 최소 수량으로.
- 개발기에서 거래소에 접속하지 않는다(REST·웹소켓 모두 · 서버와 IP 한도를 같이 쓴다). 개발기에서 대시보드 서버를 띄우지 않는다.
- 환경 파일(작업 폴더의 점-env)은 열지 않는다. 실키가 있을 수 있다.
- 공개 저장소다. 계좌 값·키·개인 정보·실응답 원본을 커밋하지 않는다. 도메인·터널 ID·토큰도 문서에 적지 않는다.
- 서버 접속은 기본 읽기 전용. 서버 상태를 바꾸는 일은 사용자가 고른 것만.
- 머지: Rust·문서만 바뀐 묶음은 시험 재실행 + CI + `bash scripts/ops/check_deploy_drift.sh`(메인 체크아웃에서 · 종료코드 0) 통과 뒤 묻지 않고 머지. 서빙 코드(`dashboard/**` · `live/execution/**` · `scripts/live_*.py`)는 매번 사용자에게 묻는다 — 머지하면 대시보드가 재시작되고 손절 감시가 그 안에 있다.
- 웹뷰 껍데기(TWA·Tauri)를 다시 권하지 않는다(사용자가 Rust 재작성을 골랐다).
- 휴대폰 웹 화면을 고칠 일이 생기면: 데스크톱 1920 이 한 픽셀도 안 바뀐 것을 비교로 보이고, `/impeccable` 절차를 따르고, 트레이딩룸 아티팩트를 다시 올린다.
- 답은 한국어. 커밋·PR 에 서명 줄을 붙이지 않는다. 맨 `git stash` 금지.

개발기에서 자주 걸리는 것
- cargo 는 `export PATH="$HOME/.cargo/bin:$PATH"` 뒤에 쓴다. 새 빌드·시험은 `ulimit -v` 안에서(프로세스 하나의 메모리 초과가 WSL 전체를 내린 적이 있다).
- 꾸러미마다 폴더와 `Cargo.lock` 이 따로다(빌드가 서로 기다리지 않게). 하나로 묶는 것은 실행 파일을 합칠 때.
- 원격 작업에서 `pgrep -f` 는 자기 명령줄에도 걸린다 — `pgrep -x <이름>` 이나 PID + `/proc/<pid>/cmdline` 확인.
- 다른 작업 폴더의 파일은 이 세션 도구로 못 고친다(훅이 막는다) — 그 폴더로 들어가서 한다.
- 그래픽 카드는 AMD Radeon RX 9060 XT. WSLg 창 모드는 GPU 를 쓰고 머리 없는 실행은 소프트웨어 렌더다.

## 6. 아직 정해지지 않은 것 (앱 세션이 사용자에게 물을 것)

1. **재개 시점.** 11-20 결정은 «웹 속도 최적화가 끝날 때까지 앱 보류»였다. 지금 Rust 전환은 진행 중이다(화면·주문은 아직 파이썬). 지금 재개하면 1.0 기준과 계약을 전환이 끝난 뒤 한 번 더 옮겨야 한다.
2. **실시간 자료를 어디서 받을지.** (가) 지금 웹처럼 SSE + 바이낸스 체결 웹소켓 (나) 처음부터 `/rt`. (나)는 Cloudflare `/rt` 규칙과 서비스 토큰 웹소켓 시험이 먼저 필요하다. 이 세션의 권고는 (나) — 전환 뒤 SSE 는 사라질 길이고, 폰이 바이낸스에 직접 붙지 않아도 된다.
3. **`proto.rs` 를 떼어 낼지**(4-1).
4. **계좌·주문 상태의 밀기 문**: 설계만 있고 없다. 앱 1.0 은 지금 웹처럼 `/api/events` 의 `acct_seq` + `/api/binance-account` 로 간다.
5. Cloudflare 에서 사용자가 할 일: `/rt` 규칙 · 서비스 토큰 2개 · 주문 경로 앱 분리(앱 설계 §6 · 브라우저 경로 문서 §5).
6. 알림(FCM)은 서버에 발송기를 더해야 한다 — 서빙 코드 변경이라 머지를 물어야 한다.
