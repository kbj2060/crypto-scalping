## 0. 먼저 — 이미 닫힌 문 세 개

설계를 읽기 전에 이걸 봐야 한다. 이 방향은 여러 번 시도됐고 대부분 닫혀 있다.

| 축 | 시도 | 결과 |
|---|---|---|
| **전체 lifecycle RL** | 10회+ (DSAC 5변형, Dueling DQN, HMM+DQN, IQL/CQL) | ⛔ `omega4_7_rl_dsac` OOS **−87~−99%** (같은 구간 라이브 +145%). SOL에서도 재현 = 자산 특이적 아님 |
| **Entry 축** | 7회 (지도 재순위 5 + 신규분류기 1 + selective classification 1) | ⛔ AUC 0.51~0.52. Schapire 약학습성상 γ≈0이면 **어떤 wrapper도 값을 못 뽑는다** |
| **증거신호 → 매매 연결** | 5회 (confluence 36칸, forced-exit veto, exit_head 피쳐, 사이징 피쳐) | ⛔ 전부 실패 |

**전체 lifecycle 실패의 근인은 아키텍처가 아니라 보상 희소성이다.** "6개월에 24번 행동"이
정답인데 RL은 탐색 중 수천 번 행동하고 매번 비용을 낸다. 아키텍처를 바꿔도 안 풀린다.

### ⚠️그리고 이 재료에 대한 직접적 부정 증거가 이미 둘 있다

1. **Entry 스모크**: 증거신호 6종을 추가한 v1이 v0보다 **전 지표 더 나빴고**, 순열중요도 상위 15에
   증거신호가 **0개**였다.
2. **Exit 스모크**: v0(23 pos피쳐)과 v1(+증거신호 6종 12열)의 VALIDATION 확률이 174,171행 전부
   **소수점까지 완전 동일**(diff=0.0). HGB가 300회 부스팅 내내 `pos_hold_bars`(중요도 0.152,
   2위의 6배)에 압도돼 증거신호 열을 **단 한 번도 분기에 쓰지 않았다**.

**따라서 이 설계의 첫 단계는 RL이 아니라 "세 번째 0인지 확인하는 킬 게이트"다.**

## 1. 남아 있는 유일한 축 — Exit timing, 그중 timeout 버킷

2026-09-01 exit 스모크테스트가 entry축과 **정성적으로 다른 최초의 결과**를 냈다:

| | checkpoint AUC (VALIDATION) |
|---|---|
| entry 축 7회 시도 | 0.51 ~ 0.52 |
| **exit 전체** | **0.7125** |
| sl 종료(21%) | 정의불가(단일클래스) — 사실상 `dist_to_sl` 재구성, 예측 아니라 기하학 |
| tp 종료(6.5%) | 정의불가 — 이익 대부분 반납(+740bp → +49bp) |
| ⭐**timeout(72%)** | ⭐**0.6101 — 진짜 불확실한 구간의 순수 신호** |

**설계 대상은 timeout 버킷의 exit timing이다.** 나머지 둘은 하드 규칙(TP/SL)이 이미 지배한다.

### 왜 이 축은 보상 희소성을 피하는가

**포지션이 열려 있는 매 봉이 결정 지점이고, 각 결정에 즉각적인 보상이 정의된다.** entry처럼
"6개월에 24번"이 아니라 열린 포지션의 모든 봉이 학습 신호다. lifecycle RL을 죽인 구조적 문제가
**정식화 자체로 사라진다.** 이게 이 축을 고른 첫째 이유다.

---

## 2. 왜 지금 다시 볼 근거가 있는가 (그리고 왜 부족한가)

exit 스모크의 "증거신호 기여 0"은 **옛 형태의 증거신호**로 잰 값이다. 그 사이 세 가지가 바뀌었다:

| 그때 (2026-09-01) | 지금 (2026-09-02 재료화) |
|---|---|
| **앵커 모집단** 학습 모델의 확률 | **인과 모집단** 재학습 — 라이브가 실제로 보는 분포와 일치 |
| **희소 이진 플래그** (발화율 1~3%) | **매 봉 조밀 텐서** — 활성 0인 봉 4.6%, 봉당 평균 3개 |
| 신호별 제각각 척도 (0.235~0.808) | **백분위 정규화** — 전부 0.48~0.62, 교차비교 가능 |

⭐**세 번째가 특히 중요하다.** exit 스모크의 실패 모드는 "HGB가 증거신호 열을 한 번도 안 썼다"
였는데, 그건 **척도 경쟁 문제**다 — `pos_hold_bars` 같은 지배적 피쳐와 경쟁하려면 열이 균등하고
조밀해야 한다. 백분위 정규화는 정확히 그 문제를 겨냥한다.

**그래도 두 번의 0을 뒤집기엔 부족한 근거다.** 그래서 킬 게이트를 먼저 둔다.

## 3. Phase 0 — 킬 게이트 (지도학습, RL 아님)

**질문 하나**: 새 재료 텐서가 timeout 버킷 AUC **0.6101**을 움직이는가?

### 3-1. 하네스와 모집단

- 하네스: `scripts/research_eth_rl_exit_gate_oracle_smoketest_20260901.py` 재사용
- **후보 풀 = h48qual/Omega의 `dir_action≠0` 원시 진입 후보** — 증거신호 발동이 아니라
  **기존 라이브 매매 시스템의 진입 후보**다. 따라서 Phase 0이 답하는 질문은 정확히:
  > "기존 매매 시스템이 이미 연 포지션을, 증거신호 재료가 더 잘 닫게 해주는가?"
  증거신호 자체가 연 포지션의 청산을 묻고 싶어도 지금은 불가능하다 — 증거신호의 **진입**이
  앵커 미래참조로 막혀 있다(`eth_autotrading_promotion_audit_20260902.md` §8).
- 체크포인트: 후보마다 보유기간 10분위 내부 지점 9개(t=0은 진입봉, t=H는 이미 청산이라 제외)
- 오라클 라벨: "지금 청산하면 실제로 실현한 `price_move_raw`보다 나은가" — 새 시뮬레이션 불필요
- **timeout 후보만** (sl/tp는 단일클래스라 AUC 정의불가)

| 구간 | timeout 후보 | 체크포인트 |
|---|---|---|
| TRAIN (2025-01-01 ~ 09-30) | 43,451 | ≈391,059 |
| VALIDATION (2025-10-01 ~ 12-31) | **13,891** | ≈125,019 |

⚠️이 split은 h48qual 번들 자신의 OOF export split이고 **CLAUDE.md 표준 Fresh-Forward split이
아니다**(원 스크립트가 이미 명시). Phase 2에서 표준 split로 재확인한다.

### 3-2. ⚠️타임라인 정렬 — 재료를 2024-12-31로 롤백 재훈련

세 가지가 서로 다른 시점에 잘려 있어 그대로 쓰면 안 된다:

| | 학습 종료 |
|---|---|
| exit 후보 TRAIN | 2025-01-01 ~ **2025-09-30** |
| 재료 메타라벨 TRAIN (2026-09-02판) | < 2025-09-01 |
| clean 레짐 TRAIN (2026-09-02판) | ≤ 2025-08-31 |

**exit 후보 TRAIN의 8개월(2025-01~08)이 재료에게는 in-sample이다.** VALIDATION(10~12월)은
깨끗하므로 판정 자체는 정직하지만, 모델이 **학습 중에만 유난히 깨끗한 피쳐**에 과의존하게 된다 —
그게 entry 7전7패를 만든 "TRAIN 관계가 VALIDATION에서 안 살아남는" 패턴의 제조법이다.

**조치 — 롤링 재훈련(사용자 결정 2026-09-03)**: 재료 메타라벨과 레짐을 **TRAIN ≤ 2024-12-31**로
다시 잘라, 후보 창(2025-01~12) 전체가 재료에게 out-of-sample이 되게 한다.
- 비용: 서버 TabPFN 1회(~30분) + 레짐 재적합
- 대가: 재료 학습이 20개월 → 12개월로 줄어 모델이 약해진다. **보수적인 검정이 된다는 뜻**이라
  나쁘지 않다 — 약한 재료로 통과하면 진짜다.
- 대안(후보 풀을 표준 split로 재생성)은 h48qual 번들 재export가 필요해 훨씬 큰 작업이고,
  기준선 0.6101과의 비교도 끊긴다.

⭐**이건 일회성 조치가 아니라 원칙이다.** 레짐·재료는 **하류 모델의 평가창 직전까지만 학습한
버전**을 백테스트에 쓰고, 라이브에서는 "그 시점까지" 학습한 버전을 쓴다. 학습·서빙 양쪽에서
**"항상 과거만 본다"**는 성질이 동일해진다. (배포 레짐과 clean 레짐의 예측 일치율은 94.5~96.9%,
chop 비중은 소수점 셋째 자리까지 거의 같다 — 그래도 5%는 어긋나므로 이 정렬이 필요하다.)

### 3-3. 세 arm

| arm | state |
|---|---|
| **A (기준선)** | pos 피쳐 23종 + 기존 시장맥락/레짐 피쳐 — **0.6101을 재현해야 한다.** 재현 안 되면 하네스 버그 |
| **B (재료를 피쳐로)** | A + `<sig>_pct` 8열 + `<sig>_age` 8열 |
| **C (레짐을 게이트로)** | B + 기존 `regime_*_prob` 3열을 **롤링 clean S12_K3로 교체**하고, 피쳐가 아니라 **게이팅**으로 사용 — 레짐별 모델 3개(bull/bear/chop) 학습 후 예측 레짐으로 하드 라우팅(Omega4.6.1 MoE 선례) |

⚠️**정정**: 기존 스모크에 이미 `regime_bull_prob`/`regime_bear_prob`/`regime_chop_prob` 3열이
**평범한 피쳐로** 들어가 있었다. 그러니 C는 "레짐 추가"가 아니라 **"레짐의 사용 방식 교체"**다.

**왜 게이트인가**: 레짐은 예측 변수가 아니라 **맥락 변수**다. 피쳐로 넣으면 "chop일 땐 X가 이 뜻,
추세일 땐 저 뜻"이라는 상호작용을 모델이 스스로 발견해야 하고, 기존 스모크가 정확히 그 방식으로
실패했다. 그리고 2026-09-02 앙상블 실측이 이 관계를 직접 보여줬다 — **레짐 게이팅은 전역이 아니라
신호별**이다(`orthogonal_combo`는 chop에서 수혜 63→87건, `taker_delta_z`는 chop에서 역효과
15 vs 72). "레짐이 결과 수준을 바꾼다"가 아니라 **"레짐이 어느 신호를 믿을지를 바꾼다"** —
정의상 게이팅 관계다. 문헌 근거는 RG-ResMoE(arXiv:2608.12251), 단 반대 문헌도 있어 불확정이므로
**B vs C 비교 자체가 이 문제에서의 답이 된다**.

⚠️레짐별 3모델은 **선택 표면이 3배**가 되므로 DSR의 trial 수에 반영한다.

### 3-4. 사전등록 판정 기준

기존 초안의 "VAL AUC +0.010"은 검정력에 비해 헐거웠다. 체크포인트 125,019개로 보면 AUC 표준오차가
0.003 수준이라 3SE로 보이지만, **한 트레이드에서 나온 9개 체크포인트는 강하게 상관된다.**
실효 표본은 체크포인트가 아니라 **후보 수 13,891**에 가깝고 그러면 SE≈0.005 → +0.010은 2SE뿐이다.

> **B 또는 C가 A 대비 ΔAUC(VALIDATION)의 후보 단위 군집 부트스트랩 95% CI 하한 > 0 이고,
> 그 부호가 무작위 5시드에서 5/5 일치할 것.**
> 못 넘으면 **재료는 매매용으로 기여 없음(세 번째 0)으로 선언하고 RL 착수를 중단한다.**
> 재료는 표시·연구 자산으로 남긴다.

**부트스트랩은 반드시 후보 단위로 리샘플한다**(체크포인트 단위로 하면 상관을 무시해 CI가
가짜로 좁아진다).

추가 진단(통과 여부와 무관하게 반드시 볼 것):
- **순열중요도 상위 15에 재료 열이 들어가는가** — entry축에서 0개였다
- **anti-stable 점검** — TRAIN 상위 20 피쳐의 VAL 부호 유지 개수, TRAIN-VAL 피쳐 AUC 상관.
  SOL 서베이에서 **−0.38(음수)** 이었다. 다시 음수면 그 자체로 중단 사유다.

비용: 재료 롤백 재훈련 ~30분(서버) + 킬 게이트 반나절(CPU).
**RL 코드는 여기서 통과하기 전엔 쓰지 않는다.**

## 4. Phase 1 — RL 정식화 (Phase 0 통과 시에만)

### 왜 지도학습이 아니라 RL인가 (이게 정당화의 핵심)

Phase 0의 지도 라벨은 **근시안적**이다 — "지금 청산하면 최종 실현결과보다 나은가"로,
**단 하나의 반사실**(끝까지 보유)과만 비교한다. 그래서 "지금은 참고 3봉 뒤에 청산"이라는
정책을 표현할 수 없다.

**RL의 가치함수는 그걸 표현한다.** 이게 exit timing에서 RL이 지도학습보다 나은 유일하고 진짜인
이유다. (entry에서는 이 논거가 성립하지 않았다 — 그래서 entry축은 닫힌 채로 둔다.)

### MDP

| 요소 | 정의 |
|---|---|
| **상태** | pos 피쳐 23종(`pos_unrealized`/`pos_mfe`/`pos_mae`/`pos_hold_bars`/`pos_dist_to_tp`/`pos_dist_to_sl` 등, **가격변동 원시값 — notional 곱하지 않음**, CLAUDE.md 파리티 계약) + 재료 텐서(`_pct` 8 + `_age` 8 + `_signed` 8). **레짐은 피쳐가 아니라 게이팅 입력**(Phase 0 arm C가 채택되면 레짐별 정책) |
| **행동** | `{hold, exit}` 이진. 열린 포지션의 매 봉 |
| **전이** | 봉 단위 전진. `exit`이면 종료 |
| **보상** | 종단 보상만: 실현 `price_move * notional − 왕복비용`. 중간 보상 0, 할인 γ=0.999 (보유시간 페널티는 비용에 이미 내장) |
| **에피소드** | 한 포지션의 진입~청산 |
| **행동정책** | 기존 하드 TP/SL + `exit_head`. 로그된 궤적이 곧 데이터셋 |

### 알고리즘 — 오프라인 RL 고정

**온라인 탐색을 하지 않는다.** DSAC를 죽인 게 정확히 그거다(탐색 중 수천 번 행동, 매번 비용).
로그된 궤적에서만 학습한다: **IQL**(우선) 또는 **CQL**. 둘 다 이 저장소에서 lifecycle 용도로
시도됐다 실패했지만, **그때는 문제 정식화가 lifecycle이었고 지금은 단일 이진 결정이다.**

행동정책이 좁으므로 분포 이탈이 문제다 — IQL의 expectile 회귀가 CQL의 보수적 penalty보다
이 상황에 적합하다(행동 밖 Q를 굳이 추정하지 않음).

### 하드 규칙과의 관계

**RL은 TP/SL을 대체하지 않는다.** 하드 TP/SL이 먼저 걸리고, **그 둘 다 안 걸린 봉에서만**
RL 정책이 hold/exit를 결정한다. 즉 timeout 버킷 전용 오버레이다. 이렇게 두면:
- sl/tp 동어반복 효과가 성과에 섞이지 않는다(스모크에서 헤드라인을 부풀렸던 그것)
- 실패해도 기존 스택이 그대로 남는다

## 5. 평가 계약 (저장소 법)

| 계약 | 적용 |
|---|---|

| **시드 다양성** | 무작위 N≥5(고정간격 증분 금지). VAL·OOS 양 창 부호 일치 필수 |

| **비용** | 왕복 10bp 기본. ≥2026-09-04 peg-maker 실측이 나오면 교체(청산은 taker 고정이므로 절감은 진입 다리뿐) |
| **사이징** | 범위 밖. 기존 리스크 사이드카 유지 |

## 6. 사전등록 실패 조건 (하나라도 걸리면 중단)

1. Phase 0에서 ΔAUC 군집 부트스트랩 CI 하한이 0 이하거나 5시드 부호 불일치 → **세 번째 0, 종료**
2. TRAIN-VAL 피쳐 AUC 상관이 음수 → **anti-stable 재현, 종료**
3. RL 정책이 세 대조군 중 **무작위 exit**를 양 창에서 못 이김 → 종료
4. timeout 버킷을 분리했는데도 개선의 절반 이상이 sl 회피에서 나옴 → 동어반복, 종료
5. VAL 최적 하이퍼파라미터가 OOS에서 부호 반전 → 종료

⚠️**TP give-back**은 2026-09-01에 수정 시도 2건(하드게이트/비대칭임계값)이 **둘 다 실패**했다.
원인은 "단일 풀링 라벨로는 SL/TP 향방을 분리할 수 없다"였다. 이 설계는 **timeout 버킷만 다뤄
그 문제를 우회**한다 — 해결한 게 아니라 피한 것이므로, tp 버킷으로 범위를 넓히려 하면 이
미해결 문제부터 다시 봐야 한다.

## 7. 범위 밖 (명시)

- **Entry / 진입 선별** — 7전7패로 닫힘. 재도전하려면 state 표현 자체가 달라야 한다
- **방향(direction)** — 기존 Omega4.6.1 direction head 유지
- **사이징** — 기존 리스크 사이드카 유지
- **TP/SL 배리어 자체** — 하드 규칙 유지

## 8. 일정과 관문

| Phase | 내용 | 비용 | 관문 |
|---|---|---|---|

## 부록 — 이 설계가 기존 이력과 다른 점 요약

| 실패 원인 | 이 설계의 처리 |
|---|---|
| 보상 희소성 (lifecycle RL 10회 실패) | **정식화로 제거** — 열린 포지션의 매 봉이 결정, 조밀한 학습신호 |
