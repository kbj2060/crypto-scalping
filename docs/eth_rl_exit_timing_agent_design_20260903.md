## 0. 먼저 — 이미 닫힌 문 세 개

설계를 읽기 전에 이걸 봐야 한다. 이 방향은 여러 번 시도됐고 대부분 닫혀 있다.

| 축 | 시도 | 결과 |
|---|---|---|
| **전체 lifecycle RL** | 10회+ (DSAC 5변형, Dueling DQN, HMM+DQN, IQL/CQL) | ⛔ `omega4_7_rl_dsac` OOS **−87~−99%** (같은 구간 라이브 +145%). SOL에서도 재현 = 자산 특이적 아님 |
| **Entry 축** | 7회 (지도 재순위 5 + 신규분류기 1 + selective classification 1) | ⛔ AUC 0.51~0.52. Schapire 약학습성상 γ≈0이면 **어떤 wrapper도 값을 못 뽑는다** |
| **증거신호 → 매매 연결** | 5회 (confluence 36칸, forced-exit veto, exit_head 피쳐, 사이징 피쳐) | ⛔ 전부 실패 |

**전체 lifecycle 실패의 근인은 아키텍처가 아니라 보상 희소성이다.** "6개월에 24번 행동"이
정답인데 RL은 탐색 중 수천 번 행동하고 매번 비용을 낸다. 아키텍처를 바꿔도 안 풀린다.

### ⚠️그리고 이 재료에 대한 직접적 부정 증거가 이미 둘 있다

1. **Entry 스모크**: 증거신호 6종을 추가한 v1이 v0보다 **전 지표 더 나빴고**, 순열중요도 상위 15에
   증거신호가 **0개**였다.
2. **Exit 스모크**: v0(23 pos피쳐)과 v1(+증거신호 6종 12열)의 VALIDATION 확률이 174,171행 전부
   **소수점까지 완전 동일**(diff=0.0). HGB가 300회 부스팅 내내 `pos_hold_bars`(중요도 0.152,
   2위의 6배)에 압도돼 증거신호 열을 **단 한 번도 분기에 쓰지 않았다**.

**따라서 이 설계의 첫 단계는 RL이 아니라 "세 번째 0인지 확인하는 킬 게이트"다.**

## 1. 남아 있는 유일한 축 — Exit timing, 그중 timeout 버킷

2026-09-01 exit 스모크테스트가 entry축과 **정성적으로 다른 최초의 결과**를 냈다:

| | checkpoint AUC (VALIDATION) |
|---|---|
| entry 축 7회 시도 | 0.51 ~ 0.52 |
| **exit 전체** | **0.7125** |
| sl 종료(21%) | 정의불가(단일클래스) — 사실상 `dist_to_sl` 재구성, 예측 아니라 기하학 |
| tp 종료(6.5%) | 정의불가 — 이익 대부분 반납(+740bp → +49bp) |
| ⭐**timeout(72%)** | ⭐**0.6101 — 진짜 불확실한 구간의 순수 신호** |

**설계 대상은 timeout 버킷의 exit timing이다.** 나머지 둘은 하드 규칙(TP/SL)이 이미 지배한다.

### 왜 이 축은 보상 희소성을 피하는가

**포지션이 열려 있는 매 봉이 결정 지점이고, 각 결정에 즉각적인 보상이 정의된다.** entry처럼
"6개월에 24번"이 아니라 열린 포지션의 모든 봉이 학습 신호다. lifecycle RL을 죽인 구조적 문제가
**정식화 자체로 사라진다.** 이게 이 축을 고른 첫째 이유다.

## 2. 왜 지금 다시 볼 근거가 있는가 (그리고 왜 부족한가)

exit 스모크의 "증거신호 기여 0"은 **옛 형태의 증거신호**로 잰 값이다. 그 사이 세 가지가 바뀌었다:

| 그때 (2026-09-01) | 지금 (2026-09-02 재료화) |
|---|---|
| **앵커 모집단** 학습 모델의 확률 | **인과 모집단** 재학습 — 라이브가 실제로 보는 분포와 일치 |
| **희소 이진 플래그** (발화율 1~3%) | **매 봉 조밀 텐서** — 활성 0인 봉 4.6%, 봉당 평균 3개 |
| 신호별 제각각 척도 (0.235~0.808) | **백분위 정규화** — 전부 0.48~0.62, 교차비교 가능 |

⭐**세 번째가 특히 중요하다.** exit 스모크의 실패 모드는 "HGB가 증거신호 열을 한 번도 안 썼다"
였는데, 그건 **척도 경쟁 문제**다 — `pos_hold_bars` 같은 지배적 피쳐와 경쟁하려면 열이 균등하고
조밀해야 한다. 백분위 정규화는 정확히 그 문제를 겨냥한다.

**그래도 두 번의 0을 뒤집기엔 부족한 근거다.** 그래서 킬 게이트를 먼저 둔다.

## 3. Phase 0 — 킬 게이트 (지도학습, RL 아님)

**질문 하나**: 새 재료 텐서가 timeout 버킷 AUC **0.6101**을 움직이는가?

- 하네스: `scripts/research_eth_rl_exit_gate_oracle_smoketest_20260901.py` 재사용
  (후보풀 TRAIN 59,974 / VALIDATION 19,355, 보유기간 10분위 체크포인트 9개)
- **timeout 종료 후보만** 사용 (sl/tp는 단일클래스라 AUC 정의불가)

| arm | state |
|---|---|
| **A (기준선)** | pos 피쳐 23종만 — 0.6101을 재현해야 한다. 재현 안 되면 하네스 버그 |
| **B** | A + 재료 텐서 `<sig>_pct` 8열 + `<sig>_age` 8열 |
| **C** | B + `regime_eth`/`regime_btc`를 **게이팅 전용**으로 (피쳐로 합치지 않음 — RG-ResMoE arXiv:2608.12251) |

### 사전등록 킬 기준

> **B 또는 C가 A를 VALIDATION AUC에서 +0.010 이상 이기고, 그 부호가 무작위 5시드에서 5/5 일치할 것.**
> 못 넘으면 **재료는 매매용으로 기여 없음(세 번째 0)으로 선언하고 RL 착수를 중단한다.**
> 재료는 표시/연구 자산으로 남긴다.

추가 진단(통과 여부와 무관하게 반드시 볼 것):
- **순열중요도 상위 15에 재료 열이 들어가는가** (entry축에서 0개였다)
- **anti-stable 점검**: TRAIN 상위 20 피쳐의 VAL 부호 유지 개수, TRAIN-VAL 피쳐 AUC 상관.
  SOL 서베이에서 이 값이 **−0.38(음수)** 이었다. 다시 음수면 그 자체로 중단 사유다.

비용: 반나절, CPU. **RL 코드는 여기서 통과하기 전엔 쓰지 않는다.**

## 4. Phase 1 — RL 정식화 (Phase 0 통과 시에만)

### 왜 지도학습이 아니라 RL인가 (이게 정당화의 핵심)

Phase 0의 지도 라벨은 **근시안적**이다 — "지금 청산하면 최종 실현결과보다 나은가"로,
**단 하나의 반사실**(끝까지 보유)과만 비교한다. 그래서 "지금은 참고 3봉 뒤에 청산"이라는
정책을 표현할 수 없다.

**RL의 가치함수는 그걸 표현한다.** 이게 exit timing에서 RL이 지도학습보다 나은 유일하고 진짜인
이유다. (entry에서는 이 논거가 성립하지 않았다 — 그래서 entry축은 닫힌 채로 둔다.)

### MDP

| 요소 | 정의 |
|---|---|
| **상태** | pos 피쳐 23종(`pos_unrealized`/`pos_mfe`/`pos_mae`/`pos_hold_bars`/`pos_dist_to_tp`/`pos_dist_to_sl` 등, **가격변동 원시값 — notional 곱하지 않음**, CLAUDE.md 파리티 계약) + 재료 텐서(`_pct` 8 + `_age` 8 + `_signed` 8) + regime 2 |
| **행동** | `{hold, exit}` 이진. 열린 포지션의 매 봉 |
| **전이** | 봉 단위 전진. `exit`이면 종료 |
| **보상** | 종단 보상만: 실현 `price_move * notional − 왕복비용`. 중간 보상 0, 할인 γ=0.999 (보유시간 페널티는 비용에 이미 내장) |
| **에피소드** | 한 포지션의 진입~청산 |
| **행동정책** | 기존 하드 TP/SL + `exit_head`. 로그된 궤적이 곧 데이터셋 |

### 알고리즘 — 오프라인 RL 고정

**온라인 탐색을 하지 않는다.** DSAC를 죽인 게 정확히 그거다(탐색 중 수천 번 행동, 매번 비용).
로그된 궤적에서만 학습한다: **IQL**(우선) 또는 **CQL**. 둘 다 이 저장소에서 lifecycle 용도로
시도됐다 실패했지만, **그때는 문제 정식화가 lifecycle이었고 지금은 단일 이진 결정이다.**

행동정책이 좁으므로 분포 이탈이 문제다 — IQL의 expectile 회귀가 CQL의 보수적 penalty보다
이 상황에 적합하다(행동 밖 Q를 굳이 추정하지 않음).

### 하드 규칙과의 관계

**RL은 TP/SL을 대체하지 않는다.** 하드 TP/SL이 먼저 걸리고, **그 둘 다 안 걸린 봉에서만**
RL 정책이 hold/exit를 결정한다. 즉 timeout 버킷 전용 오버레이다. 이렇게 두면:
- sl/tp 동어반복 효과가 성과에 섞이지 않는다(스모크에서 헤드라인을 부풀렸던 그것)
- 실패해도 기존 스택이 그대로 남는다

## 6. 사전등록 실패 조건 (하나라도 걸리면 중단)

1. Phase 0에서 재료가 A를 +0.010 못 넘거나 5시드 부호 불일치 → **세 번째 0, 종료**
2. TRAIN-VAL 피쳐 AUC 상관이 음수 → **anti-stable 재현, 종료**
3. RL 정책이 세 대조군 중 **무작위 exit**를 양 창에서 못 이김 → 종료
4. timeout 버킷을 분리했는데도 개선의 절반 이상이 sl 회피에서 나옴 → 동어반복, 종료
5. VAL 최적 하이퍼파라미터가 OOS에서 부호 반전 → 종료

⚠️**TP give-back**은 2026-09-01에 수정 시도 2건(하드게이트/비대칭임계값)이 **둘 다 실패**했다.
원인은 "단일 풀링 라벨로는 SL/TP 향방을 분리할 수 없다"였다. 이 설계는 **timeout 버킷만 다뤄
그 문제를 우회**한다 — 해결한 게 아니라 피한 것이므로, tp 버킷으로 범위를 넓히려 하면 이
미해결 문제부터 다시 봐야 한다.

## 7. 범위 밖 (명시)

- **Entry / 진입 선별** — 7전7패로 닫힘. 재도전하려면 state 표현 자체가 달라야 한다
- **방향(direction)** — 기존 Omega4.6.1 direction head 유지
- **사이징** — 기존 리스크 사이드카 유지
- **TP/SL 배리어 자체** — 하드 규칙 유지

## 부록 — 이 설계가 기존 이력과 다른 점 요약

| 실패 원인 | 이 설계의 처리 |
|---|---|
