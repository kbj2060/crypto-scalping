## 데이터 구역
- CPU 계산은 로컬(12코어, 15GB). 서버는 읽기·수집 파일 복사만. 로컬 바이낸스 REST 금지, 정적 아카이브(data.binance.vision)만.
- 입력 파일은 sha256 을 결과에 적는다.

## 시각 규약
- 5분 패널 행 τ = 봉 시작, 값은 τ+5분 확정. 결정 시각 t 의 기준가 = 봉 (t−5분)의 종가. 피쳐는 그 봉까지, 라벨·체결은 봉 t 부터(공유 봉 없음).
- 🔴저장 예측의 `ts` 규약은 씨앗마다 다르다(11-07 정정): `*_dirshort_oos_seed` = 결정 시각(봉 마감) · `*_dir4h_oos_seed` = 봉 시작(결정 = ts+5분). 예측과 봉 수익의 상관이 꺾이는 위치로 트랙마다 직접 확인한다.

## 체결·비용
- 엄격: 메이커 2bp · 테이커 5bp(표준 수수료, 우대 가정 금지). 지정가는 **관통**해야 체결(같으면 미체결). 큐 위치·부분 체결은 모델링하지 않는다 — 낙관 쪽 한계로 적는다.
- 통과 후보: 메이커 0 · 테이커 5bp, 관통 규칙 동일.
- 펀딩: 코인 간 롱숏은 패널에 펀딩이 없어 빠진다(1단계와 같음) — 한계로 적는다.

## 판정 등급
- 돈 걸린 매매: 양측 95% + 위약 95분위 + 부호 일관. 예측 칸 개선: 단측 90%.
- 재사용 공개: 2024~2026 시험 창은 여러 연구가 이미 봤다. 처음 쓰는 창을 우선한다.
- 지표는 분모·건수와 일상 단위로 보고한다. 모델−롱·모델−숏을 같이 낸다(시장 중립 포트폴리오는 BTC 상관으로 대신한다).

## 버그 방지 절차 (전 트랙)
1. 사전등록을 먼저 커밋한다.
2. `--selftest`: 손계산 1건 · 양성 대조 · 음성 대조.
3. 변이 시험: 일부러 망가뜨린 판을 자가 점검이 잡는지 본다.
4. 재현 대조: 알려진 기존 수치(예: 저장된 시험 예측, 2단계 회전율)를 다시 낸다. 어긋나면 판정 중단.
5. 시험 채점 전에 `leak-auditor` 가 작성 맥락 없이 코드를 검토한다. 결함이 나오면 고친 뒤 시험을 연다.
6. 판정은 1회만(결과 파일이 있으면 거절). 음의 판정도 버그가 아닌지 위 절차로 확인된 것만 인정한다.
