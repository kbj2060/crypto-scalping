# 설계: 횡보/추세 구분 모델 + 전환 예측 (2026-11-02, 설계만 — 계산 없음)

사용자 11-02 «횡보와 추세장이 바뀌는 지점을 맞추는 모델, 또는 횡보와 추세장을 구분하는 모델을 만들고 싶어. 연구해서 설계도를 보여줘.»
선행 검정: XRP 저거래량 돌파 반대 진입 2시행 불통과(`docs/experiments/xrp_lowvol_sweep_fade_20261102.md`) — 이 모델의 **쓰임새**는 «횡보에서만 페이드, 추세에서만 추종»을 고르는 것.

## 0. 먼저 알아둘 것 — 이 저장소에 이미 있는 것과 교훈
| 이미 한 것 | 결과 | 설계에 반영 |
|---|---|---|
| 박스 유지 확률 HGB(30분·1h·4h, 배포) | AUC .785~.788, 그러나 로지스틱 6칸 기하만으로 .77 (HGB 증분 +.014~.026) | **«횡보 지속» 예측은 이미 있다.** 새 모델은 이것을 반드시 기준선으로 이겨야 한다. 정확도의 대부분은 «띠 폭 ÷ 변동성» 기하 |
| BTC 레짐 감지기(HMM→czz→Jump Model, 분류기 4계열) | 감지기 정확도 61→68%, 지연 +12→0봉이 되어도 **진입 손익은 정확히 0 변화** | 정확도 자체는 목표가 아니다. **쓰임(전략 전환)으로 판정** |
| 레짐 전환 엣지(라벨 16조합) | 전부 무의미(CI가 0 관통) | **전환 «시점» 맞추기는 가장 어려운 문제** — 마지막 단계, 중단 조건 명시 |

| 추세 전환 탐지기/경보기 | 경보기 정밀도 78%(기저 23%)이나 탐지기 자체는 «봉 가격폭 상위» 대조보다 못함 | 사건 정의가 약하면 경보기도 갇힌다 → 라벨 정의를 먼저 |
| 레짐 정의 5곳(RegimeEngine·HMM·GBM3·RL REG·대시보드) | 의미가 서로 다르고 경로도 어긋남 | 새 모델은 **정의를 하나만 사전등록**하고 이름을 새로 붙인다 |
| 레짐 차이는 분기를 못 넘는다(BTC 호장: 한 분기 양수가 다음 분기 음수) | 9번 뒤집힘 | 분기별 부호 안정성이 통과 조건 |

## 1. 문제를 셋으로 쪼갠다 (섞으면 안 된다)
| | 질문 | 시간 방향 | 난이도 | 쓰임 |
|---|---|---|---|---|
| **N** 지금 레짐 | 최근 H 봉은 횡보였나 추세였나 | 과거 → 현재 | 쉬움(ER·VR 한 줄) | 표시·사후 라벨, **예측 아님** |
| **F** 앞으로 레짐 (**주 모델**) | 앞으로 H 봉이 횡보일 확률 | 현재 → 미래 | 중간 | **전략 전환**의 실제 입력 |
| **T** 전환 | 앞으로 H 안에 레짐이 바뀔 확률(위험률) | 현재 → 미래 | 어려움 | 경보 |
핵심: N 은 이미 맞춘 «착각» — 지금 레짐을 아는 건 쓸모가 있어도 지연 때문에 이득이 없다(czz·EMA 교훈). **F 를 만들고, T 는 F 의 변화로 파생**하되 별도 판정한다.

## 2. 라벨 정의 (미래 H 봉, 사전등록으로 하나만 고정)
스케일 불변 지표를 쓴다(변동성과 레짐이 뒤섞이는 것을 막으려고).
- **ER**(Kaufman 효율비) = |P_{t+H}−P_t| / Σ|ΔP| ∈ [0,1]. 0 에 가까우면 횡보, 1 에 가까우면 추세.
- **VR**(Lo–MacKinlay 분산비, q=H/4) = Var(q봉 수익)/(q·Var(1봉 수익)). <1 되돌림, >1 추세.
- **Trend-scan t값**(López de Prado): 미래 창 여러 길이에 선형 추세를 맞춰 |t| 최대값.
- **3분류**: 횡보 / 중간(버림) / 추세 — 학습 분포의 하위·상위 분위수로 자르고 **가운데 구간은 라벨 없음**(억지 분류 방지, 경계 플리커도 줄임).
- 지평 H: 1h·4h·12h 세 개를 병행(전략 보유시간에 맞춤: 사용자 원장 보유 1~5h → 4h 중심).
- 경계 계약: 피쳐는 τ 마감 봉까지, 라벨은 τ+1 봉부터. ER/VR 피쳐(과거)와 ER 라벨(미래)이 같은 봉을 공유하지 않게 한다(사건 라벨 경계 계약).
- 비교 대상 라벨: 기존 «박스 유지»(고정 칸 이탈) — 같은 시점에서 두 정의가 얼마나 일치하는지 먼저 잰다.

## 3. 입력 피쳐 (τ 에 알 수 있던 것만)
| 군 | 예 | 이유 |
|---|---|---|
| 변동성 구조 | RV 1h/4h/24h/7d 비, 변동성의 변동성, 직전 구간 ER·VR | 레짐 지속성의 가장 강한 예측자 |
| 범위·위치 | 24h 범위 안 위치, 최근 고저 갱신 후 경과, 레벨(청산맵·지지/저항) 거리 | 박스 기하 |
| 활동 | 거래대금 z, 체결 건수, 테이커 불균형(CVD) | 추세는 거래량이 따라온다 |
| 파생 | OI 변화, 펀딩, 롱숏비, 청산 버스트 | 레버리지 쏠림 |
| 교차 시장 | BTC·ETH 레짐 상태, 상관 | 리더 코인 |
| 시간 | 시간대(KST 21~05 미국장), 요일, 거시 일정까지 남은 시간 | 장세 변화의 실제 계절성 |
| 지속시간 | 현재 레짐 경과 길이(런 길이) | 위험률 |
정의가 모호한 피쳐는 쓰지 않는다(전부 서빙 함수로 계산해 학습·서빙 같은 식).

## 4. 모델 사다리 (싼 것부터, 위로 갈수록 정당화 필요)
0. **규칙**: 직전 H 의 ER·VR·ADX·Choppiness 한 줄, 지속(현재 레짐 계속).
1. **로지스틱(기하+변동성)**: 박스 유지에서 «기하만으로 .77» 이 나온 것의 레짐판 — 진짜 기준선.
2. **HGB**(시간 순 CPCV, 가중=최근 우선): F 의 주 후보. early_stopping=False, 시드 다수.
3. **Jump Model 인과 디코딩**(Nystrup 계열, 점프 페널티 λ): 확률을 «상태 사전»으로 HGB 에 피쳐로 공급. 단독 라벨러 아님.
4. **BOCPD 위험률**(Adams–MacKay): 로그 변동성·ER 스트림의 변화점 확률 r_t=0 을 T 의 피쳐로.
5. (보류) 시퀀스 DL — **사용자 컨펌 전까지 착수하지 않음.** HGB 가 기준선을 못 이기면 DL 도 이유가 없다(선행 실험 다수).
디코더: 확률 → 상태는 **점프 페널티 DP + 히스테리시스**로 (BTC 결론: «argmax 는 3봉 런 = 못 씀, 디코더가 일한다»).

## 5. 평가 — 목적(쓰임)으로 판정
**상한부터** (모델 만들기 전, 가장 싼 단계):
- Stage 0 **오라클 상한**: 미래 H 레짐을 «알았다면» 사용자 규칙(저거래량 돌파 반대, 추세 추종 지정가)에 전환했을 때 순수익이 비용 이상 개선되는가. 개선이 비용 미만이면 **모델 제작 중단**. (펀딩 캐리·변동성 사이징에서 같은 질문이 7번 중 대부분 «상한이 0» 이었다.)
**정확도(예측 등급, 단측 90%)**: F 의 Brier skill / AUC 를 아래 기준선 **모두** 이긴다.
 ① 기저율 ② 지속(직전 레짐) ③ 변동성 단독 로지스틱 ④ 배포 박스유지 HGB ⑤ 같은 분포의 순환이동 위약(95분위). 일 블록 부트스트랩 CI.
**전환 T**: 하루 경보 예산(예: 2회) 고정 → 정밀도·재현율·선행 시간, **무작위 경보(같은 빈도)** 와 변동성 z 경보를 이겨야. 사건 수를 계산 전에 센다(검정력).
**쓰임(돈 걸린 등급, 양측 95%)**: 레짐 게이트가 붙은 전략 순수익 − 항상 켬 − 반대로 켬 − 무작위 게이트. 분기별 부호 안정성(최소 4분기 중 3분기 +).
데이터 분할: 학습 2024~2025, 검증 2026-01~05, 시험 2026-06~(1회), 전진 11-02~. 코인 풀링(BTC·ETH·SOL·XRP)으로 독립 레짐 수를 늘리되 **코인별 성적을 따로** 낸다.
모든 판정은 `/prereg` 로 계산 전 커밋. 리뷰는 `leak-auditor` 에게 독립 검토.

## 6. 단계와 중단 조건
```
[S0 오라클 상한] ──개선<비용──▶ 중단·보고
      │
[S1 라벨 선별: ER / VR / trend-scan / 박스유지 일치도, 3분류 경계]
      │   (정의 하나 고정)
[S2 F 모델: 로지스틱 → HGB → +Jump/BOCPD 피쳐]
      │──기준선 ①~⑤ 못 이김──▶ 중단·보고(박스유지로 충분)
[S3 T 모델: 경보 예산 평가]
      │──무작위/변동성 경보 못 이김──▶ T 폐기, F 만 유지
[S4 쓰임 검증 → 통과 시 전진 기록기 → 대시보드 한 줄(횡보/추세 확률)]
```
예상 소요(작업량 순): S0 0.5일 · S1 0.5일 · S2 1일 · S3 1일 · S4 1일. 로컬 CPU 가능(GPU 불필요).

## 7. 솔직한 기대치
- F 는 «변동성·박스 기하» 위에 약간의 증분을 얹는 정도일 가능성이 크다(박스유지 HGB 증분 +.014~.026 선례).
- T 는 선행 연구가 전부 널이었다(전환 엣지, 경보기의 탐지기 한계, czz 지연). 성공 확률이 낮고 그래서 마지막 단계·독립 판정이다.
- 가장 가치가 큰 산출은 모델이 아니라 **S0 의 답**일 수 있다: «레짐을 알면 사용자 규칙이 얼마나 좋아지나».
