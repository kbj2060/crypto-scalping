# 딥러닝 레이어 설계 & 학습 테크닉 참고자료 (2026-08-16)

이 문서는 "레이어를 어떻게 쌓고 어떻게 학습시키는가"에 대해 4개 소스를 실제로 읽고 정리한
참고자료다. **다음 세션에서 새 아키텍처를 설계하거나 학습 루프를 짤 때 여기부터 확인할 것.**
각 항목마다 어느 소스에서 나온 건지 표시했고, 여러 소스가 서로 다른 관점을 줄 때는 그 대조 자체를
남겼다 — 하나로 뭉뚱그리지 않았다.

## 1. 레이어를 어떻게 쌓는가 — 깊이(depth)

**순수 선형층은 쌓아도 의미 없다** (d2l): 아핀함수의 아핀함수는 아핀함수다. 비선형 활성화가 깊이의
존재 이유. `H = σ(XW⁽¹⁾+b⁽¹⁾)`, `O = HW⁽²⁾+b⁽²⁾`.

**깊이가 왜 도움되는지 — 두 개의 다른 관점(서로 대체 아니라 보완)**:
- d2l: 같은 함수를 얕고 넓은 망보다 훨씬 적은 파라미터로 표현 가능(압축).
- arXiv 모노그래프(5장): **깊이 = 최적화 알고리즘의 반복 횟수 그 자체.** ReduNet 유도에서 각
  레이어는 `ΔR_ε`(MCR² rate-reduction 목적함수)에 대한 gradient-ascent 한 스텝이다.
  `z^(ℓ+1) = P[z^(ℓ) + η(E^ℓz^ℓ − σ([C_k^ℓz^ℓ]))]` — 이게 곧 잔차+softmax게이트 블록이고,
  ResNet/ResNeXt 블록과 구조적으로 같다(Fig. 5.3). **실전 규칙**: 목적함수(coding-rate 등 수렴
  지표)의 개선이 정체되는 지점에서 레이어 추가를 멈춘다 — 아키텍처 서치가 아니라 수렴곡선으로
  깊이를 정한다.
- 같은 장에서 나온 원리적 구분: **width = 통계적 자원(클래스를 분리하는 데 필요한 표현력),
  depth = 계산적 자원(목적함수를 실제로 최적점까지 푸는 데 필요한 반복수).** 클러스터링/분류
  세팅에서 유도된 것이지 일반정리는 아니지만, "왜 넓히는 것과 깊게 하는 것이 다른 효과를 내는가"에
  대해 folklore가 아닌 근거를 준다.

**깊이에서 무너지는 것들 (d2l)**:
- Exploding gradient: L개 층의 야코비안이 곱해짐. 100개의 유닛분산 랜덤 가우시안 행렬을 곱하면
  값이 10²³을 넘는다는 데모로 보여줌 — 순수 반복곱셈의 결과.
- Vanishing gradient: sigmoid는 입력이 크거나 작을 때 미분이 0에 수렴 → 깊은 층에서 그래디언트가
  으깨짐. ReLU는 미분이 정확히 0 또는 1이라 이 문제를 완화(값을 그대로 통과시키거나 완전히 막거나).
- 대칭성 붕괴: 모든 가중치를 똑같이 초기화하면 같은 층의 모든 유닛이 영원히 동일한 함수를 계산 —
  랜덤 초기화가 스케일 문제와 별개로 필요한 이유.

**해결책 — Xavier/Glorot 초기화** (d2l, 수식 있음): forward/backward 양쪽에서 분산을 안정시키는
두 제약(각각 `∝1/n_in`, `∝1/n_out`)을 평균내서: 가우시안이면 `σ = √(2/(n_in+n_out))`, 균등분포면
`U(±√(6/(n_in+n_out)))`. **He/Kaiming init(ReLU 전용 분산공식)은 d2l 해당 챕터에 없음** — 이
문서를 쓰는 나(어시스턴트)의 일반 지식으로 보충: `σ = √(2/n_in)` (Kaiming He 2015), ReLU가 절반의
입력을 0으로 죽인다는 사실을 반영해 Xavier보다 분산을 2배로 잡는다. ReLU 계열 활성화를 쓸 때는
Xavier보다 이쪽이 표준.

**해결책 — 잔차/스킵 연결**:
- d2l: nested function class 논리 — 층을 추가해도 이전 함수족을 포함하도록 보장하려면, 층이
  `f(x)`가 아니라 `g(x)=f(x)-x`(잔차)를 학습하게 하면 된다. 최적의 선택이 "아무것도 안 하기"라면
  `g(x)→0`으로 가중치를 0에 가깝게 만들면 되니(쉬움), identity가 자동으로 fallback이 된다. 순수
  층은 identity를 처음부터 학습해야 해서 훨씬 어렵다.
- arXiv 모노그래프: 별도 메커니즘이 아니라 그냥 "현재 위치 + step×gradient" 형태의 unrolled
  최적화 스텝 자체가 잔차 구조다. attention/MLP 블록 유도(§5.2.1)에서도 똑같이 나옴 — 이건
  "잔차연결이 vanishing gradient를 막는다"는 통상적 설명과는 다른, 원리적으로 더 근본적인 프레임.

## 2. 정규화(Normalization) 레이어

**BatchNorm** (d2l, 수식): `BN(x) = γ⊙(x−μ̂_B)/√σ̂_B² + β`. affine변환 후, 활성화 전에 적용.
학습 땐 미니배치 통계, 추론 땐 누적된 전체 통계 사용. **우리 데이터에 직결되는 경고**: 배치가
i.i.d.가 아니면(연속된 5분봉처럼 자기상관 있는 데이터) 정규화 신뢰도가 떨어진다고 d2l이 명시. 배치
크기 1에선 아예 작동 안 함, 너무 크면 정규화의 암묵적 정규화 효과가 씻겨나감(50~100이 권장 범위).

**LayerNorm**: BatchNorm과 수학적으로 동일하되 정규화 축이 배치가 아니라 피처(샘플 하나 내부)다.
그래서 배치 크기·구성에 무관 — 가변 길이 시퀀스/어텐션 모델에 선호되는 이유. **우리의 자기상관
있는 시계열 윈도우 데이터에 BatchNorm보다 적합하다는 근거가 됨(N-HiTS/ModernTCN 쪽).**

**Pre-norm vs Post-norm — d2l과 Tuning Playbook이 서로 다른 조각을 채워준 좋은 사례**:
- d2l: 오리지널 Transformer는 post-norm(`LayerNorm(x+Sublayer(x))`). GPT-2가 pre-norm으로
  바꿨고 "더 효율적인 학습"이라 말하지만 메커니즘은 설명 안 함.
- **Tuning Playbook이 이걸 구체적으로 채움**: 정규화를 잔차 안쪽에 두는 `x + f(Norm(x))`가
  안정적이고, `Norm(x + f(x))`(post-norm)는 학습 불안정을 일으키는 것으로 알려져 있다고 명시. 학습
  불안정 디버깅 체크리스트의 구체적 항목 중 하나.

**RMSNorm**: 세 소스 다 언급 없음 — 명시적 공백. (일반 지식: `RMSNorm(x) = γ⊙x/RMS(x)`,
평균-빼기 단계를 생략해 LayerNorm보다 계산이 싸고 LLaMA 등 최신 LLM이 표준으로 채택 — 필요하면
별도로 찾아볼 것.)

**정규화의 원리적 근거 — arXiv 모노그래프**: MCR² 목적함수 `ΔR_ε`는 피처의 raw 스케일에 대해
단조증가라서, 표현끼리 공정 비교하려면 스케일을 정규화해야만 한다 — "이게 BatchNorm 필요성의
자연스러운 정당화"라고 직접 언급(§4.2.3). ReduNet의 매 레이어 sphere-projection 스텝은 저자들
스스로 LayerNorm 블록과 닮았다고 각주에 씀(§5.1.1).

## 3. 최적화 — Optimizer, 학습률 스케줄

**SGD/Momentum/Adam 업데이트 규칙 (d2l, 전부 수식 확인됨)**:
- SGD: `x ← x − η∇f_i(x)`. 개별(또는 미니배치) 샘플 그래디언트는 비편향 추정량이지만 분산이 크다.
- Momentum: `v_t = β·v_{t-1} + g_t` (β≈0.9), `x_t = x_{t-1} − η·v_t`. 최근 그래디언트를 강조하는
  leaky average. 곡률이 방향마다 다른 ill-conditioned 표면에서 진동은 상쇄하고 일관된 방향은
  강화. 유효 스텝 크기는 `η/(1−β)`.
- Adam: 1차·2차 모멘트 EMA(`β1=0.9, β2=0.999`) + bias correction + `x_t ← x_{t-1} − η·v̂_t/(√ŝ_t+ε)`.
  Momentum + Adagrad의 좌표별 적응 스케일 + RMSProp의 정규화를 통합한 형태.

**AdamW의 decoupled weight decay — d2l이 명시적으로 안 다룬다고 밝힌 부분, 일반 지식으로 보충**:
Adam에 L2 정규화를 loss에 그냥 더하면, weight decay 강도가 `√ŝ_t`로 나뉘면서 파라미터별 적응
학습률에 결합돼버린다(원치 않는 효과). AdamW(Loshchilov & Hutter, 2019)는 weight decay 항을
그래디언트 기반 업데이트에서 분리해서 별도로 적용: `θ_t ← θ_{t-1} − η(v̂_t/(√ŝ_t+ε) + λθ_{t-1})`.
**세 소스 다 이 서브틀티를 안 다룸 — 우리 TabM 학습 스크립트가 AdamW를 쓰므로 실무적으로 중요한
사실이고, 이미 decoupled 버전을 쓰고 있다는 것 자체가 맞는 선택.**

**학습률 스케줄 (d2l)**:
- Cosine annealing: `η_t = η_T + (η₀−η_T)/2·(1+cos(πt/T))` — 끝으로 갈수록 아주 작은 학습률로
  "정제".
- Warmup: 학습 초반 몇 epoch은 학습률을 작은 값에서 목표치까지 선형으로 올림. 이유: 무작위
  초기화 상태에서의 초기 업데이트 방향은 거의 의미가 없어서, 큰 스텝을 밟으면 파라미터를 망가뜨릴
  수 있다 — "매우 깊은 네트워크에서 파라미터 발산을 제한한다"고 명시.

**배치 크기 — Tuning Playbook의 명확한 규칙**: **배치 크기를 검증 성능을 올리기 위한
하이퍼파라미터로 다루면 안 된다.** 다른 하이퍼파라미터(특히 LR·정규화)를 재튜닝하고 스텝 수만
충분하면, 어떤 배치 크기로도 같은 최종 성능에 도달 가능(Shallue et al. 2018 인용). 배치 크기는
순전히 처리량 레버 — 그리고 공짜가 아니다: 작은 배치가 주는 그래디언트 노이즈는 암묵적 정규화
효과가 있어서, 배치를 키우면 과적합에 더 취약해지고 더 강한 정규화가 필요할 수 있다. 배치 크기를
바꾸면 LR·모멘텀·정규화 하이퍼파라미터를 처음부터 다시 튜닝해야 한다. 실전 규칙: 하드웨어가 버티는
최대 배치 크기를 쓰고(스루풋이 선형으로 스케일되는지 확인), gradient accumulation은 일반적으로
피할 것(처리량 이득이 없음).

## 4. 정규화(Regularization) / 과적합 방지 — 우리 프로젝트와 직결

**Dropout** (d2l): `h' = 0`(확률 p) 또는 `h/(1-p)`, `E[h']=h`로 비편향. 근거 3가지: 입력 노이즈 =
Tikhonov 정규화와 동치(Bishop 1995 인용), 유닛 간 co-adaptation 방지, 암묵적 앙상블/배깅 효과.
배치/레이어 배치는 원칙보다는 휴리스틱("입력에 가까울수록 낮은 p") — 명확한 선택 방법론은 없음.

**Weight decay/L2**: `L(w,b) + (λ/2)‖w‖²` → SGD에서 `w ← (1−ηλ)w − (그래디언트 스텝)`. Adam류
옵티마이저에서의 차이는 d2l이 다루지 않음 → §3의 AdamW 항목 참고.

**Early stopping — 우리 라벨 노이즈 상황과 직결**: d2l의 구체적 경험적 주장: 이 기법의 이득은
**학습 데이터에 라벨 노이즈/변동성이 있을 때 집중적으로 발생**하고, "깨끗하고 분리 가능한
데이터셋에서는 이득이 미미하다." 금융 수익률 기반 라벨은 본질적으로 노이즈가 크므로, early
stopping을 1차 정규화 수단으로 쓰는 게 이 소스 기준으로도 정당화된다.

**Double descent / 용량-대-데이터 판단 — d2l + arXiv 모노그래프가 서로 다른 각도에서 같은 문제를
다룸**:
- d2l: 딥러닝은 명목상 용량과 무관하게 학습오차가 거의 0에 도달 → 고전적 VC차원/Rademacher
  복잡도로는 일반화를 설명 못함. Double descent(용량이 interpolation 임계점을 넘으면 일반화오차가
  비단조적으로 개선)를 보고. weight decay만으로는 이 현상을 완전히 설명 못한다고 인정.
- arXiv 모노그래프(3장 §3.3, 증명 있음): 유한 데이터셋에 대한 전역 최적 디노이저는 노이즈 레벨→0일
  때 학습 데이터의 최근접이웃 룩업으로 붕괴한다(수식 3.3.3) — 즉 충분히 강력한 모델은 반드시
  암기한다. **모델 크기 대비 데이터셋 크기의 비율이 지배하는 phase transition**이 실증적으로
  관찰됨(모델이 데이터셋 대비 크면 암기, 데이터가 충분히 커지면 암기 비율 급감). 우리처럼 유효
  데이터가 제한적인 상황에선: 모델 용량을 절대적 크기가 아니라 **유효 학습셋 크기 대비**로
  판단해야 하고, loss를 0까지 밀어붙이기보다 의도적으로 정밀도 ε를 정해 손실 압축을 최소화하는
  쪽이 (엔트로피 관점에서 유도된) "올바른 목적"이라는 논지 — 결국 early stopping/명시적 정규화를
  통계적 학습이론과는 다른(정보이론적) 각도에서 다시 정당화.

**아키텍처 선택 자체에 대한 규칙 (d2l)**: "많은 태스크에서 딥러닝은 수천 개 이상의 학습 샘플이
있어야 선형모델을 이긴다"는 명시적(비공식) 기준선. 우리 TabM 기반 baseline이 여전히 최선인 이유와
연결지어 생각할 만하다 — 다만 d2l 자신도 이 규칙이 overparameterized 딥러닝 영역에서는 double
descent 때문에 깨질 수 있다고 인정.

**우리 프로젝트가 이미 검증한 것과의 연결**: GCE(q=0.7)/ELR(λ=3.0,β=0.7)/latent-mixup의 개별·조합
효과를 TabM에서 이미 테스트했고(GCE 단독만 개선, 나머지 단독/조합은 악화) — 이건 위의 이론들이
말하는 "라벨노이즈 대응 + 암기 방지"의 구체적 실행형이었다. N-HiTS/ModernTCN에서도 같은 조합이
이긴다는 보장이 없으니 별도로 isolation test 중(진행 중인 백그라운드 작업).

## 5. 시퀀스/어텐션 아키텍처

**복잡도 비교표 (d2l, 정확한 수치)**:

| | CNN | RNN | Self-Attention |
|---|---|---|---|
| 계산복잡도 | O(k·n·d²) | O(n·d²) | O(n²·d) |
| 순차 연산(병렬화 가능성) | O(1) | O(n) | O(1) |
| 최대 경로 길이 | O(n/k) | O(n) | O(1) |

(n=시퀀스 길이, d=피처 차원, k=conv 커널 폭). 우리의 짧은 5분봉 윈도우(수십~수백 bar)에서는
O(n²) 어텐션 비용이 치명적이지 않을 가능성이 높고, 어텐션의 O(1) 경로길이는 dilation 없이도 윈도우
내 임의의 두 bar를 바로 연결한다는 뜻 — ModernTCN(CNN 계열, 경로길이가 n/k에 비례)과 비교할 때
참고할 트레이드오프.

**어텐션이 왜 동작하는가 — arXiv 모노그래프의 원리적 유도 (가장 독창적인 부분)**: 토큰을 저랭크
가우시안 부분공간 혼합모델로 모델링하고, MCR² 압축항의 그래디언트를 1차 Neumann 급수로 근사 +
softmax 커널로 부분공간 소속을 추정하면 **정확히 multi-head subspace self-attention 형태**가
나온다(§5.2.1) — 다만 표준 어텐션과 달리 Q/K/V가 전부 같은 학습된 부분공간 basis에 묶여있다.
결론: **어텐션 = 토큰을 로컬(헤드별) 부분공간/가우시안 모델로 압축하는 그래디언트 스텝 한 번.**
잔차연결은 "현재위치+그래디언트스텝"의 자연스러운 형태로 다시 등장.

**선형시간 어텐션(ToST)**: 토큰 쌍별 유사도 대신 그룹별 2차 모멘트 통계만 쓰는 변형(§5.3.2) —
O(n) 시간/메모리, Long Range Arena에서 표준 Transformer/Reformer/BigBird/Linformer/Performer보다
우수. 짧은 윈도우에선 우선순위 낮지만 윈도우를 늘릴 계획이 있으면 참고할 만.

**Causal/자기회귀 아키텍처**: 같은 유도를 인과적 마스킹(과거 토큰만 사용)으로 확장하면 표준
causal-attention-mask 구조가 그대로 나오고, KV-caching이 왜 작동하는지도 1원리에서 설명됨. 다만
저자들 스스로 실제 언어모델링에서 causal CRATE(60M)가 비슷한 크기의 GPT-2보다 확실히 떨어진다고
밝힘(cross-entropy 4.61 vs 3.87) — "이론적 장점에도 불구하고 시퀀스모델링 태스크에서의 격차는 여전
히 남아있다"고 인정, SSM/Mamba류를 대안으로 언급.

## 6. 실전 워크플로우 (Google Deep Learning Tuning Playbook)

**새 프로젝트/새 아키텍처 시작 순서**:
1. 아키텍처: 새로 설계하지 말고 **이미 검증된, 우리 문제와 최대한 비슷한 문제를 푼 논문의
   아키텍처를 재사용**하라.
2. Optimizer: 그 문제 유형에서 제일 많이 쓰는 것부터(SGD+Nesterov 또는 Adam/NAdam), 단순한
   변형(고정 모멘텀/고정 ε,β)부터 시작.
3. 배치 크기: 속도용으로만 선택(§3 참고), 검증성능 튜닝 대상 아님.
4. 초기 baseline: 빠르고 가벼운 구성으로 "그럴듯한" 결과 하나 확보(스케줄 없는 고정 LR, 작은
   모델) — 무작위보다만 나으면 됨.

**4단계 과학적 루프**(반복): 목표 설정(좁고 명확하게) → 실험 설계·실행 → 결과에서 배우기 → 새
best config를 채택할지 판단. **한 라운드에 여러 걸 동시에 바꾸면 원인 분리가 안 된다** — 매
라운드 목표는 하나.

**하이퍼파라미터 삼분류**: scientific(측정 대상) / nuisance(공정 비교를 위해 매번 재최적화해야
함, 보통 optimizer HP) / fixed(고정, 결론이 그 값 밖으로 일반화 안 될 수 있음을 감수).

**HP 탐색 방법론**:
- 탐색 단계엔 **quasi-random search(Halton 등)를 베이지안 최적화보다 선호** — 비적응적이라 사후에
  다른 목적함수로 재분석 가능, 재현 가능, 탐색공간 경계 문제 진단 쉬움, 병렬/순차 실행이 통계적으로
  동일. "적응형 알고리즘이 2배 예산의 quasi-random search를 이기기는 매우 어렵다"(Recht/Jamieson
  인용). 최종 마무리 단계에서만 베이지안(Vizier 등)으로 전환.
- **시행 횟수가 얼마면 충분한가 — 일반론 없음**을 명시하되, Adam 기준 구체적 규칙: **10회 미만 →
  LR만 튜닝, 10~25회 → LR+β1, 25회+ → LR+β1+ε, 그 이상 → β2도.**
- 진단 도구: hyperparameter axis plot(최적점이 탐색공간 경계에 몰리면 경계를 넓혀야 함),
  isolation plot(nuisance 파라미터를 최적화해 없앤 뒤 scientific 파라미터만 비교).

**노이즈 vs 진짜 개선 — 우리 N≥5 시드 게이트와 정확히 같은 정신**: 분산의 3가지 원천(재학습
분산/시드, 탐색 자체의 분산, 데이터분할 분산)을 명시적으로 구분. **"새 설정을 채택하기 전, best
trial을 N번 재학습해서 재학습 분산을 파악하라."** 동일 설정을 재학습한 두 번의 결과만으로도
통계적으로 "유의한" 차이가 나올 수 있다고 경고 — 단일 실행에 대한 유의성 검정은 신뢰할 수 없다.
결정 규칙: 신규 설정과 베이스라인 둘 다의 재학습 분산을 감안했을 때 더 나으면 채택 — "완전한
확신"을 요구하지 않되, 복잡도가 늘어나는 만큼의 이득이 있어야 함.

**학습 불안정성 디버깅 체크리스트**:
1. 불안정 유형 구분: 초기화 직후 vs 학습 중반 갑작스런 발산.
2. LR 스윕으로 lr* 찾고, lr* 바로 위 LR들에서 손실이 오르는지 확인 → 안정성 문제인지 판별.
3. 그래디언트 L2 norm을 로깅 — 이상치 스파이크가 원인 진단과 clipping 임계값 설정에 씀.
4. 짧은(~500스텝) 러닝을 2배 LR로 매 스텝 평가하며 돌려서 나중에 회복되는 초반 불안정을 탐지.
5. **해결 우선순위**: LR warmup(초반 불안정에 최선) → gradient clipping(관측된 그래디언트
   norm의 90th percentile 근처로) → 다른 optimizer 시도(Adam이 Momentum이 못 다루는 불안정을
   다룰 때 있음) → 아키텍처 관행(잔차+정규화, 특히 **정규화를 잔차 안쪽에**: `x+f(Norm(x))`가
   `Norm(x+f(x))`보다 안정적) → **LR을 그냥 낮추는 건 최후의 수단.** 업데이트의 50% 이상이
   clipping당한다면 그건 사실상 LR을 낮춰야 한다는 신호를 clipping으로 가리고 있는 것.

## 7. 이번 세션의 N-HiTS/ModernTCN 작업에 바로 적용된 것

진행 중인 백그라운드 작업(N-HiTS/ModernTCN 구현+학습)에 이미 이 정리 이전에 반영된 것들:
GCE/ELR/mixup 조합(§4), N≥5 진짜 랜덤 시드 게이트(§6의 노이즈 구분과 동일 원리), isolation→HP스윕
순서 분리(§6의 scientific/nuisance 구분 그대로).

**이번 정리로 새로 확인/보강할 만한 것**:
- AdamW의 decoupled weight decay 공식(§3) — 우리 스크립트가 AdamW를 쓰는 게 맞는 선택이었다는
  확인.
- Pre-norm 배치 규칙(`x+f(Norm(x))`, §2·§6) — TCN/N-HiTS 구현에 정규화를 잔차 안쪽에 뒀는지 다음
  검토 때 확인.
- Tuning Playbook의 HP 시행횟수 규칙(§6) — "20~30 trial"로 지시했던 것이 Adam 기준 대략
  β1+ε까지 튜닝하는 수준과 맞아떨어짐, 근거로 인용 가능.
- 배치 크기를 검증성능 튜닝 대상에서 제외하라는 규칙(§3) — HP서치 공간에 배치사이즈를 넣었다면
  빼는 걸 고려.

## 아직 이 저장소에 없는 것 (공백으로 확인됨)

- He/Kaiming init 명시적 사용 여부 — 확인 필요.
- RMSNorm — 4개 소스 전부 공백, 필요하면 별도 조사.
- Label smoothing의 정확한 메커니즘/효과 — d2l도 다루지 않음, 별도 소스 필요.
- 시계열/표형 데이터에 대한 아키텍처 이론은 4개 소스 다 사실상 공백(arXiv 모노그래프는 비전/언어만
  검증) — N-HiTS/ModernTCN 자체 논문이 여전히 가장 직접적인 근거.
