## 1. 먼저 «왜 0.8건/일인가»를 분해했다 — 군집이 아니라 «독립 사건 부족»

| | 값 |
|---|---|
| 신호 | 5.51/일 |
| **에피소드**(신호 간격 ≤12봉이면 한 덩어리) | **1.23/일** · 평균 4.5신호 · 길이 9봉 |
| 체결 | 0.80/일 |
| **슬롯 점유율** | **23.1%** · 유휴 중앙 155봉(12.9h) |

⭐**포착률 = 0.80/1.23 = 65%.** 집행을 «완벽하게» 고쳐도 상한이 1.23건/일이다.
⇒ §2.2 가 집행 개선 4종을 전부 실패로 기록한 이유가 여기 있다. 고칠 곳이 아니었다.

(같은 추세가 계속 발화). 그래서 전역 완화는 낭비가 크다.

## 4. 네 레버 (사용자 지시) — 결과

### 4.1 피쳐 입력 다변화 ✅ **작동한다(느슨한 쪽에서만)**
새 데이터 수집도 새 피쳐 코드도 필요 없었다 — **프레임에 이미 61개 미사용 열이 있었다**.
배포 번들의 102열 계약에 안 들어갔을 뿐, 같은 `FeatureEngineer.process` 산출물이다.

| 군 | 열수 | 내용 |
|---|---|---|
| cvd | 7 | 누적 델타·기울기·가격괴리·돌파 |
| btc | 13 | BTC 수익률 사다리·ETH/BTC 스프레드·베타잔차·리드래그 |
| comp | 6 | bb/atr 백분위 랭크·압축·압축해소 |
| vwap | 7 | VWAP 거리 3창·앵커드·되찾기/거부·당일 고저 거리 |
| foi | 6 | 펀딩-OI 괴리·플립·OI↑가격↓·과밀 위험 |
| wick | 6 | 윅 z·전고저 스윕 되찾기·실패 돌파 |

⭐**클린 레짐이 여기 있다.** `state7_*/state12_*` 는 `_with_raw_state12` 의 **결정적 tanh 변환**이라
적합된 분류기가 아니다 ⇒ **폴드 경계를 넘지 않는다**. v3 가 레짐을 «완전 제거»한 이유는
balnobb 6열의 적합창이 테스트창을 덮는 누수였는데, 이 12열에는 그 문제가 없다.

**인과성 검사**: 61열 전부에 대해 `|corr(x_τ, r_τ)|` vs `|corr(x_τ, r_{τ+1})|` 을 비교.
**한 봉 밀림 의심 0건.**

⭐**조이면 약간 손해, 풀면 크게 이득.** 「더 많이 쏠 때 더 잘 고른다」 —
빈도가 구속조건인 이 문제에 정확히 맞는 방향이다. 확인창에서도 같은 모양

### 4.2 모델 아키텍처 변경 ⛔ **무승부**
`best_epoch` 이 항상 1~2 라 «총 150~400 스텝»만 돈다. 학습을 길게(에폭 24·patience 5·
lr 7e-4) 주면: 37신호/일 +7.01 vs 기본 +8.32 · 22신호/일 +9.20 vs +9.06. **무승부.**
⭐**용량 프로브 — 축이 끝났다**(고정 q=0.85 · 개발 4폴드 · ~2.1건/일):

| 용량 | 체결/일 | 건당bp | CI95 | 순/일 |
|---|---|---|---|---|
| k4·h96·l2 (¼) | 2.09 | +5.73 | [+0.52,+11.10] | 12.0 |
| **k8·h192·l3 (동결본)** | 2.11 | +8.14 | [+2.91,+13.65] | 17.2 |
| k16·h256·l3 (4배) | 2.15 | +8.34 | [+3.12,+13.30] | 18.0 |

**줄이면 −2.41, 늘리면 +0.20**(시드폭 2.36 안). ⇒ 동결본 크기가 **고원의 시작점**이다.
🔴**「용량 부족이 아니라 신호 부족」이라는 첫 진술은 부정확했다** — 용량은 무관하지 않고,
이미 고원에 도달해 있을 뿐이다. 학습을 길게/lr 을 낮추는 축이 무승부라는 판정은 그대로다.
⇒ **아키텍처는 레버가 아니다**(하지만 「아무거나 써도 된다」는 뜻이 아니다 — ¼로 줄이면 진다).

## 5. 지시 밖에서 추가로 연 축 — ⭐게이트 랭킹 함수

지금까지 게이트 점수는 `Q[고른 방향]` 하나뿐이었다. 학습 0으로 다섯 가지를 비교
(wide 157 · 37신호/일 · 개발 4폴드):

| 점수 | 체결/일 | 건당bp | CI95 |
|---|---|---|---|
| q = Q[방향] (현행) | 2.28 | +6.30 | [+1.14,+11.55] |
| d = D[방향] | 2.29 | +6.33 | [+1.21,+11.45] |
| dq = D·Q | 2.29 | +6.14 | [+1.16,+11.48] |
| margin = D[방향]−D[반대] | 2.68 | +2.32 | [−1.97,+7.01] |
| **edge = D[방향]−D[cash]** | **2.07** | **+8.32** | **[+2.48,+13.78]** |

⭐**`edge` 가 이긴다.** 의미도 맞는다 — 「거래할 만한가」를 직접 읽는 랭킹이고,
CASH 클래스가 그걸 위해 존재한다. `margin` 이 최악인 것도 같은 이유다(CASH 를 버린다).

## 5.1 ⭐귀속 — 이득은 «피쳐»에서 오고, `edge` 는 그 위에서만 듣는다
동결값 그대로(고정 q=0.85 · 개발 4폴드 · ~2.1건/일):

| 구성 | 건당bp | CI95 |
|---|---|---|
| base 96 + q (v3 게이트) | +3.63 | [−1.48,+8.89] |
| base 96 + **edge** | +3.78 | [−1.54,+9.05] |
| **wide 157 + edge** | **+8.14** | **[+2.91,+13.65]** |
| base⊕wide 확률평균 + edge | +5.94 | [+0.46,+11.45] |

⭐**게이트만 바꾸면 +0.15 — 사실상 0.** `edge` 는 **넓은 피쳐가 CASH 머리를 쓸모 있게
만들었을 때만** 듣는다(상호작용). ⇒ 「게이트 점수를 바꾸면 된다」로 일반화하면 안 된다.
🔴**base⊕wide 혼합은 기각** — 같은 아키텍처라 확률 스케일이 맞는데도 약한 쪽이 끌어내린다
(TabM+LGBM 혼합 실패가 스케일 탓만은 아니었다는 뜻이다).
