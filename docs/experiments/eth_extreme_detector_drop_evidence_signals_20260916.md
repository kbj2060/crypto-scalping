# 극점 탐지기에서 증거신호를 뺀다 (2026-09-16)

사용자 질문 흐름: "증거신호가 못 맞추는 것 같다" → 8종 전수 측정(진입·청산타이밍·청산파라미터
전부 0) → "그럼 제거하는 게 낫지 않아?" → 증거신호를 남길 마지막 이유였던 **극점 탐지기**를
먼저 절제 측정 → **빼면 좋아진다**.

## 무엇을 뺐나
1. 피쳐 9열: `f_<신호>` 8개 + `n_signals` (38 → 29피쳐)
2. **모집단 제약**: "증거신호 8종 중 하나라도 발동한 봉만 채점" → **전체 봉**

`dem`·`kalman_dev_z` 등 `BASE_COLS` 는 그대로 `compute_signals` 가 준다 — 그 모듈 자체는 남는다.
뺀 것은 **발동 여부**(트리거)이지 지표 값이 아니다.

①이 배포 아티팩트의 AUC 0.7099 를 0.7086 으로 재현한다(빌드 충실성 확인).

**피쳐만 빼는 건 무효(②)고, 모집단 제약을 빼야 이득이 난다(③).** 원인은 후보 풀이다 —
"발동 봉만 채점"이 420,870개를 34,968개로 12배 줄여 더 좋은 봉을 고를 기회를 뺏고 있었다.
(이득의 일부는 학습 데이터가 27.5k → 330k 로 는 것이기도 하다. 둘 다 같은 제약을 푼 결과다.)

## 배포 형태
- 컷을 **모집단 분위 → 하루 콜 건수**로 바꿨다(강 1.46 · 강+중 2.93 · 강+중+약 7.22건/일).
  모집단이 12배 커져 같은 분위가 12배 많은 콜이 되기 때문이다. 화면 빈도는 보존된다.
- 🔴**손실가중 사이드카(p2)는 내렸다.** 같은 프레임으로 재학습해 측정했더니 이 모집단에서는
  **무력하다**: 강 235건 중 3건(1.3%)만 강등하고 정밀도 69.4% → 69.4% 로 불변. 컷을 강등률
  10~50% 로 다시 잡아도 68.1~71.2%(기준 69.4%) 범위의 잡음이고, 버린 콜이 오히려 더 정확한
  구간도 있었다(하위 20% 강등시 버린 콜 74.5%). 사이드카의 원래 일(«빗나가면 비싼» 역추세
  콜 회피)을 새 부모가 이미 하고 있다. 서버의 옛 38피쳐 사이드카는 아래 형상 검사에 걸려
  자동으로 무시된다(= v1 동작). 빌더의 `--frame` 인자는 재검증용으로 남긴다.
- 라이브 모듈에 **아티팩트 피쳐 목록 검사**를 넣었다 — 옛 38피쳐 아티팩트를 조용히 먹고
  죽지 않도록, 불일치면 안 쓴다(부모는 웜업 표시, 사이드카는 v1 동작).
