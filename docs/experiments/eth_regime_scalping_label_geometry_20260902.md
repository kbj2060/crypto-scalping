## GBM3 기반임을 코드 수준에서 보장

사용자 지적 반영. TRAIN 범위를 **배포된 GBM3 artifact의 `train_range` 필드에서 직접 읽고**,
`_debounce`/`_run_lengths`는 인라인해 **GBM2(2-class trend/chop) 계보에 대한 import 의존성을
완전히 제거**했다. 기준 라벨도 GBM3 자신의 것(RegimeEngine 3-class, **raw/무디바운스**)이다 —
디바운스는 GBM2의 발명이므로 여기서는 기본값이 아니라 **정당화가 필요한 선택 축**으로만 둔다.

## 현재 라벨이 왜 스캘핑 스케일이 아닌가

`RegimeEngine.compute()`의 최단 창은 `er_24`(24봉=2시간)이고, **방향 앵커는 `net_change_48`/
`ret_48`(4시간)**, 확인 기울기는 `mtf_trend_1h`(1시간 EMA 기울기)다. 즉 "bull"은 *지난 2~4시간이
효율적으로 올랐다*는 뜻이다 — 분~1시간을 보유하는 스캘퍼에게는 **이미 닫힌 창**을 알려준다.

## 라벨 계열 (스케일 S로 일반화)

```
er_S   = |close − close[−S]|  / Σ|diff|(S)
er_2S  = |close − close[−2S]| / Σ|diff|(2S)
net_2S = close − close[−2S]                    (방향 앵커)
slope_S= EMA(close, S).pct_change()            (mtf_trend_1h의 일반화, S=12가 원본)
trend  = (er_S ≥ T1_S) | (er_2S ≥ T2_S)
bull   = trend & net_2S>0 & slope_S>0  /  bear = 대칭  /  chop = 나머지
```
S ∈ {6, 12, 24, 48}(30분/1시간/2시간/4시간), 디바운스 K ∈ {1, 3, 6, 12}. S=24가 현재 스케일.

**⭐임계값 보정은 필수다.** 효율비는 스케일 의존 분포를 갖는다(랜덤워크에서 E[ER]~1/√N). 현재
0.20/0.16을 S=6에 그대로 쓰면 trend_share가 기계적으로 부풀어 모든 비교가 무의미해진다. 그래서
T1_S/T2_S는 **TRAIN에서 현재 라벨 자신의 발동률**(P(er_24≥0.20)=0.4130, P(er_48≥0.16)=0.3541)에
**백분위 매칭**했다 — 실제로 16개 조합 전부 chop share가 0.48~0.57로 유지됐다. README §5.13
(horizon별 K 재보정)과 같은 규율이다.

## 핵심 지표 — "전환이 잘된다"를 어떻게 재나

**전환 엣지**: 라벨이 bull(bear)로 **새로 바뀌는 그 봉**에서, 이후 6/12/24봉 forward return을
라벨이 방금 주장한 방향으로 부호를 맞춰 평균한 값. 블록 부트스트랩(B=400, 블록=forward window
길이) 95% 신뢰구간을 붙였다 — 인접 전환의 forward 창이 겹쳐 강하게 자기상관하므로 iid 부트스트랩은
구간을 심하게 과소평가한다.

⚠️1차 실행에서는 CI 없이 점추정만 봤고 "S=24/K=3이 3배 낫다"고 읽힐 뻔했다. **S=48에서 K에 따라
부호가 뒤집히는 것**(K=1 +0.46 → K=3 −1.51 → K=6 +0.56)을 보고 CI 없이는 못 읽는다고 판단해
추가했다. 판단은 아래처럼 완전히 바뀌었다.

## 판정

**1) ❌스케일을 줄이면 더 나빠진다 — 가설과 정반대.**
S=6(30분)은 h6 엣지 **+0.05bp**로 사실상 정확히 0이고, raw run median이 **2봉**이다. 2봉짜리
상태는 레짐이 아니라 노이즈다. 점추정은 S가 커질수록 **오히려 증가**한다(S=6 → S=24).
현재 S=24 스케일이 이 계열의 최적 근처에 이미 있다.

**2) ❌어떤 조합도 전환 엣지가 유의하지 않다.** 유일 통과 셀도 우연 기대치 안이고, 디바운스는
같은 스케일 안에서 부호가 뒤집힌다(S=48: +0.46 → −1.51 → +0.56) — 노이즈의 서명.

**3) ❌비용 벽.** 모든 엣지가 1~2bp인데 baseline |move|는 32~66bp, 거래비용 하한은 10bp다.
"유의한" 셀조차 **비용의 1/6**이다.

## ⭐재프레이밍 — 이게 "레짐 라벨은 쓸모없다"는 뜻은 아니다

이 실험이 측정한 것은 **"전환 시점의 방향 예측력"** 이라는 가장 까다로운 한 가지 개념이다.
레짐 라벨의 실증된 가치는 그게 아니라 **조건부 게이팅**이다 — 2026-08-27 연구에서 현재 라벨은
chop 구간에서 증거신호 lift를 **+29~37% 개선**시켰다(`volume_wick_climax` 2.49→3.41,
`liquidity_sweep` 2.54→3.44, `smt_divergence` 2.63→3.51, `orthogonal_combo` 3.04→3.91).
즉 레짐은 **"지금 반전 신호가 잘 먹힌다"** 를 말해주지 **"가격이 오를 것이다"** 를 말해주지 않는다.

따라서 스캘핑용 레짐 라벨을 계속 추구한다면 목적함수를 바꿔야 한다:

> **"전환이 빠른 라벨"이 아니라 "증거신호 조건부 lift를 더 크게 개선하는 라벨"**

이건 Phase 1이 검정하지 않은 **다른 질문**이고, 넘어야 할 기준선(+29~37%)이 이미 존재한다.
그리고 스캘핑 관련성은 스케일이 아니라 **증거신호 자신의 horizon**(대부분 H=8~72봉)으로 들어온다.
