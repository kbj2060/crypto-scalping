# 배포 레이더(A10 HAR-1m) 위 체결 재료 재검 (2026-11-16)

스크립트 `scripts/research_radar_hawkes_20261116.py`(레이더 연구 스크립트 `research_realtime_risk_radar_20261115.py` 의 load·features·target·fit_predict·qlike 를 그대로 import) · 산출 `tmp/tape_raw_20261115/radar_hawkes.json`.
사용자 «레이더 위 재검» — 앞 연구(`docs/experiments/tape_raw_cef_20261115.md`)의 비교 상대가 연구용 GBM 이었으므로, 실제 배포된 레이더 식 위에서 다시 잰다.

## 설계
- 레이더 그대로: 코인별 OLS · log RV(1분봉 종가) 1·5·15·60·240분·1일·7일 + UTC 시각×주말 48칸 · 표적 다음 15분·60분 RV · 학습 2024-01-08~2025-12 · **시험 2026-06-01~10-27(ETH 127일·나머지 149일, 칸당 18~21만 분)** · QLIKE(낮을수록 좋음).
- 얹는 재료(분 마감까지의 체결만, 회귀에 열로 추가 — 같은 OLS):
  - **N 체결량**(대조): log 체결 수 · log 거래량, 10초·1분·5분·1시간 (8열)
  - **E Hawkes**: log 강도(매수+매도, 지수 커널 τ=1·10·60·600초, ms 체결 시각) + 분지 비율 근사 (5열)
  - **Z 위약**: E 의 하루 전 값
- 판정: 날짜 블록 부트스트랩 2,000회 단측 90% · 코인 Holm.

## 읽기
- **통과**: 레이더에 체결 재료를 얹으면 15분 폭 예측이 4% 낫다. 4코인 모두, 위약은 0.
- **그런데 대부분은 Hawkes 가 아니라 «체결 수·거래량» 자체다.** 레이더는 가격만 보고 «얼마나 바쁜가»를 안 본다. 단순 체결 수·거래량만 넣어도 −4.1%, Hawkes 를 더 얹으면 −0.6%(BTC 는 −1.2%) 추가.
- 앞 연구에서 «E 가 기준선(체결 수 포함) 위에 −2%»였던 것과 맞는 크기 — Hawkes 고유 몫은 0.5~1% 수준.

## 쓰는 법(배포는 안 함 · 배포 대기 B2)
- 1순위: **레이더 + N**(log 체결 수·거래량 8열). 서버 lake 테이프(초별 명목·테이커 주문 수 = aggTrade 수, 11-15 대조로 확인)로 바로 계산 가능 — ms 워커 불필요.
- 2순위: + E. τ=10·60·600초 강도는 초별 체결 수로 거의 같게 계산되나(초 안 시각 차이는 τ≥10초에서 작음), τ=1초는 ms 시각이 필요 → 쓰려면 근사 오차를 먼저 잴 것.

## 남은 위험
- **80%·95% 띠 포함률은 다시 안 쟀다** — 띠 배수(1.5σ̂·2.4σ̂)는 레이더 HAR 로 맞춘 값. σ̂ 가 바뀌면 띠 재보정 필요.
- 급변 경보(레이더에서 불통과)는 이 재검 범위 밖.
- 시험 2026-06~10 은 레이더 연구가 쓴 같은 구간(재사용) · 레이더 결과를 본 뒤 고른 비교다.
- 라이브 lake 테이프의 체결 수 열(order_n)과 이번 연구의 aggTrade 수가 같다는 확인은 XRP 하루 대조뿐.
