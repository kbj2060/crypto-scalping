## 2. 그래서 진짜 미측정은 4개다

| | 무엇 | 기존 격자에서 빠진 이유 |
|---|---|---|
| **A** | **BOS / CHoCH** (구조 계속 vs 전환) | SMC 의 뼈대인데 이 저장소에 항목 자체가 없다. `features/engineering.py::_create_market_structure` 는 BTC 상관·FVG 거리일 뿐 구조 돌파가 아니다 |
| **B** | **브레이커 / 미티게이션 블록** | plain OB(1.07x)는 쟀지만 «깨진 뒤 구조돌파 → 리테스트»라는 브레이커 고유 조건은 미측정 |
| **C** | **CRT** (Candle Range Theory) | 앵커가 다르다 — sweep 은 48봉 **롤링** 스윙, Po3 는 **아시아 세션**, CRT 는 **고정 HTF 봉 경계**. 게다가 청산이 레벨(반대 극단)이라 고정지평판으로는 본래형이 아니었다 |
| **D** | **TBS** (Time-Based Setups) | 사이클 4분면(Q1 축적→Q2 조작→Q3 분배) 격자는 미측정. 킬존은 *세션*이지 *사이클 분면*이 아니다 |

🔴**TBS 는 용어가 모호하다.** CRT 와 함께 가르쳐지는 계열의 지배적 독법인 **quarterly theory**
(사이클 4등분)로 구현했다. 다른 독법(예: Three Bar Setup)이 의도였다면 이 결과는 그 독법에 대한
판정이 아니다 — 스크립트 도크스트링에 같은 문구를 박아 뒀다. ⚠️5분봉에서 22.5분 사분면(90분
사이클의 1/4)은 정수봉이 아니라 만들 수 없어 격자는 **4h→1h · 24h→6h** 둘만 쓴다.

## 3. 설계 — 선행 라운드가 밟은 지뢰를 미리 넣는다

| # | 장치 | 왜 |
|---|---|---|
| 1 | `acc_needed`(손익분기 적중) · **`margin_pp`(여유)** 를 1급 컬럼으로 | 09-16 의 벽이 정확히 이 칸이었다. 정확도만 보면 또 속는다 |
| 2 | `fire_pct`(전체 봉 대비 발동) + 10% 초과 경고 | OB 29% · FVG 27% — **존이 차트를 덮으면 신호가 아니라 배경**이다 |
| 3 | 되찾기 on/off **쌍**으로 편성 | 09-16 4R 에서 D0(터치만) +4.08 > D1(되찾기) +1.18 — 되찾기가 정보를 더한다는 증거가 없다 |
| 4 | ⭐**앵커 이동 대조군**(격자를 반 칸만 민 팔) | 이 라운드의 핵심 신규. CRT/TBS 의 주장은 «그 시간 경계가 특별하다»다. 밀어도 같은 숫자면 정보는 봉 경계가 아니라 **최근 레인지 가장자리**에 있고, 그건 이미 닫힌 sweep 축이다 |
| 5 | 교집합 팔을 단품과 **같은 표**에 | 컨펌 쌓기 3회 재현 |
| 6 | 셀마다 **MDE**(80% 검정력) | «0 이다»와 «못 잰다»를 가른다 |
| 7 | 발동 인덱스 **순환이동** 200회 | 다중검정 귀무 — 우연히 몇 셀이 통과하는지 |
| 8 | **네이티브 배리어** 별표 | CRT 는 «반대 극단이 타깃»이라 레벨 청산이 본래형. intrabar·**SL 우선**(라이브 `evaluate_exit` 컨벤션) |

**인과성**(CLAUDE.md 사건-라벨 경계 계약): 발동 봉 i 는 봉 i 까지만 본다 → 진입 `open[i+1]` →
라벨은 i+1 부터. 스윙 피벗은 **확정 지연 k=6봉**을 반영해 p+k 이후에만 쓴다(중심 롤링 최대값을
그대로 쓰면 6봉 미래참조다). HTF 레인지는 **완결된 직전 칸**만 쓴다. TBS 는 Q2 **마지막 봉**에서
발동시켜 진입이 정확히 Q3 시가가 되게 했다.

**사전등록 판정**: PASS = 블록초과 > 5.52bp(양다리 peg) AND 초과 CI95 가 0 배제 AND |t_블록| ≥ 2
AND 전·후반 부호 일치 AND BH-FDR q < 0.10 **AND (C/D 계열) 앵커이동 대조군보다 클 것**.

## 4. 하네스 검증 — 랜덤워크에서 보정까지 끝냈다

실데이터가 없어도 할 수 있는 두 가지를 먼저 했다.

**(a) 단위검증(`--selftest`)** — 6개 항목 통과: 피벗이 확정 전에 보이지 않을 것(미래참조 트립와이어) ·
BOS/CHoCH 전이 1회만 · CRT 칸당 1회 · 터치만 대조군이 되찾기 팔의 **상위집합**일 것 ·
TBS 진입이 Q3 시가일 것 · 배리어 동시타격 시 **SL 우선**.

**(b) 합성 랜덤워크 150,000봉(517일)** — 엣지가 있으면 안 되는 표본이다:

```
pass_cells 0 · H=48 에서 비용선 초과 셀 0 · 순환이동 귀무 평균 0.94 (p95 3.0)
background_arms [] · median MDE 7.18bp
```

**하네스가 랜덤워크에서 아무것도 만들어내지 않는다**는 것이 확인됐다. 예비 주행(60k봉)에서
브레이커가 봉의 **10.4%**(30건/일)로 켜져 «배경» 경고가 떴고, 그래서 정의를 교본대로 조였다 —
구조돌파 시점의 **가장 최근에 깨진 존 하나만**, **첫 터치 1회만**. 5.2% 로 내려왔다.

## 5. 🔴 왜 이 세션에서 실측을 못 했나

작성 세션(`claude/dashboard-gex-orderflow-ict-gmdmt6`) 컨테이너는 egress 정책상
`data.binance.vision` 과 `api.binance.com` / `fapi.binance.com` 이 **모두 차단**돼 있다
(프록시 status 에 `connect_rejected … 403` 기록). 정책 거부는 우회하지 않는 것이 규칙이라
캔들을 받지 못했고, 저장소 컨테이너에는 `binance_data/klines/` 가 클론되지 않는다.

**서버에서 이 두 줄이면 끝난다** (수 분):

```bash
python scripts/research_eth_smc_crt_tbs_20260919.py                      # 실측 (ETH 5m, ~495k봉)
python scripts/research_eth_smc_crt_tbs_20260919.py --synthetic 150000   # 귀무 보정 재확인
```

산출: `tmp/eth_smc_crt_tbs_20260919/cells.csv` · `barrier.csv` · `summary.json`.
실데이터 모드에서는 `Z_sweep_plain(대조)` 팔이 자동으로 붙는다(라이브 `compute_signals` 호출,
식 두 벌 금지) — **이미 닫힌 축과 나란히** 읽으라는 뜻이다.

## 6. 결과를 어떻게 읽을 것인가 (미리 고정)

| 나오는 그림 | 읽는 법 |
|---|---|
| C/D 가 **앵커이동 대조군과 같다** | CRT/TBS 의 «시간 경계» 주장 기각. 정보는 레인지 가장자리에 있고 그건 닫힌 sweep 축 |
| 적중 우위는 **양수인데 `margin_pp` 가 음수** | 09-16 과 같은 벽(b 가 문제). ICT/SMC 계열 5번째 재현 |
| 되찾기 팔 < 터치만 팔 | 09-16 4R 의 D0>D1 재현 — 「되찾기」가 SMC 서사일 뿐이라는 두 번째 증거 |
| 교집합 팔이 단품보다 나쁨 | 컨펌 쌓기 **4번째** 실측 사례 |
| A/B 가 **전 셀 CI 0 포함 + MDE < 비용선** | 이번엔 «못 쟀다»가 아니라 **«비용선 규모의 엣지는 없다»** 라고 말할 수 있다 |
| 배리어판이 고정지평판보다 나쁨 | 배리어가 b 를 더 줄인다는 이 저장소 반복 결과의 재현 |

**어떤 결과가 나와도 이것은 승격 근거가 아니다.** PASS 가 나오면 그때 fresh-forward 규칙
(CLAUDE.md)과 seed/artifact 게이트를 새로 걸어야 하는 별개 절차가 시작될 뿐이다.

## 7. 대시보드와의 관계

같은 세션의 대시보드 조사 답변과 이어진다: **ICT/SMC 계열을 대시보드에 올리는 것은 «판단보조
오버레이»로서는 가능하고, «신호»로서는 위 영수증들이 막는다.** 이 라운드가 PASS 를 내지 못하면
BOS/CHoCH·브레이커·CRT·TBS 도 같은 등급(오버레이 가능, 신호 아님)으로 확정된다.
