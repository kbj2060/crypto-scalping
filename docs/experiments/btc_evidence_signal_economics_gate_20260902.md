## 0. ⭐⭐인덱스 오프셋 버그 (108바 = 9시간) -- 최초 결론을 무효화한 원인

### 무엇이 틀렸나

각 신호 빌더는 fires에 `"pos": idx`를 남기는데, 이 `idx`는 **빌더가 받은 프레임**의 행
인덱스다. 게이트는 그걸 **raw klines**의 인덱스로 그대로 썼다.

| | 시작 시각 | 행 수 |
|---|---|---|
| BTC 후보 CSV (빌더 입력) | 2024-01-01 00:00 | 277,191 |
| BTC raw klines (게이트 입력) | **2023-12-31 15:00** | 277,299 |

**오프셋 +108바 = 9시간.** 모든 진입이 실제 신호 발동보다 9시간 앞선 봉에서 일어났다 --
사실상 **무작위 진입**이었고, 그래서 전부 비용만큼 잃었다(−5~−7bp ≈ 비용 9bp).

    pos=     0  ts=2024-01-01 00:00  klines_idx=   108   오프셋 +108
    pos=200000  ts=2025-11-25 10:40  klines_idx=200108   오프셋 +108

### ⭐왜 ETH 하네스 대조군이 이걸 못 잡았나 (재사용 가치가 가장 큰 교훈)

0/672가 너무 완전해서 하네스를 의심했고, ETH로 대조군을 돌려 알려진 셀 3/4를 **소수점까지**
재현했다(§2). 그래서 "하네스 정상 ⇒ BTC 0/672는 진짜"라고 결론냈는데 **그 추론이 틀렸다.**

ETH fires의 `pos`는 ETH klines와 **오프셋 0으로 우연히 정렬**돼 있었다(실측 100% 일치).
즉 대조군은 **시뮬레이터는 검증했지만 BTC fires -> klines 매핑 경로는 지나가지 않았다.**

⇒ **대조군이 통과해도, 대조군이 지나지 않는 경로는 검증되지 않는다.**
대조군을 설계할 때 "이 대조가 실제로 어느 코드 경로를 덮는가"를 명시해야 한다.

### 수정

저장된 `pos`를 버리고 **타임스탬프로 klines에 직접 매핑**한 뒤 정확 일치를 검증한다
(`run_grid` 내부, 불일치 시 예외). 프레임 출처에 무관하게 안전하다.

### ⭐버그 진단의 독립 확인

**무작위 진입 귀무분포의 평균이 −6.16 ~ −7.15bp인데, 버그 있던 실행의 격자 최선이
−5.76 ~ −6.56bp였다.** 두 분포가 겹친다 -- 버그가 정확히 "무작위 진입"이었다는
독립적 증거다. 서사("비용이 엣지의 2배")가 그럴듯했던 이유도 이것이다:
무작위 진입은 실제로 비용만큼 잃는다.

### 읽을 때 주의

- **B 검정은 변별력이 약하다.** 무작위 진입은 20회 추출 전부에서 통과 셀 **0개**를 냈다
  (평균 0.0, 최대 0). 즉 양수이기만 하면 통과한다. 실질 판별은 A와 C가 한다.
- `taker_delta_climax`(VAL 숏 정방향 −1.50)와 `orthogonal_combo`(VAL 숏 정방향 −1.82)는
  **갭은 양수지만 절대값이 음수인 측면-구간이 있다.** 통과지만 상위 3종보다 약하다.
- 상위 3종(`demarker_extreme`, `short_term_return_z`, `kalman_deviation_meanrev`)만이
  **네 측면-구간(롱/숏 x VAL/OOS) 전부 정방향 절대값 양수**다.

### 두 가지를 나눠 읽어야 한다

⭐**(1) 방향 정보는 HOLDOUT에서도 확실히 살아있다.** 다섯 신호 **전부**가
방향뒤집기를 +8.1~+17.4bp 차로 이기고, 무작위 진입 귀무분포(B=200, 평균 −6.2~−7.2bp) 대비
**백분위 100%**다. 측면별 갭도 10개(5신호 x 롱/숏) 전부 양수다.
트리거가 방향을 담고 있다는 건 세 구간 연속으로 재확인됐다.

⚠️**(2) 그런데 10bp 비용을 뺀 절대 수익은 대부분 사라진다.**
다섯 신호가 **전부** VAL/OOS 대비 축소됐다(+2.4~+11.0 -> −1.3~+3.3bp).
셀을 VAL+OOS 96개 중 최선으로 골랐으므로 축소 자체는 예상된 방향이고,
**HOLDOUT 값이 정직한 추정치**다.

### 실제로 쓸 수 있는 것

**`demarker_extreme` +3.25bp**만 여유를 두고 양수다(n=428, 승률 81.3%, 5개월).
이 저장소의 ETH 배포 신호 HOLDOUT이 +1.97~+11.53bp였으므로 그 범위 안에 든다.
`orthogonal_combo` +1.47bp는 2군이라 판정 대상이 아니었고, `short_term_return_z` +0.06bp는
부호만 양수일 뿐 0과 구분되지 않는다.

⚠️**한계**: 무작위진입 귀무분포는 "진입 타이밍에 정보가 있는가"를 답하지 "+3.25bp가
재현되는가"를 답하지 않는다. 배포를 검토한다면 **트레이드별 분산 기반 신뢰구간**이
다음 진단이다. HOLDOUT은 이미 소진됐으므로 그 계산은 같은 사전등록 셀의 결과를 다시 읽는
형태여야 하고, 셀을 바꾸는 순간 오염이다.

⚠️**HOLDOUT 소진.** 스크립트는 결과 파일 존재 시 실행을 거부한다. 이 신호 풀·이 라벨 정의로는
재노출할 수 없다.
