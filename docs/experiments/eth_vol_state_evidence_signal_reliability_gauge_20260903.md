## 발단

정직한 L3 라벨에서 단순 규칙을 훑다가 `atr_pct >= p90` / `parkinson_vol >= p90`이 3 ATR
페이드에서 3창 전부 크게 양수로 나왔다(무필터 대비 VAL +14 / OOS +12~23 / HOLDOUT +50bp).
파라미터 1개짜리 규칙이라 *"증거신호로 올릴까"* 라는 물음이 자연스러웠다.

## ⭐두 결과는 모순이 아니라 정합한다

```
bottom 신호 발동 → 지정가는 3 ATR **아래**(= 신호가 틀리는 방향)에 건다
고변동성 → 가격이 계속 내려감 (신호 실패 = hit률 하락)
        → 우리 지정가가 체결됨
        → 그 뒤 되돌림 (페이드 성공 = +50bp)
```

**고변동성은 "신호가 오버슈트할 국면"을 가리킨다.** 신호 자체는 틀리고, 그 실패 방향으로
3 ATR 더 간 지점의 페이드가 먹힌다.

## 결론 -- 9번째 증거신호가 아니라 **메타 지표**

증거신호로 올리면 사용자가 *"뭔가 일어나고 있다"* 로 읽는다. 실제 의미는 **"지금은 나머지
8종을 믿지 말라"** 이므로 **정반대로 오독된다.**

⭐올바른 자리: 대시보드의 **신뢰도 게이지** -- *"증거신호 신뢰도: 낮음(고변동성 국면, 적중률
−14%p)"*. 방향 정보가 없으므로 칩이 아니라 **8종 위에 얹는 상태 표시**다.

⚠️**아직 배포하지 않았다.** 효과는 8/8 일관에 표본도 크지만(5,714건), 다음이 남았다:
  · 기존 레짐 분류기(chop/bull/bear)와의 중복도 -- **미측정**(레짐 parquet이 서버에 없어 ④가 안 돌았다)
  · 임계값(p90)이 절벽 위인지 -- 3 ATR 페이드 쪽에서는 p90→p95에서 VAL 부호가 뒤집혔다
  · 창별 안정성 -- 위 표는 VAL/OOS/HOLDOUT 합산이다
