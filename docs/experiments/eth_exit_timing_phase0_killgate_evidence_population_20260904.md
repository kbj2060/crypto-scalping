## 1. 왜 모집단을 바꿨나 — Omega 후보 풀 기각

09-03 설계는 후보 풀로 **h48qual/Omega 원시 진입후보**를 골랐다. 사용자 지적(09-04): *"Omega 라이브는 시드 검증
결과 사용 불가인데 이걸 가지고 개발하나?"* — 맞다. Omega4.6.1 라이브는 3시드 6창 중 4창 부호 반전, DSR 0.88~0.92
(통과선 0.95), PBO 0.44, falsification FAIL로 **엣지가 입증된 적이 없다**.

기술적으로 "엣지 없는 진입의 포지션"도 청산 학습 데이터로는 유효하다(청산 모델은 진입 이후 경로에서 배우고
기준선도 같은 포지션의 '끝까지 보유'다). 그러나 둘이 실제로 물린다: ① Omega를 끌 거면 그 포지션에 맞춘 청산
모델은 **배포 대상이 없다** ② `pos_tp/pos_sl`은 h48qual 브라켓 기하고 포지션 분포는 h48qual 방향 헤드의 편향을
물려받는다. 그리고 설계가 Omega를 고른 유일한 이유("증거신호 진입은 앵커 미래참조로 막혀 있다")는 09-02 raw 인과
모집단(cluster_dedup 없음)이 만들어지고 09-03 L1 게이트(known_ts 절단 재계산 + 유령 발동 0)로 인과성이 기계
확인되면서 사라졌다.

②의 목적("진입은 재량/단순 규칙, 모델은 안 잃는 걸로 번다")에 맞는 모집단은 **재량 진입이 실제로 일어나는
자리 = 대시보드 증거신호 발동 봉**이다. 사용자 선택(09-04): A안 채택.

## 4. 판정 기준 (사전등록, 설계 §3-4 그대로 + 보조 2개)

> **VAL timeout 체크포인트에서 ΔAUC = AUC(B 또는 C) − AUC(A)**, 5시드(무작위 추출, `default_rng(20260904)`) 평균확률 기준,
> **발동(후보) 단위 군집 부트스트랩(B=1000) 95% CI 하한 > 0** 이고 **5시드 각각 ΔAUC > 0 (5/5)**.
> 못 넘으면 "재료는 매매용 기여 없음(세 번째 0)" 선언, RL 착수 중단. 재료는 표시·연구 자산으로 남긴다.

보조(통과 여부와 무관하게 보고, 경고 사유):
- **일(day) 단위 군집 CI** — 09-03 "독립 일수 42~45일, 행단위 p는 군집 무시" 교훈. 발동 CI는 통과인데 일 CI가
  0을 포함하면 PASS-with-warning으로 표시하고 사용자와 논의한다(사전등록 기준 자체는 발동 단위).
- **OOS ΔAUC 부호**(설계 실패조건 ⑤) · **anti-stable**: TRAIN-VAL 단일피쳐 AUC Spearman ρ가 음수면 중단 ·
  **순열중요도 top15에 재료 열 진입 여부**(entry축은 0개) · **정책평가**: 같은 트리거율의 무작위 exit 대조를
  VAL·OOS 양창에서 못 이기면 실패(③), 저장소 표준 트레일링(SL3/ARM1/Trail0.1, intrabar)을 비교군으로 나란히 둔다.
- 비용은 표준 10bp(1회)와 09-04 실측 7.8bp(진입 peg + 청산 taker) 둘 다 보고.

**이 결과는 research/dev score다.** 저장 원장은 쓰지 않았지만(발동→시뮬 직접) timeout 선택이 결과 기준 선택이라
