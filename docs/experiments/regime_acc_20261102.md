## 검증 (누수·위약)
- 라벨 독립 재구성(원자료 + 스냅샷에서 직접 계산) 400건 불일치 0. 레벨 스냅샷은 t 에 닫힌 봉만(open < t), 피쳐는 봉 i 마감까지, 라벨은 i+1 이후.
- 라벨 순환이동 위약(200회): 정확도 평균 50.9%, 최대 54.4% → 모델 68.7% 는 우연이 아니다.
- 중요도(정확도 하락): **띠 폭 ÷ 변동성(lw_sig) 0.097** ≫ 시간대(hc) .042 · 띠 안 위치(bpos) .039 · 변동성 비(rv48_288) .011. 즉 정확도의 큰 몫은 «띠가 변동성에 비해 좁으면 곧 뚫린다»는 **기하**다(박스 유지 모델과 같은 원리, 알려진 효과). 레벨 기하를 전부 빼도 63.7% (변동성·ER·시간대만으로도), 기하만 쓴 HGB 64.3% → 기하 + 나머지 결합이 68.7%.

| 라벨 | 시험 정확도 | AUC | 항상 다수결 |

→ 정확도가 의미 있게 올라가는 건 균형이 맞는 4시간 라벨이다. 1시간·12시간은 비율이 한쪽으로 쏠려 다수결에 거의 못 올라선다(AUC 는 .74~.80).

## 한계
1. 라벨은 «가장 가까운 지지~저항 띠 이탈»이다 — 사용자의 눈으로 본 횡보/추세와 같지 않을 수 있다(레벨이 대시보드 청산맵 재구성이고, 띠가 넓으면 횡보로 판정이 쉬워진다).
2. 기하 몫이 크다: 모델의 «새 정보»는 기하 기준선 대비 +6.9%p. 기하는 레벨 위치만 알면 계산되는 정보라 틀린 건 아니지만, 정확도 수치를 «시장 이해»로 읽으면 안 된다.
3. 시험 구간(5개월, 4코인)은 한 번 썼다. 더 개선하려면 새 사전등록 + 전진 데이터(2026-10-24 이후)가 필요하다.
4. 모델은 훈련 라벨이 H=4h 인 «미래 4시간» 예측이다. 지금 이 순간의 레짐을 «과거 4시간»으로 정의하면 정의상 100%에 가깝다(순환이라 평가 가치 없음).
5. 서빙 코드는 아직 없다: 필요 입력 = 시간별 청산맵 레벨(대시보드 `compute_spliced_levels`) + 이 스크립트의 `features()`와 레벨 기하 계산. 학습·서빙 같은 함수를 쓰려면 `features()` 를 서빙에서 import 해야 한다.

## 정정 (2026-11-02, 독립 검증 뒤)
- 사전등록의 «레벨 결측 0»은 정확하지 않다: 지지·저항 중 한쪽이 없어 라벨이 0(횡보)으로 굳는 행이 학습 데이터 113/97,904(0.12%, yA48=0이 93·=1이 20), 제로샷 153/115,390 이다(`(W>nan)|(W<nan)` = False → NaN 대신 0). 정확도에 미치는 영향은 무시할 수준. 개선하려면 해당 행의 라벨을 NaN 으로 두고 제외.
- 확신도 0.8 이상은 시험 구간의 약 3%(455/13,908)이고, 0.6 이상 전체가 약 16%다(채팅 설명에서 0.8↑를 16%라고 잘못 말한 것을 바로잡음).
- 배포 모델은 시험 구간까지 포함한 전 행으로 재적합(`final`)했으므로 2026-10-23 까지는 in-sample 이다. 실제 OOS 증거는 전진 기록기(2026-10-24 이후)뿐이다.
- 4코인 청산 스냅샷 pkl 은 `research_xrp_lowvol_sweep_fade_v2_20261102.snapshots` 를 코인별로 호출해 만들었다(생산 스크립트는 세션 스크래치패드에 있었고 저장소에 없음 — 제로샷 스크립트의 `snap` 은 CSV 코인용으로 같은 방식).
