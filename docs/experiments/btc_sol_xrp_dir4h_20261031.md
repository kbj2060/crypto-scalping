## 해석
- **SOL**: ETH 레시피가 SOL 에서도 4h 방향 정보가 있다(세 팔 모두 양수, 크기 정보도 있음). 사전등록대로 고른 팔 = **E(ETH 학습 모형을 SOL 피쳐에 적용)**. S 팔과의 차이는 잡음 범위로 보이며(검증 .028 vs .038, 시험 .077 vs .069), S 로 바꾸는 건 사후 선택이다.
- **XRP**: 10-21 불통과(단독 학습·지정가 매매 샤프)와 달리 이번 잣대(표시 정보)로는 J 팔이 **엄격 통과** — 그러나 ① 검증 5달 내내 정보가 없었고 ② 하한 +.002 로 경계선 ③ 피어슨 ≈ 0·모델−롱 음수. «XRP 4h 화살표는 약한 부호 정보, 크기 없음»으로 읽어야 하며, 서빙한다면 전진 창 확인을 붙이는 게 맞다.
- **BTC**: 두 번째 라운드도 불통과(세 팔 다). 10-10 결론 «4h HGB 는 BTC 에서 안 된다»가 이 레시피·이 기간에도 유지.
- 왜 XRP 가 이번엔 통과했나(가설, 검정 안 함): 옛 판정은 단독 학습만 봤고(이번 S 팔도 검증 .002 로 같은 모습) 매매 샤프로 채점했다. 합동 팔의 시험 양수는 2026 하반기에만 보이므로 «방법 차이»보다 «구간 차이» 몫이 클 수 있다.

## 서빙에 필요한 것(체크리스트 — 이번엔 만들지 않음)
통과 = SOL(E 팔)·XRP(J 팔). 둘 다 지금 서빙 경로가 ETH 한 코인 고정이다.
1. **모델 파일**: SOL = 배포 ETH 모형(`eth_dir4h_model.joblib` 의 models) 그대로 쓰되 SOL 용 표본 밖 기록·문턱이 따로 필요 → `data/live/sol_dir4h_model.joblib`(models 참조 또는 복사 + SOL oos·lo·hi). XRP = 4코인 합동 HGB 를 매달 학습 → `data/live/xrp_dir4h_model.joblib`.
2. **표본 밖 씨앗**: 이 실험의 `preds.npz` 에서 SOL_E·XRP_J 를 2023-01~2026-10 로 `{sol,xrp}_dir4h_oos_seed.parquet`(배포 `OOS_SEED` 와 같은 형식 ts·pred) — `thresholds()` 의 8,640행 예열 요건 충족.
3. **`train()` 코인 인자**: 대상 코인 프레임 바꾸기(`frames["ETH"]=대상`, `frames[대상]=ETH`) + J 팔 = 4코인 행 [::4]·y 표준화 쌓기. 학습 창 구멍 검사를 4코인 모두에. 매달 cron(ETH `20 18 1 * *` KST 뒤, 같은 flock).
4. **학습 원천**: 서버 `data/live/dir4h_panel` 은 ETH+19코인(480일) — SOL·XRP·BTC 가 이미 교차 코인으로 들어 있어 추가 다운로드 없음.
5. **실시간 프레임**: `rest_frames()` 는 ETH 만 klines 9,000봉 + metrics 5종, 나머지는 340봉 klines 만 받는다 → 대상 코인(SOL·XRP)도 metrics 5종 + 긴 klines 필요(J 팔 XRP 는 피쳐 자체는 XRP 한 벌만 필요 — 학습만 4코인). `daily_closes()` 심볼 인자. REST 추가분 = 코인당 metrics 5종 꼬리 + klines — 서버 IP 한도 확인(로컬 REST 금지).
6. **파리티**: 서버에서 SOL·XRP 판 `--parity`(REST 피쳐 ↔ vision 피쳐 어제 하루, 상관 ≥ .999).
7. **API**: `/api/dir4h?asset=sol|xrp`(신뢰경계 = 허용 코인 집합) + 코인별 아티팩트 mtime 캐시.
8. **화면**: app.js 4h 칸이 ETH 고정 → 코인 따라 바꾸기 = 화면 변경이므로 `/impeccable` 절차 대상. XRP 툴팁에 «합동 학습 · 크기 정보 없음(피어슨 ≈ 0) · 전진 확인 중», SOL 툴팁에 «ETH 학습 모형 적용» 한 줄.
9. **전진 기록**: XRP 는 경계선 통과라 서빙 시 전진 창(예: 90일) IC·적중 초과 기록을 같이 둔다.
