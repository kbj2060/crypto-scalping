## 1. 문제 정식화가 두 번 바뀌었다

**처음**: "신호가 제안한 방향을 받을지 거절할지" (수락/기권 필터).

**1차 전환** — 사용자가 "방향을 고르는 모델 아니었나"라고 지적. 방향 모델(안 B)의 오라클 천장을
재려다 **계산 결함**을 발견했다. v1은 **롱 체결가에서 숏 수익**을 쟀는데, 지정가는 한쪽으로만
걸리므로(bottom 신호 → 3 ATR 아래 매수) 체결되면 롱이고 그 가격에서 숏이 될 수 없다.
실현 불가능한 반사실이었다.

v2에서 두 팔을 **각자 다른 체결 사건**으로 다시 계산했다(신호방향 = 아래 매수 / 역방향 = 위 매도).
그러자 부호가 뒤집혔다 — v1에서 −8~−18bp였던 "뒤집기"가 **+7~13bp로 수익**이 됐다.

⭐**두 팔 다 "3 ATR excursion 페이드"다.** bottom 신호에서 아래 매수는 더 빠진 걸 사고, 위 매도는
튄 걸 판다. **엣지의 출처는 신호의 방향이 아니라 excursion 자체**이고, 신호는 "그런 움직임이
나오고 되돌릴 만한 순간"을 짚어줄 뿐이다.

**"양쪽 다 걸기"가 방향을 완벽히 아는 오라클A를 이긴다. 모델 없이.** 그래서 기준선이 바뀌었고,
트리거당 총 체결이 1.01~1.02건이라(양쪽 동시 체결 0.9%) 주문은 둘이어도 포지션은 사실상 하나다.

**2차 전환** — 무제한 자본에서는 필터가 **원리상 손해**다(거의 모든 팔이 양수라 거르면 이익을
버린다). B0-a에서 τ를 올릴수록 단조 악화했고 시드 0/5였다. 사용자가 "잣대가 틀렸다"고 지적해
**슬롯 제약**으로 옮기자 정반대가 됐다 — 1슬롯에서 필터가 약 2배 이득.

⚠️이 과정에서 **역선택 오진을 한 번 했다.** τ=−5bp의 제외군(n=119)에서 유지 16.50 vs 제외 26.70을
보고 "역선택"이라고 했는데, CI가 [14.6, 38.0]으로 완전히 겹치는 노이즈였다. 의미 있는 크기
(τ=+5bp, 제외 n=1,551)에서는 유지 20.83 vs 제외 8.95로 **정상 판별**이었다. 작은 부분집합의
평균을 결론으로 쓰지 말 것.

## 2. 표본이 병목이었고, 확장이 풀었다

τ를 올리면 성과가 오르는데 n이 32~67, 독립 블록 9일로 무너져 검정력이 없었다.
깊이 {2.0,2.5,3.0,3.5} × 대기 {6,12}로 확장해 **체결 11,311 → 138,005건**으로 늘렸다.
(대기는 상위집합이라 wait=12로 한 번 시뮬하고 `btf<=6`으로 걸러 파생)

그 결과 최적점 n이 107~224, 독립 블록 17~25일이 됐고 3창이 +59~63bp로 수렴했다.

⭐**순위 배분(M 상위만 살리기)은 실패했다** — 표본은 지켰지만(n 201~297) 무작위 M 대조군을
못 이겼다(p=0.25~0.55). 개선분 전부가 "동시 대기 주문 수를 줄인 것" 자체에서 나왔다.
대기 중인 주문들끼리는 서로 비슷해 상대 순위에 정보가 없고, **전체에서 상위 12%를 뽑는 건
정보가 있다**. 그래서 τ 임계값 방식을 유지했다.

## 4. 선택 축 — 사전등록으로 닫았고, 전부 현행이 남았다

### 피쳐 (B2 → B8)
확장 표본(행/피쳐 **504**)에서 재선별. **k=15~161이 전부 +54~62bp로 평평**하고 뚜렷한 봉우리가
없다. 선별본 최고(k=25)가 VAL 동률·OOS −3.0bp로 뒤져 **161개 동결**.
*판정 규칙: 선별의 목적은 단순화이지 성능 향상이 아니므로, 동등하면 이미 대조군을 통과한 쪽.*

### 아키텍처 (B9 → B15)
| 후보 | 결과 |
|---|---|
| absolute_error / quantile(0.5) | VAL 동률, OOS −7.0 |
| **quantile(0.6)** | VAL +3.02 · **OOS −2.35** · HOLDOUT +5.51 |
| winsorize(p1/p99) | VAL −1.97 · OOS −8.61 |
| 분류 `y > 40bp` | VAL −5.08 · **OOS +4.13** · HOLDOUT +7.37 |
| 분류 `y > 0` | 3창 −25bp 이상 |
| TabPFN 회귀 (18k×4) | 3창 −0.08~−2.39 |
| **TabPFN 분류 (18k×5)** | 양 창 승리 ✅ · **순열검정 VAL p=0.139 / OOS p=0.052 ❌** · 대조군 ✅ |

⭐**여러 후보가 서로 다른 한 창에서만 이긴다** — quantile(0.6)은 VAL/HOLDOUT, 분류는 OOS/HOLDOUT.
이건 대안이 진짜 나은 게 아니라 **창별 노이즈가 ±5bp 수준**이라는 뜻이고, "양 창 동시 승리"를
기준으로 잡은 이유다. 한 창만 봤으면 여러 번 잘못 결론냈을 것이다.

### ⭐데이터량 vs 학습기 분리 (B14)
TabPFN을 서브샘플로 돌리니 "데이터를 78% 버려서 진 것"이라는 가설이 생겼다. HGB도 **같은 18k
서브샘플**로 돌려 분리했다:

```
데이터량의 값어치 (HGB-full − HGB-sub) : VAL −0.82 · OOS +0.89 · HOLDOUT −0.33
동일 데이터 학습기 차이 (TabPFN − HGB) : VAL +0.91 · OOS +1.79 · HOLDOUT +5.52
```

**데이터를 100%→22%로 줄여도 성능이 안 변한다(±0.9bp).** 81,168행이 필요 없고 18,000행이면
포화다. 그러면 "컨텍스트 제약이 TabPFN을 죽인다"는 이 저장소의 기존 법칙은
**표본이 포화되지 않았을 때만 참**이다 — 정정이 필요하다.
그리고 TabPFN **분류기**는 같은 데이터에서 HGB를 3창 전부 앞선다(+0.91/+1.79/+5.52).

⚠️**즉 TabPFN 분류가 진짜로 조금 나을 가능성이 실재한다.** 다만 10번째 후보의 경계선 결과
(OOS p=0.0518)라 다중검정에 당하지 않으려면 채택 불가다. **표본이 더 쌓이면 재검정할 것.**

`docs.priorlabs.ai/improving-performance` · `/capabilities/embeddings`를 읽고 적용했다.
지금까지의 TabPFN 비교가 불공정했을 가능성을 확인하기 위해서다.

## 5. 누수 방지 두 겹

**OOF 교차적합** — 재료 `_pct`는 메타라벨 TRAIN이 필터 TRAIN과 **100% 겹쳐** 모든 행이 in-sample
이었다. 청산 설계의 해법(TRAIN 롤백)은 발동 모집단이 2024-01에 시작해 밀 공간이 없어 안 통한다.
시계열 확장창 K-fold OOF로 해결(워밍업 2024-01~04 제외, fold k는 그 앞 구간만 학습).
레짐도 같은 방식으로 fold별 재훈련(임계값도 fold 학습창에서만 백분위 보정).

⚠️결과적으로 재료와 레짐 예측값은 **둘 다 기여 0**으로 확인돼 최종 피쳐에서 빠졌다.
누수를 막아놓고 보니 애초에 쓸 게 없었다 — **이 재료의 세 번째 0**이다.
