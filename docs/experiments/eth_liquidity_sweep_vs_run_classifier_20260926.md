# ETH 유동성 스윕 vs 런 분류기 — 파이프라인 + 누수 귀무 검정 (2026-09-26)

- 요청: 사용자 *"이전에 증거신호로 쓰던 liquidity sweep 과 liquidity run 신호를 구분할 수 있는
  최고 정확도를 가진 모델이나 로직을 만들어줘"*
- 스크립트: `scripts/research_eth_liquidity_sweep_vs_run_classifier_20260926.py`
- ⚠️**상태: 실데이터 미실행.** 이 세션은 클라우드 컨테이너라 `binance_data/` 가 없고, 네트워크 정책이
  `data.binance.vision`·`fapi.binance.com`(및 bybit/okx/coinbase/kraken/hyperliquid)을 막았다.
  아래 숫자는 전부 **합성 무작위보행 귀무 검정**이다. 실데이터 정확도는 아직 없다.

## 질문 정의

가격이 직전 48봉 스윙 고/저점(대시보드 `liquidity_sweep` 과 같은 레벨)을 **찌른 봉 i** 에서,
- **SWEEP** = 레벨 안쪽(반전) 방향으로 먼저 간다
- **RUN** = 찌른(지속) 방향으로 먼저 간다

| 항목 | 값 | 이유 |
|---|---|---|
| 트리거 | 봉 i 의 고가 > 직전 48봉 고가 (바닥은 거울상) | `찌름 & 안쪽마감` 이 라이브 `top/bottom_liquidity_sweep` 과 **봉 단위 동치임을 assert** (식 두 벌 금지) |
| 사건 dedup | 같은 측면 찌름이 직전 12봉에 없을 때만 | 런 구간에서는 매 봉이 찌른다. 과거만 보는 인과 dedup (유령 발동 없음) |
| 결정 시점 | 봉 i 마감 후 | 트리거는 봉 i *안에서* 일어난다 (OBS=0 금지) |
| 라벨 | 기준가 close[i], ±1.5·ATR[i] **대칭** 배리어, 봉 i+1 부터 24봉(2h), 고/저가 first-touch | 1.5 ATR = 08-29 V반등 라벨 최종판 이동량 기준 |
| 제외 | 같은 봉 양쪽 터치 · 24봉 미결 | 건수는 `events_by_outcome` 에 보고 |
| 피쳐 | `g_*` = 트리거 봉 i 자신 (깊이·마감위치·꼬리·몸통·거래량·테이커 델타·BTC 동시찌름), `f_*` = 봉 i-1 까지 맥락 (모멘텀 3/12/48/288, EMA288 거리, 레인지 폭, 레벨 나이, EQH 터치수, 24h 레벨 간격, ATR 레짐, 최근 찌름 수, 반대측 경과, 시각) | 피쳐 창 끝 i < 라벨 시작 i+1 (경계 계약). `f_*` 는 ATR[i-1] 로 정규화 |

⭐**대칭 배리어를 고른 이유.** 08-29 V반등 모델은 분류 정확도 61.6% 였는데 매매 승률은 49% 로
무너졌다. NO_V_REBOUND 클래스가 "반대 방향"이 아니라 "나머지 전부"였기 때문이다
(`eth_liquidity_sweep_v_rebound_feature_plan_20260829.md`). 이 라벨은 두 클래스가 정확히 반대
방향이다. 그래서 **분류 정확도 = TP=SL=1.5ATR 방향 베팅의 승률**(비용 전, 제외 사건 빼고)이 되고,
무작위보행이면 기저가 정확히 50% 다.

## 모델 사다리

| 이름 | 내용 |
|---|---|
| R0 | 다수클래스 |
| **R1** | **대시보드 규칙 그대로** — 안쪽 마감 = SWEEP, 바깥 마감 = RUN |
| R2 | 깊이 2 트리 (2~3피쳐 규칙, 탐지 신호의 비교 기준) |
| LR | 로지스틱 (C 는 VAL 로 선택) |
| HGB | HistGradientBoosting (g+f, 16조합 격자를 VAL 로그손실로 선택, 결정적) |
| HGB_ctx | f 만 (트리거 봉 없이 맥락만) — 트리거 봉 정보의 기여 측정 |

평가는 두 가지로 한다.
1. **고정 분할**: TRAIN <2025-09 · VAL 2025-09~12 (선택) · OOS 2026-01~03 · HOLDOUT 2026-04+
   (08-29 에 소진 선언 → 진단 전용). 라벨 창이 다음 구간으로 넘어가는 사건은 엠바고로 버린다.
2. ⭐**월별 확장창 walk-forward** (2023-01~): 매달, 그 달 시작 전에 라벨까지 끝난 사건만으로 학습한다.
   하이퍼파라미터는 고정이다. 표본외 사건이 약 1만 건이라 로직 간 1~2pp 차이를 가릴 수 있다.
   **"최고 정확도" 판정은 이것으로 한다.**

## 누수 검증 — 합성 데이터에서 완료

### ① 셀프테스트 + 돌연변이 검사
셀프테스트는 네 가지를 확인한다.
- 라벨이 봉 i 의 시가·거래량에 불변이다.
- 폭을 고정하면 라벨이 봉 i 의 고/저에도 불변이다.
- `build()` 라벨 = `first_touch(i+1, …)` 재계산과 일치한다.
- 봉 i+1 이후 가격을 5% 바꿔도 피쳐가 불변이다.

누수 3종을 일부러 심은 변형을 **셋 다 잡았다**.

| 심은 누수 | 결과 |
|---|---|
| 라벨 시작 `idx+1 → idx` | `AssertionError: build() 라벨 시작이 i+1 이 아니다` |
| 맥락 피쳐 `p = idx-1 → idx+1` | `AssertionError: 피쳐가 미래 봉에 의존` |
| `g_body` 에 다음 봉 종가 | `AssertionError: 피쳐가 미래 봉에 의존` |

### ② 절단 인과성
사건 30건마다 데이터를 봉 i 에서 잘라 피쳐를 다시 만들었다. 불일치 0, 최대 상대오차 1e-14.

### ③ ⭐무작위보행 귀무 (`--synthetic-null`)
실제 타임스탬프(2021-12~2026-09, 502,272봉)에 1분 무작위보행을 5분봉으로 집계해 넣고 **같은
파이프라인 전체**를 돌렸다. 예측가능성이 0 이므로 정답은 50% 다. 시드 5개는 랜덤 추출이다:
`228532758, 193491212, 786824425, 22783539, 202004588`.

walk-forward 정확도 (사건 약 1만 건):

| 시드 | R1 대시보드 | R2 | LR | HGB | HGB_ctx |
|---|---:|---:|---:|---:|---:|
| 193491212 | 49.82 | 49.63 | 48.91 | 50.68 | 50.61 |
| 202004588 | 49.82 | 49.95 | 50.47 | 50.80 | 49.76 |
| 22783539 | 49.95 | 50.64 | 50.46 | 49.74 | 49.50 |
| 228532758 | 49.93 | 49.78 | 49.02 | 49.98 | 49.52 |
| 786824425 | 49.41 | 50.76 | 49.58 | 50.14 | 50.27 |

**25개 값이 모두 48.9~50.8% 다. 누수 징후는 없다.** 단일피쳐 AUC 최대 0.521, FAIL/FLAG 0.

같은 귀무가 알려 준 **우연 폭**:
- **3개월 OOS(약 670건)는 ±5pp 로 흔들린다.** 별도 시드 20260926 에서 VAL 로 고른 LR 이
  OOS **55.75%** (일군집 CI [51.6, 59.8] — 0.5 를 배제)였다. 같은 모델이 VAL 48.8% · HOLDOUT
  49.8% 였으니 순수한 우연이다. HOLDOUT 도 시드 하나에서 53.9% 가 나왔다.
  → **3개월 OOS 하나로 "최고 정확도"를 주장하면 안 된다.**
- 여러 로직 중 최고를 고르면 walk-forward 에서도 **최대 +0.8pp**, "최고 − R1" 차이는 **최대 +1.36pp**
  (시드 1/5 에서 일군집 CI 가 0 을 배제)까지 우연으로 나온다. 일군집 CI 는 최고 선택 후에는
  약간 낙관적이다.

## 실데이터 판정 기준 (사전등록 — 실행 전에 고정)

실데이터 walk-forward 에서 다음을 **모두** 만족해야 "R1(대시보드 규칙)보다 나은 스윕/런 판별기"다.
1. 최고 로직 정확도 ≥ **51.5%** (귀무 최대 50.8% 위)
2. 최고 − R1 ≥ **+2pp**, 그리고 paired 일군집 CI 가 0 을 배제 (귀무 최대 +1.36pp 위)
3. 연도별(2023·2024·2025·2026) 정확도가 **전부 50% 초과**
4. 누수 진단 FAIL 0. 탐지 신호 FLAG 가 뜨면 누수부터 의심한다 (모델 − R2 ≥ 5pp 인데 최상위 중요도 피쳐의 분위 효과가 평평한 경우)

3개월 OOS·HOLDOUT 숫자는 보조로만 읽는다. 1~3 을 넘어도 **분류 점수일 뿐 거래 성과가 아니다**.
09-14 에 이 축의 bp 는 1,741일에서 음수로 종결됐고, 이 라벨의 제외 사건(양쪽 터치)은 실거래에서는
손실일 수 있다. 진입 파이프라인으로 옮기면 `gate_eth_entry_layers_20260903.py`(특히 L2 1분 재구성 —
같은 봉 양쪽 터치 해소)와 fresh-forward 를 따로 통과해야 한다.

## How to apply

- ⭐**이벤트 분류 정확도를 주장하기 전에 같은 파이프라인을 무작위보행에 돌려 우연 폭을 먼저 잰다.**
  이번에 3개월 OOS 가 귀무에서 55.75% 를 냈다. 사건 약 700건짜리 창의 5pp 는 신호가 아니다.
- 방향 판별 라벨은 **두 클래스가 정확히 반대인 대칭 배리어**로 만든다. "X 인가 vs 나머지 전부"
  라벨은 분류 정확도가 매매 승률로 옮겨지지 않는다 (08-29 의 61.6% → 49%).
- 대시보드 규칙(R1, 안쪽 마감=스윕)은 모든 비교에 베이스라인으로 넣는다. 모델이 이것을 +2pp
  이상 못 넘으면 "스윕/런 판별 모델"은 대시보드 칩 이상의 정보가 없다.
