## 2. known_ts 측정 (30일)
20초 폴링으로 행별 첫 관측 시각을 기록해 지연(first_seen − 스탬프)의 p50/p95, **≤12초 비율**(결정 시각에 스탬프 C 행이 보이는가), ≤300초 비율(행 T 규약 성립 여부)을 낸다.
사전 관측(09-05 00:15Z curl): 16:15:16Z에 최신 행 16:10 → 스탬프 C 행 지연 > 16초; 기존 서버 수집기(oi_lsratio.duckdb, 1시간 배치)는 지연 하한 102초만 준다.
- ≤300초 비율 < 95% → 행 T 규약도 못 지키므로 **러너 규약을 고치기 전엔 성과 판단 금지**.
- ≤12초 비율 ≥ 95%가 나오면 lag0 규약(스탬프 C 행 사용)을 **새로 사전등록**해 별도 원장으로 돌린다(기존 원장에 흡수하지 않음).

## 3. 가설과 판정
- **H1(주)**: B2 마감 트레이드 평균 순손익(10bp) > 0. 백테스트(lag1) TRAIN +4.9 [−1.1, 11.0] / VAL +12.7 [2.3, 23.6] / OOS +12.3 [−0.45, 26.8] bp/건, 3.4건/일.
- **H2(주, 채택 기준)**: **B2 한계 일손익**(자본 대비 bp/일, 슬롯=자본/5, 청산일 기준) 의 90일 일군집 CI 하한 > 0. 백테스트 (R∪B)−R +3.3 / +6.1 / +7.4 bp/일.
- **H3(2차)**: 합집합 cap5 재구성(두 원장 진입·청산 시각) − R cap5 > 0. R 원장이 이미 cap5로 잘려 있어 보수적.
- **H4(2차)**: 롱·숏 측면 각각 > 0 (OOS 숏 측면 차이 −6.9 였음 — 측면 갭이 재현되면 숏 전용 제외 변형을 **새로 사전등록**).
- 빈도: 백테스트 3.4건/일 ±40%. 벗어나면 임계·z 창 정의(행 공간 vs 봉 공간 결측) 확인.

**절차**: 30일 계측 점검(known_ts §2 + 진입 지연 중앙 ≤30초 + 슬리피지 |·| ≤3bp + 빈도 + 재구성 파리티 ≥95%) → 90일 판정(H2 CI 하한 > 0 → R 섀도우의 두 번째 사건원으로 채택 설계 / 상한 < 0 → 폐기 / 사이 → 90일 연장 1회).
킬 스위치: 최근 30일 B2 평균 < −10bp/건 ∧ 일군집 CI 상한 < 0 → 정지·보고.

## 4. 무엇이 이 규칙을 반증하는가
- known_ts 가 행 T 규약조차 못 지킴(지연 > 5분 잦음) → 데이터 소스 문제, 성과 무의미.
- 섀도우 평균이 백테스트 lag1 CI 밖으로 낮음 → 연구의 metrics 정렬(덤프 create_time)과 API 스탬프 의미가 다름(파리티 `--parity`로 재확인).
- 빈도가 ±40% 밖 → 행 결측/중복 처리 차이.
