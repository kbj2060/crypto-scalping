# ETH h48qual/zig075 — quality 라벨 방향별 base rate 직접 검증: "데이터 문제 vs 모델 문제" (2026-08-11)

## 배경 / 가설

`quality_head` 게이트의 숏 편향(h48qual, zig075 둘 다 재현됨 — `eth_h48qual_quality_trend_bias_h48orig_control_20260811.md`,
`eth_zig075_quality_trend_bias_control_20260811.md`)이 **모델(아키텍처/학습) 문제가 아니라
데이터 문제 아니냐**는 질문이 나왔다.

이미 확인된 사실만 놓고 보면 그럴듯한 가설이었다: `quality_for_action`은 방향판별력이 0에
가깝고(순위상관·회귀전환·앙상블-disagreement 전부 실패), 그런데도 게이트 통과 거래는 계속
숏으로 쏠린다. 판별력 없는 분류기가 그래도 한쪽으로 쏠린다면, 가장 흔한 설명은 "학습 라벨
자체의 base rate가 이미 그쪽으로 쏠려 있어서, 분류기가 개별 거래를 구분하는 게 아니라 그냥
학습 데이터의 사전 확률(prior)을 흡수했다"는 것 — 즉 모델이 아니라 **학습에 쓰인 라벨/데이터
자체가 방향 비대칭**이라는 가설.

이 문서는 이 가설을 실제로 검증한 결과다. 결론부터: **틀렸다.**

## 방법

- h48qual: 라이브 번들 `report.json`의 `label_contract.quality_label_dir` →
  `sltp_h48_conservative_padded_to_zigzag_timestamps` → manifest를 따라가 원 소스
  (`scripts/build_omega1_2_triple_barrier_labels_20260619.py`, config `h48_conservative`,
  tp_mult 1.2/sl_mult 0.8, 48bar ATR 배리어)까지 추적. 연속값 `tb_long_quality`/
  `tb_short_quality`(수수료 0.0042·MAE 페널티 0.20·스탑아웃 페널티 0.003 반영한 배리어-후
  수익률) 원본 CSV를 직접 로드.
- zig075: `CURRENT_LIVE_MANIFEST.json` → zig075 번들 `report.json`의
  `direction_label_dir` → `label_contracts/zigzag_action_labels_20260531`까지 추적.
  `quality_mode=same_as_direction`이므로 quality 라벨 base rate = `zigzag_action` 클래스
  분포 그 자체.
- **정합성 검증**: 두 번들 모두 이렇게 복원한 LONG/SHORT 카운트가 각 번들 자체 `report.json`의
  class count와 정확히 일치하거나 오차 ≤0.03%(zig075) / 오차는 전부 CASH 버킷에서만 발생하고
  LONG/SHORT은 정확 일치(h48qual, 타임스탬프 패딩 단계 특성) — 파일을 잘못 짚었을 가능성은
  사실상 배제.
- 학습 구간(2024 + 2025-01~09)과 평가 구간(VAL 2025-10~12, OOS 2026-01~02)을 분리해서 각각
  방향별 base rate 계산. (`report.json`엔 실제 적용된 것과 무관한 `quality_target_rule`
  boilerplate 블록이 있었음 — h48qual/zig075 둘 다 byte-identical이라 트레이너 리포트 작성기의
  템플릿 값으로 판단, manifest 체인 쪽을 정답으로 채택.)

## 결과

### h48qual: `tb_long_quality>0` vs `tb_short_quality>0` (기존 오라클 게이트 스크립트의 이진화 기준)

| 구간 | n | P(long>0) | P(short>0) | 활성 거래 중 숏 비중 | z | p |
|---|---:|---:|---:|---:|---:|---:|
| **학습(2024+2025 1~9월)** | 183,936 | 31.44% | 31.36% | **49.94%** | −0.44 | 0.66 (균형) |
| VAL(2025-10~12) | 26,496 | 29.02% | 30.35% | 51.12% | 2.81 | 0.005 |
| OOS(2026-01~02) | 16,897 | 26.25% | 30.99% | 54.14% | 8.17 | <1e-15 |

**학습 라벨은 완벽히 균형(49.94%, p=0.66) — 숏 쪽으로 쏠려 있지 않다.** 비대칭은 VAL(+1.1pp,
약함)과 OOS(+4.1pp, 뚜렷함)에서만 나타난다 — 즉 **모델이 학습한 데이터가 아니라 평가받는
구간에서만** 나타나는 현상.

### zig075: `zigzag_action` 클래스 분포(= quality 라벨 그 자체, same_as_direction)

| 구간 | LONG | SHORT | 숏 비중 | z | p |
|---|---:|---:|---:|---:|---:|
| **학습** | 86,795 | 77,575 | **47.19%** | −22.83 | ~0 |
| VAL | 12,843 | 10,578 | 45.16% | −14.87 | ~0 |
| OOS | 7,484 | 7,393 | 49.69% | −0.75 | 0.46 (균형) |

**학습 라벨은 유의하게 불균형 — 그런데 숏이 아니라 롱 쪽으로 쏠려 있다**(숏 47.2%). 가설과
정반대 방향이라 "학습 라벨 편향이 숏 쏠림을 설명한다"는 시나리오는 zig075에서 성립할 수 없다.
OOS 스윙 크기 비교(wave_return/path_edge)에서는 숏 스윙이 더 "뚜렷"하지만(edge 기준 +35%),
카운트 자체는 균형(49.69%, n.s.) — 이 역시 OOS 구간 고유 현상.

## 해석: 데이터 문제도, 단순 모델 문제도 아니다 — 학습/평가 구간 분포 불일치(regime shift)

가설이 예측한 메커니즘("분류기가 학습 라벨의 쏠린 사전확률을 그대로 반영")은 **직접 반증됨**:
h48qual 학습 라벨은 코인플립 수준으로 균형이고, zig075 학습 라벨은 오히려 롱 쪽으로 유의하게
쏠려 있다. 두 경우 다 숏 쏠림의 근원이 될 수 없다.

대신 숏 쏠림은 **평가 구간(VAL/OOS)의 실현된 라벨에서만** 나타난다 — 특히 OOS(h48qual
+4.1pp, p<1e-15)에서 뚜렷하다. 학습 구간(2024년 전체 + 2025년 1~9월, 21개월 다양한 레짐 포함)은
균형이었는데, VAL+OOS(2025-10~2026-02, 연속된 하락 구간, ETH -32%)만 떼어보면 숏 쪽이
유리해지는 것 — 이는 "학습 데이터가 편향됐다"가 아니라 **"학습 구간은 여러 레짐이 섞여 균형을
이뤘지만, 평가 구간이 우연히 한 방향 레짐에 집중되어 있다"**는, 훨씬 흔하고 다루기 어려운
문제(non-stationarity / train-eval 분포 불일치)다.

이건 **왜 지금까지의 "모델 쪽 수정 시도"가 전부 실패했는지**를 설명해준다: horizon 변경,
회귀 전환, temperature scaling, 앙상블 불일치 — 전부 "같은 아키텍처·같은 피처에서 더 나은
스칼라를 뽑아내는" 접근이었다. 하지만 원인이 train/eval 레짐 불일치라면, 같은 표현(representation)
안에서 추출 방식만 바꿔서는 애초에 고칠 수 없는 문제다. 반대로, 이미 결정된 "새 데이터 소스 탐색"
방향은 옳은 방향이되, **레짐에 걸쳐 안정적으로 유지되는 신호**를 요구해야지 단순히 "예측력 있는
피처 하나 더 추가"로는 같은 함정(레짐 국소적으로만 통하는 피처)에 다시 빠질 수 있다.

**아직 검증 안 된 대안 메커니즘**: `direction_head`의 게이트 이전(pre-gate) 숏 비중도 이미
57~59%로 약하게 쏠려 있다는 사실 자체는 기존에 확인돼 있다. `quality_head`가 이 작은 쏠림을
증폭시키는 것인지(예: direction_head의 confidence가 레짐에 따라 달라지고, quality_head가 높은
confidence 쪽을 더 잘 통과시킴)는 이번 진단 범위 밖 — 다음으로 확인해볼 만한 구체적 가설이다.

## 결론 (요약)

"숏 편향이 데이터 문제 아니냐"는 질문에 대한 직접 검증 결과: **학습 라벨 자체의 방향별 base
rate는 원인이 아니다**(h48qual 균형, zig075는 오히려 롱 쪽 쏠림 — 둘 다 가설과 반대이거나
무관). 대신 숏 편향은 **VAL/OOS라는 특정 평가 구간이 학습 구간보다 레짐이 훨씬 덜 다양하고
우연히 하락 쪽에 쏠려 있다는 사실에서 나온다** — "라벨이 잘못됐다"가 아니라 "학습 구간과 평가
구간의 시장 레짐 분포가 다르다"는 문제이며, 순수 모델 버그도 순수 데이터 라벨링 오류도 아닌
그 사이의 문제(train-eval non-stationarity)로 봐야 한다.
