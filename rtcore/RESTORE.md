# rtcore 재시작 복원 — 조사·설계(2026-11-20) · 구현(2026-11-21, §4~)

지금 rtcore 는 재시작하면 풋프린트 과거 봉·1초 수급 칸·청산 칸이 빈다(재시작 뒤 본 체결만 센다). 파이썬 대시보드가 재시작 때 무엇으로 되살리는지 정리하고, 코어가 같은 값을 되살릴 길을 고른다.

## 1. 파이썬이 되살리는 것 (dashboard/coin_flow.py · server.py, 2026-11-20 판)

**스냅샷 json 형식**(`footprint_save`): `{"bar_seconds": 300, "bucket": <칸 폭>, "symbol": "ETHUSDT", "last_ms": <마지막 웹소켓 체결 T>, "cells_v": 3, "bars": {"<봉 시작 초>": {"<round(가격/칸 폭)>": [매수, 매도, 고래매수, 고래매도, 리테일매수, 리테일매도]}}}` — 마지막 144봉, 반올림 전 값. 읽을 때 `bar_seconds`·`bucket`·`symbol`·`cells_v` 가 다르면 통째로 버리고, 143봉보다 오래된 봉은 버린다. `last_ms` 가 공백 메우기의 시작점이다(`ready` 일 때만 저장 = «last_ms 까지 빈 곳 없음»).

**테이프 표 형식**(`live_trade_tape_collector_20260916.py` `_init_sqlite` 415~):
`trade_tape_1s(symbol TEXT, ts_sec INTEGER, price_bin INTEGER, buy_qty, sell_qty, buy_n, sell_n, buy_max, sell_max, retail_buy_qty, retail_sell_qty, whale_buy_qty, whale_sell_qty, whale_*_n, retail_*_n, order_*_n)`, PK `(symbol, ts_sec, price_bin)`, WAL. 초는 완결된 것만 5초마다 한 번 쓴다(`FLUSH_SECONDS`). 칸 폭은 `BUCKETS`(ETH 0.1 · BTC 1.0 · SOL 0.01 · XRP 0.0001 …) — 풋프린트 칸(ETH 0.5)의 약수. 고래·리테일은 라이브와 같은 되묶기(`TakerOrderAggregator`)·같은 경계(`size_bands`)로 센 주문 단위다. 공백은 `gaps` 표, 1분봉 대조는 `verify_1m`.

옮길 때 그대로 지켜야 할 규칙(파이썬 원문):
- 테이프 칸 → 풋프린트 칸 키: `int(round(round(price_bin × 테이프칸, 10) / 칸 폭))` (2026-10-20 SOL 동률 사고 — SQL 반올림 금지).
- 공백 경계 두 초는 뺀다: `lo = max(창 바닥, last_ms//1000 + 1)`, `hi = 첫 체결 ms//1000`(배타) — 끊기기 직전 초와 붙은 첫 초는 라이브가 일부 셌다. 두 초 일부 체결은 빠진다(5분봉의 1% 미만).
- 테이프가 `hi − 1` 까지 따라잡을 때까지 5초 간격 최대 12번 기다린다(5초마다 쓰므로).
- 테이프 복원은 칸에 **더한다**(`+=`), 스냅샷 복원은 봉을 **통째로** 쓴다.
- 1초 칸 복원은 라이브가 이미 가진 초를 **덮지 않는다**(`setdefault`). 가격 칸은 그 초 마지막 체결가가 아니라 칸 가중평균이다(테이프에 순서가 없음 — 오차 < 테이프 칸 1개).
- 🔴`okx_tape_footprint` 는 범위에 비례해 메모리를 쓴다 — 2026-11-20 개발기 WSL 정지(13.7GB). 범위를 창(144봉)으로 자르고 읽는다.

## 3. 권고

**(다) + (나)** — 파이썬 ETH 외 코인 경로(스냅샷 → 테이프로 공백 메우기)와 같은 모양을 코어 안에서 만든다.
1. 코어가 `ready`(빈 곳 없음 = 시작 뒤 공백을 다 메움)일 때만 30초마다 자기 스냅샷을 쓴다(봉 칸 반올림 전 값 + `dhl` + 마지막 체결 `last_ms` + `bucket`·`cells_v`). 종료코드 70 으로 끝나기 직전에도 한 번.
2. 시작 때 스냅샷을 읽고(설정이 다르면 버림), `(last_ms, 첫 체결)` 공백과 1초 칸 660초를 테이프에서 메운다(위 «그대로 지켜야 할 규칙»). 청산은 `binance_ctx`·`okx_ctx`·`bybit_liq` 에서 660초 + 5분봉 창.
3. 메운 봉은 `dirty` 로 올려 다음 밀기가 싣는다(footprint.rs `restore` 자리 주석). 메우는 동안 `ready=false` — 화면은 «수집 중» 을 본다.
4. 시험: 합성 테이프 SQLite(정답지 생성기가 파이썬 `okx_tape_footprint`·`tape_seconds` 를 그대로 돌려 만든 값)와 일치 · 스냅샷 쓰기 → 읽기 왕복 비트 일치 · 그림자 대조기(`tools/shadow_footprint.py`)의 비교 시작 봉을 «복원 뒤 첫 봉» 으로 앞당겨 실서버 대조.

(가)는 테이프 의존성을 못 쓸 때만 임시로 — 파이썬을 끄는 순간 원천이 없어지고, 파이썬 값을 되읽어 대조하면 «파이썬과 파이썬» 을 비교하게 된다.

결정(2026-11-20 본 세션): `rusqlite` 0.37 bundled 를 넣는다(읽기 전용으로만 연다) · 코어 스냅숏 = `data/live/rtcore/<심볼>.json` · 테이프 = `data/hot/binance_tape.sqlite`(환경변수로 바꿈).

## 4. 구현 (2026-11-21 · `src/restore.rs` · 서버 미반영)

범위: 바이낸스 선물 몫(풋프린트 봉 144 + 1초 칸 660초 + dhl). 나머지 원천은 §6 표.

**코어 스냅숏**(`RTCORE_SNAP_DIR`, 기본 `data/live/rtcore/<심볼>.json`, 빈 값 = 복원 끔)
- 모양: `{"v":1, "symbol", "bar_seconds":300, "bucket", "last_ms", "bars":[[봉, [[칸 키, 6칸]…], dhl|null]…], "sec":[[초, 7칸]…], "holes":[[시작, 끝)…]}`.
  봉 = 창(가장 새 144봉)의 반올림 전 값 · dhl = 그때 화면에 보이던 값(링이 덮으면 링으로 잰 값, 아니면 얼린 값) · sec = 1초 링(가장 새 초 − 660 부터) ·
  last_ms = 받은 `@trade` 중 **가장 늦은** 거래소 시각 · holes = 못 메운 초 구간(창 안에 걸친 것만). 실수는 serde_json `float_roundtrip` 으로 비트까지 되읽는다.
- `v`(판 번호)·종목·봉 길이·칸 폭이 다르면, 깨졌으면, 창(143봉 전) 안 봉이 하나도 없으면 통째로 버리고 테이프로만 시작한다(로그 한 줄).
- 주기 30초(파이썬과 같다). 이 주기는 «테이프가 없을 때 잃는 최대 시간»일 뿐이다(테이프가 있으면 스냅숏 뒤 공백은 테이프가 메운다). 쓰기 조건 =
  «이번 판에서 메우기를 한 번 끝냈고 지금 메우는 중이 아니다»(파이썬 `ready` 일 때만 저장과 같은 뜻 — 메우는 중에 쓰면 last_ms 가 공백 너머로 가서 그 공백이 영영 안 메워진다).
  종료코드 70 직전에도 한 번(main.rs).
- 쓰기: 심볼 락 안에서는 값만 떠서(복사) 락 밖에서 직렬화 → `<심볼>.json.tmp` 에 쓰고 `fsync` → 이름 바꾸기(반쪽 파일이 안 남는다). 타이머 태스크가 실행기 밖 스레드(spawn_blocking)에서 돈다.

**복원 순서**
1. 시작(수신 전): 스냅숏을 읽어 봉(통째로)·dhl·last_ms·holes 를 되살린다. 1초 칸은 옆에 둔다(테이프가 있는 초는 테이프 값을 쓰려고).
2. 수신을 먼저 붙인다(버퍼에 쌓았다 합치지 않는다). 그 `@trade` 연결의 **첫 체결** 시각 first_ms 가 경계다 → 공백 [lo, hi) 를 정하고 «메우는 중»
   표시 → 별도 스레드가 테이프를 읽고(최대 12번 × 5초 기다림) → 심볼 락 안에서 합친다. 그사이 실시간 체결은 그대로 쌓인다.
   - 이유: 복원을 먼저 끝내고 붙으면 «복원 끝 ~ 붙은 첫 체결» 이 다시 빈다(테이프는 완결된 초만 5초마다 쓴다 → 붙는 순간의 앞 몇 초는 아직 테이프에 없다).
     합치기는 실시간과 순서가 바뀌어도 같은 값이다: 봉 칸은 `+=`, 1초 칸은 실시간이 가진 초를 안 건드림, dhl 은 링 밖 봉만. 파이썬도 같은 방식(받으면서 동시에 메운다).
3. 재연결도 같은 길(파이썬 `footprint_tape_restore` 는 재연결마다 돈다). 메우는 중에 또 끊기면 새 공백은 holes 로만 남긴다.

**경계(이음매)**
- 봉: lo = max(창 바닥, last_ms 의 초 + 1), hi = first_ms 의 초(배타) · 창 바닥 = first_ms 의 봉 − 143봉. 테이프 봉 칸은 `+=`, 스냅숏 봉은 통째로.
  끊기기 직전 초(last_ms 의 초)는 스냅숏 몫만, 붙은 첫 초(first_ms 의 초)는 실시간 몫만 든다 → 그 두 초의 «스냅숏 뒤 · 첫 체결 앞» 체결은 빠진다(파이썬과 같다 · 구멍으로 안 친다).
- 1초 칸: [first_s − 660, first_s) 를 실시간 > 테이프(테이프 끝 초까지) > 코어 스냅숏 순으로. 같은 초를 두 번 더하지 않는다(통째로 한 번 쓴다).
- 테이프는 5초 플러시라 붙은 직후엔 hi − 1 까지 없을 수 있다 → 테이프 끝이 hi − 1 에 닿을 때까지 5초 간격 최대 12번 → 그래도 모자라면 있는 데까지 메우고 [테이프 끝 + 1, hi) 는 holes.
- 칸 키 = `int(round(round(price_bin × 테이프칸, 10) / 칸 폭))`(짝수 반올림 · SQL 반올림 금지). SQL 은 파이썬 원문 그대로(봉·1초·dhl 세 개).
- dhl(링 밖 봉): 테이프가 봉을 다 들면 테이프(server.py fp_dhl 의 SQL·어긋남 검사) → 테이프 값이 없거나 검사에 걸리고 테이프가 안 건드린 봉이면 스냅숏 값 →
  테이프가 덜 따라온 봉은 방금 채운 링으로 → 그 밖은 스냅숏 값(테이프가 건드린 봉은 없음).

**«구멍 있음» 표시**: 풋프린트 메시지(스냅숏·밀기 모두)에 `holes` = 창 안 봉 중 못 메운 초 구간에 걸친 봉 시작 시각(메시지마다 지금 목록 전체 · 빈 목록은 키를 뺀다).
못 메운 구간 = 테이프를 못 읽음([lo, hi) 전체) · 테이프가 덜 따라옴 · 테이프 수집기 끊김(`gaps` 표 — 1분봉 대조가 맞은 분 `verify_1m` 은 뺀다) · 지금 메우는 중 · 스냅숏에 실려 온 옛 구멍.
`ready`(창 144봉이 다 참)와 따로다. 파이썬 `/api/footprint` 에는 없는 칸(proto.rs 주석).

같은 시각»)을 그대로 알아야 한다. `@trade` 에는 주문 식별이 없어 코어의 되묶기(같은 가격·방향·연속 ID·100ms·같은 초)는 추정이다 -- 2026-09-19 aggTrades

나머지 원천 약 7개 위에) 또는 `/market/stream?streams=a@aggTrade/b@aggTrade/…` 묶음 연결 1개(감싸기 모양 대조 필요). 메시지 수는 `@trade` 보다 적다(묶인 만큼).
빠진 번호(`a`)를 메우는 REST(aggTrades fromId)는 코어가 안 한다 -- 구멍은 워커처럼 «그 뒤부터 다시» 로 처리해야 한다.
